# 农资315 · 追溯码与生产扫码管理平台

> 已上线：普工／线长 APP 权限与员工采集详情，操作与增量迁移见 [说明](docs/普工线长与采集记录说明-20261016.md)。[下载 APK 3.1.13](https://www.nz315.cn/downloads/nz315-production-3.1.13.apk)。

面向农药生产企业的产品、追溯码、生产采集和扫码查询平台。网站使用 Nuxt 4、Vue 3、Nuxt UI 和 MySQL；安卓扫描仪应用源码在 `regcode-production/`。

主仓：[Blue03150328/nz315](https://github.com/Blue03150328/nz315)，默认分支 `master`。

## 当前业务流程

生成追溯码、打印贴标 → 工人登录扫描仪 → 选择本厂产品和生产线 → 填写生产资料 → 连续采集 → 上传形成生产记录并入库 → 后台监督进度。

- 生成码本身不等于已生产入库；有效生产采集上传后才创建或绑定码库记录。
- 设备归属厂家，工人使用个人账号；设备不固定员工或生产线。
- 新版工人端支持输入生产线或从下拉列表选择，服务器自动匹配当前任务，没有任务时自动创建。
- 首次加入一轮生产须联网登记。登记后每次扫码先保存到 SQLite，断网仍保留已登记批次的数据。
- 采集每隔 10～15 分钟上传，结束采集保留 5 秒取消时间，确认结束后自动补传。
- 所有已加入任务的设备都结束、完整事件及结束标记上传后，任务自动结束。暂停、离线和关机不算结束。
- 旧任务、旧采集会话和未完成队列继续保留，不能覆盖其他批次已生产码的资料。

上述自动输入生产线、默认日期和设备心跳等工人端功能属于新版安卓源码。已发布 APK 与源码的版本状态应分别核对；此次网站 Docker 更新不自动重新打包或安装 APK，新 APK 需在 Android12 实机验收后单独发布。

## 后台操作

### 生产管理

入口：后台 → **生产管理**，默认打开 **生产线管理**；顶部可切换生产任务、历史外部采集。

- 生产线管理一行一条线，展示负责人、当前产品、运行／暂停／离线／待同步设备及本线有效／重复／异常码总量。
- 添加生产线只建立档案；负责人可输入姓名或选择已有姓名，是独立标识，不授予扫码权限。负责人可编辑，已有任务的线名保留。
- 工人开工后自动建立任务、登记操作员和设备，所有参与设备完整上传并结束后自动结束任务。
- 生产任务展示任务、生产线、操作员、产品、状态、有效／重复／异常码及起止时间，不重复展示设备数量。
- 操作员采用“姓名（工号）”同列显示。点击“员工详情”查看每人的产品、批号、码数、起止时间和扫码原文。
- 表格每格单行、四边网格清晰；拖动表头移动整列，拖动边线调宽，支持横向滚动。
- 右上角“显示列”勾选需要的字段，支持全选与恢复默认。显示列、顺序和宽度按当前账号保存在浏览器。
- 支持模糊查询、生产线／操作员／状态表头筛选和日期查询。
- 产线页顶部汇总本账号可见的全部进行中设备，不受分页和列表筛选影响；码数仅采用服务器已确认记录。
- 厂家管理员或总部管理员可删除无意义的任务列表记录。删除保留码库、生产资料、工人设备归属及采集历史；未完成或未上传完整的任务不能删除。
- 产线支持单行删除、勾选多条及全选本页批量删除。删除隐藏档案和工人新缓存，历史资料保留；任务未结束或待同步时不能删除，批量失败整批保持原样。重新添加同名线可恢复档案。

### 账号和设备

1. 后台 → 系统设置 → 账号管理，添加本厂“生产操作员”，填写个人姓名、工号和登录密码。
2. 后台 → 生产管理 → 生产线管理 → 扫描仪管理，填写设备名称和厂家，生成激活二维码。
3. 扫描仪扫码激活，二维码有效期 5 分钟；激活后无需重复注册。
4. 工人用个人账号登录，选择产品和生产线后开工。

| 角色 | 使用范围 |
|---|---|
| 总部管理员 | 跨企业管理账号、设备、产品、生产和码库 |
| 厂家管理员 | 管理本厂账号、设备、产品、生产和码库 |
| 码管理员 | 本厂业务管理，具体写入权限由接口校验 |
| 只读用户 | 查询获授权的后台数据 |
| 生产操作员 | 登录扫描仪采集、上传和备份；不能登录后台 |

### 码库与外码

- 码库记录实际生产采集，展示上传来源及对应生产资料。
- “修正生产信息”仅影响当前上传记录中的具体码，并记录修改日志。例如一条上传为 6 张，只修改这 6 张。
- 外码采集独立保存扫码原文，分类、去重与生产绑定分开；TXT 导出保留原始网址内容。
- 公众扫码入口：`https://www.nz315.cn/trace?code=追溯码`，生产资料来自实际码和对应上传记录。

## 本机启动：Docker

Windows PowerShell：

```powershell
cd C:\Users\MR\Desktop\work\nz315
.\docker-start.ps1
```

启动地址：[http://127.0.0.1:3101/login](http://127.0.0.1:3101/login)。脚本使用独立 Compose 项目 `nz315-docker-local`，包括网站、MySQL 和一次性初始化服务。

已有镜像再次启动：

```powershell
.\docker-start.ps1 -NoBuild
```

查看及停止：

```powershell
docker compose --env-file docker.env ps -a
docker compose --env-file docker.env logs --tail 100 app
docker compose --env-file docker.env stop
```

`docker.env` 是本机私有配置，不提交 Git。数据库保存在命名卷中，停止或重建网站不会清空。不要用 `down -v` 作为普通停止操作。

本机已复制过线上快照，账号密码沿用快照；`DOCKER_SEED_DEMO=0` 防止再次写入演示数据。后续本机操作不会回传线上，线上新增数据也不会自动下载。本地删除测试任务不代表线上任务被删除。详见 [DOCKER.md](DOCKER.md)。

## 本机源码开发

Node 版本参考 Dockerfile；本机现有 Node24 可以运行。连接的是开发数据库时：

```powershell
npm ci
Copy-Item .env.example .env
# 编辑 .env，填写开发数据库和独立 SESSION_SECRET
node scripts/db-init.mjs
npm run dev -- --host 127.0.0.1 --port 3100
```

`db-init.mjs` 默认写演示数据，只适用于空的开发库。真实数据库只使用审核过的增量迁移；不要拿演示初始化覆盖业务库。已有 Docker 数据副本仍按前述 Docker 方式运行即可。

## 线上 Docker 部署

正式配置为 [compose.production.yml](compose.production.yml)，与本机含 MySQL 的配置分开。

- Docker 托管网站，继续连接服务器现有 MySQL `nz315` 数据库。
- Nginx 继续处理 HTTPS，并反代 `127.0.0.1:3100`。
- 凭据从只读文件加载；原会话密钥沿用，不进入源码或镜像。
- 仅运行已审核的监控增量迁移，不初始化演示数据，不导入本机测试库。
- 容器健康检查通过后移除旧 `nz315` PM2 启动项，网站只由 Docker 托管；其他项目不变。
- 原 APK 下载链接保留，新 APK 单独验收发布。

服务器日常操作：

```bash
cd /var/www/nz315
docker compose --env-file .docker-deploy.env -f compose.production.yml ps
docker compose --env-file .docker-deploy.env -f compose.production.yml logs --tail 100 app
docker compose --env-file .docker-deploy.env -f compose.production.yml restart app
```

完整发布、迁移、备份和回滚步骤见 [docs/DOCKER_PRODUCTION.md](docs/DOCKER_PRODUCTION.md)。实际已发布提交、镜像和验收结果以服务器 `.docker-release.json` 为准。

## 源码目录

| 目录或文件 | 用途 |
|---|---|
| `app/` | 网站页面、组件、样式和权限入口 |
| `server/api/` | 登录、后台、设备、上传和公众查询接口 |
| `server/utils/` | 数据权限、生产事务、自动归线、监控、码库投影和审计 |

| `tests/` | 单元测试和隔离数据库/API 验收 |
| `compose.yml` | 本机独立网站及测试 MySQL |
| `compose.production.yml` | 正式网站容器，沿用现有数据库 |
| `Dockerfile` | 构建网站、初始化工具和运行镜像 |
