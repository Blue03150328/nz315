# 追溯码生成前分文件设置

日期：2026-10-24。状态：本机实现及隔离验收完成，尚未部署正式站。

## 使用方式

选择产品后，在「生成设置」中填写「每个文件的追溯码数量」和「生成文件数量」。页面自动计算本次总量，不再单独填写总生成数量。

例如每文件 400 条、20 个文件，点击「生成追溯码」即请求生成 8000 条。随后点击「导出 TXT」「导出 urls.txt」或「导出 CSV」，直接按生成时的设置下载：多文件为 ZIP，单文件直接下载。导出后不再弹出分文件设置，也不再进行部分导出或余码续导。

每个文件包含指定数量的码，CSV 表头不计入码数；各文件按顺序编号、连续取码。重复下载或更换格式始终使用本批原码和相同文件边界。修改表单只影响下一次生成，现有结果仍保留本批的数量设置。

默认 1 个文件、每文件 100 条。文件数量为 1～1000 的整数，每文件码数为正整数，总量不超过 50 万条；超过 20 万条仍先确认总量及预计体积。重置恢复默认设置并清空结果。下载失败保留未导出提醒，可直接重试；浏览器触发下载后仍须确认文件已保存。

## 实现与验证

- 运行文件仅调整生成页及共享导出模块，接口继续提交数字产品 ID 和两项设置的乘积，不改码值生成规则。生成响应条数与计划不符时提示重新生成，保留上一批结果，避免下载缺码文件。
- 生成前校验数量，生成时保存本批设置快照；生成和打包期间禁止重复提交及修改数量。三格式共用本批设置，移除导出设置弹窗，保留打包进度和防丢失提醒。
- 网站单元测试 166 项：161 通过、5 项既有跳过、0 失败；含生成总量边界和非法输入回归。独立 Python ZIP 读取器核对三格式 20×400、中文文件名、BOM、CRC 和码顺序通过。
- 共享模块 TypeScript 严格检查（含数组索引边界）通过；独立 Nuxt 生产构建通过，产物 `.tmp/generator-files-output`，未覆盖原 `.output`。
- Edge 浏览器 12 组隔离验收通过：默认及非法数量、20×400 实际生成请求、三格式下载及内容、修改表单不影响旧批、重新生成、下载失败及单文件重试、390px 小屏、50 万条确认取消、重置及零页面异常。
- 浏览器使用虚构接口，测试服务数据库指向本机关闭端口；未写真实业务数据。无 DDL、APK、离线工具或服务器配置变更，离线工具 v1.2.1 下载信息保持。

复验：`node --test tests/generator-export.test.mjs`；准备独立构建后，设置 `NZ315_GENERATOR_EXPORT_TEST=1` 执行 `node tests/generator-export.integration.mjs`。可使用 `NZ315_GENERATOR_EXPORT_BUILD` 指定构建目录。
