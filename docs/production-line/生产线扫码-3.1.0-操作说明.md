# 生产线与工人扫码 3.1.0 操作说明

本版按2026年10月12日最后确认的流程实现：新建任务只填任务名称、生产线、整份已入库码文件和参与的生产操作员。不按设备分码，不填写领用数量，不走余码审核与转领。

当前本地Docker已经更新：http://127.0.0.1:3101/login 。这是独立示例数据库，平台示例账号为admin / admin123，原业务数据库和线上数据没有被替换。安卓实机先使用独立测试应用验收；2026年10月12日已完成配套后台增量上线，已连接扫描仪已覆盖安装3.1.0。正式APK连接 https://www.nz315.cn ，其他设备可从 https://www.nz315.cn/downloads/nz315-production-3.1.0.apk 下载并覆盖安装。详细发布范围和备份见同目录上线记录。

## 管理员操作

1. 系统设置 → 用户权限 → 新增用户 → 角色选“生产操作员” → 选择所属厂家 → 保存。每人使用自己的工号；设备不固定绑定某个人。
2. 追溯码生成并入库。用于新任务的码文件应全部为尚未生产、尚未归入其他任务的本厂码。已经生产的记录不会覆盖。
3. 生产任务 → 设备管理 → 添加设备 → 登记并生成激活二维码。在新设备扫描二维码完成激活。已有设备无需因更换操作员而重新登记。
4. 生产任务 → 新建任务 → 填任务名称、生产线 → 选择整份已入库码文件 → 搜索并多选本厂生产操作员 → 保存。产品由文件归属自动核验，生产批号、日期、有效期由工人填写；后台不再填写质检资料，也不会默认质检合格。
5. 主列表按任务和生产线显示每位操作员的有效扫码、重复、异常、开始及停止时间。点击“员工详情”查看原始扫码与异常原因；点击“码明细”查看已扫码或未扫描的码。表头的生产线、操作员下拉框支持搜索；顶部支持任务/生产线/文件/姓名/工号模糊搜索，以及状态、日期筛选。点击“重置”恢复全部。
6. 需要调整人员时，点击“编辑人员”，选择本厂操作员后保存。历史扫码仍归属原操作员和设备，不因编辑而转给新员工。
7. 所有参与工人都在手机结束采集、完整数据及结束标记上传后，点击“结束任务”。核对尚未联网登记的离线设备，勾选记录收齐后确认。服务器会拒绝已知会话仍在采集、序号缺口、尚未上传结束标记的任务。未全部扫描时页面会提醒核实。本动作只结束任务和保留历史，不释放或转领码。

## 工人操作

1. 首次联网激活和登录个人工号，完整下载产品及已安排任务的码清单。首次未缓存的账号或清单不能离线使用；离线登录授权为72小时。
2. 生产扫码 → 选择产品 → 填生产日期、有效期、生产批号 → 确认资料 → 开始连续采集。首个有效码确定实际任务及生产线，服务器再次校验任务人员和产品归属。同一任务已有生产资料时须保持一致；扫描其他任务的码会记录异常，不自动切线。
3. 每次扫描先写本机SQLite事务，成功才提示“已保存”。同一码不同网址按唯一完整32位码去重；缺位、多候选、未安排任务、其他产品等原文保留为异常。云端收到收据后才减少待上传数量。默认每轮10～15分钟随机上传，也可点击“立即上传”；每批最多20条。
4. 手机没有“换人”或“交班”按钮。完成当前工作先点击“结束采集”：立即暂停收码，弹出5秒取消倒计时。5秒内点“取消结束，继续采集”可以恢复；离开应用也会取消尚未提交的结束。倒计时结束后才冻结本机批次并生成结束标记。
5. 结束页面区分本机有效采集、云端有效记录、待上传及结束标记状态。有网时立即补传；断网或服务器未确认时继续保留本机数据，提示导出TXT或联网补传。缓存显示任务尚未完成时会提醒，本机数量不能代表其他工人是否完成整条线。
6. 点击“导出生产记录TXT”选择保存位置；或者“导出本人完整备份”保存JSON。TXT为带签名的结构化UTF-8记录，包含原文、事件UUID、序号、工人授权标识、任务、生产资料和结束标记，不含密码、设备凭证或上传授权令牌。普通“一行一个码”的文本没有完整追责信息，不能替代此文件。
7. 返回首页 → 退出登录。其他工人用自己的工号登录后开始自己的采集；原员工的记录和待上传队列保留，员工身份不会被替换。

## 离线文件补传

电脑后台 → 追溯码上传 → 离线生产记录TXT → 选择手机导出的完整TXT → 预览校验 → 确认导入并绑定。新导入路径绑定已入库任务码，自动上传与TXT导入共用事件UUID、序号和服务器收据。文件再次导入，或以后手机恢复联网重传相同事件，都不会重复生产。首次使用仍须联网缓存；断网不清队列，不要求等整批扫码结束才保存。

厂家的账号只能处理本厂数据。工人只能导出自己的本机记录。厂管确认文件收齐不等于服务器能够发现从未联网登记的设备；人工确认必须真实完成。历史未记录真实工人身份的记录显示历史未记录，不会冒充当前管理员。

## 本地启动与后台增量更新

在 backend-patch 目录的PowerShell执行：

```powershell
.\docker-start.ps1 -NoBuild
```

源码改变后重新构建：`.\docker-start.ps1`。停止：`docker compose --env-file docker.env stop`。保留数据库卷和docker.env；不要删除数据卷来更新。

后台补丁包以本轮修改前的3.0.1后台源码为基线，manifest记录各文件修改前后SHA256。生产更新前应验证文件基线、备份源码/数据库/环境配置，保留现有SESSION_SECRET。先应用补丁，再运行 `node scripts/migrate-production-workers.mjs`（只做增量结构迁移，不跑演示数据初始化），构建并检查接口后受控重启。不要在生产执行不带 --migrate-only 的 db-init，不要用本地示例库覆盖生产库。

本版增加任务人员关系、来源文件、开始/停止时间及时间戳字段，允许任务在工人采集前没有批次；保留旧接口、历史记录和未完成队列。旧设备队列继续使用自动补传或原JSON备份；新TXT格式用于新版生产任务。不要在旧队列未确认完成时清除应用数据或卸载应用。
