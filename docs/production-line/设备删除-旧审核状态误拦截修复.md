# 设备删除：旧审核状态误拦截

线上设备gg（编号7）的生产和外码批次已结束、会话最终序号与收到序号一致，生产任务也已完成。删除仍被拒绝，是因为旧流程的一个worker_pool保留review状态，原activeCount把ready、active、review全部作为未结束采集计数。

修复后，review码池仅在关联批次已经sealed、至少有一个工人会话、全部会话completed且最终序号非空并等于收到序号时，不再拦截设备删除、重新激活或调换归属。审核仍保留在后台，不代表已收到的数据还未上传。

未开始或采集中的预配码、没有完整关联批次的孤立审核码池、未结束会话和序号缺口仍拦截。即使码池已退出审核，封存批次里的不完整会话也独立拦截。厂家权限和设备行锁不变，错误提示说明可能是未结束采集或旧预配码。

设备删除仍为逻辑删除、撤销设备凭证并留操作日志；本修复不释放旧预配码，不改质检/审核状态，也不修改追溯码、批次、会话、事件或收据。不代用户删除当前连接的设备。

验证：新增5组真实隔离接口验收通过，覆盖权限、完整审核批次、历史及码占用不变、不完整会话/序号、孤立码池和已封存异常会话；原设备12组生命周期回归通过。网站75项单测通过、4项既有跳过，生产构建通过。无DDL、无APK更新。线上发布状态单独记录在部署目录的.device-delete-release.json及私密备份状态中。
