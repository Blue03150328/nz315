# 安卓 3.1.5：生产线与产品分开

本轮根据用户确认，取消新建任务的码文件选择。任务只确定名称、生产线及操作员，产品和生产资料由工人在终端选择、填写。

## 操作

1. 后台先完成产品及追溯码入库。
2. 进入“生产任务”，新建任务，填写名称、生产线并选择本厂生产操作员；总部管理员额外选择厂家。
3. 操作员登录登记在本厂的设备，进入“生产扫码”。准备页可选择本厂全部启用且已有入库码的产品，不受任务原产品或码文件限制。一个工人参与多条进行中的线时，额外选择生产线。
4. 填写本次产品的生产批号、生产日期及有效期，开始采集。扫码先保存本机，定时上传；结束采集保留五秒取消、补传、TXT及备份。
5. 后台同一条线按实际采集显示产品、批号、日期和员工进度。不同产品、不同批次独立保存，不把整条线视为一个共享生产批次。

本机已有未结束采集优先恢复原资料。需先结束、上传自己的原生产采集，才能新开另一批；外码记录与生产记录独立。

## 数据及兼容

- 只展示本厂启用且存在 `upload_batch_id` 入库记录的产品。产品缓存使用完整版本快照；新版开工要求 `stockVersion=1`，下载中断继续保留上一份完整缓存，避免以旧协议或空码清单开工。
- 新任务 `production_task.product_id/batch_id/source_upload_id` 为空。真实产品与日期固定在 `worker_run.context_json` 及对应 `batch`，可信身份仍由授权及任务成员校验。
- 扫码在同一事务中核对入库、企业、产品、规格、全局占用并归属生产线、绑定资料、保存事件收据。其他任务、旧设备码池占用不能抢码；同批重复只计一次，换批扫描旧码记录异常，不覆盖历史资料。
- 旧任务原有码文件、码占用、已生产资料及旧队列不回写或重分配；旧接口和旧请求幂等哈希保留。新版任务按实际扫码增加已用明细。
- 完整工人上传按本次产品、批号、日期投影到码库；离线签名 TXT 使用同一收据。管理员异常确认留原异常收据并补投影。含多产品的线禁止整任务更正生产资料，仍支持逐码核对更正。
- 数据库增量仅使任务产品可空，给 `code_usage_batch` 添加 `product_id` 和 `production_snapshot`。上线使用 `scripts/migrate-full-release.mjs --database=nz315`，不运行演示初始化。原业务行与原列逐表校验，备份及结果以服务器 `.full-release.json`、`/var/backups/nz315/stock-line-20261013-3.1.5/state.json` 为准。
