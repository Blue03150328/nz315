# UI 改版提示词手册

> 用途：指导 AI 助手（或设计外包）把本项目现有界面从「AI 生成感」改为「专业中后台 + 克制的移动端」。
> 用法：按 §4 的顺序逐条复制粘贴，**一次只改一页**，改完验收再进下一条。
> 本文件是方法论 + 可复制提示词，不含代码改动。

---

## 1. 诊断：AI 味从哪来（实测定位）

「AI 味」不是主观感受，而是一批**可枚举的具体写法**。本项目实测到的病灶如下：

| # | 病灶 | 出现位置（实测） | 为什么显得像 AI 生成 |
|---|---|---|---|
| 1 | 斜向渐变绿横幅 | `app/pages/index.vue:41`（`bg-gradient-to-br from-primary to-emerald-600`）、`app/components/TraceAlert.vue:73`（`cfg.gradient` 每个状态一套渐变） | 渐变是 AI 落地页的头号特征；业务系统用渐变几乎没有理由 |
| 2 | 大圆角 + 彩色投影 | `index.vue` 的 `rounded-2xl shadow-lg shadow-primary/30`；`TraceAlert.vue` 多处 `rounded-xl ... shadow-sm` | 圆角 ≥16px + 有颜色的阴影 = 模板感 |
| 3 | 同一语义多套绿色并存 | `main.css` 令牌是 `hsl(142 32% 30%)`（沉稳深绿），页面里却另有 `emerald-600`、`#2c5c3a`、`#f8f9f4`（`nearby-stores.vue` 自成一套）、后台 `#283850` | 没有单一色彩来源，页面之间「各写各的」 |
| 4 | 每张卡一个彩色圆底图标 | 后台数据概览 6 张指标卡（绿/蓝/绿/蓝/橙/红各一色） | 用颜色区分「卡片身份」而非「语义」 |
| 5 | 居中三行标题堆叠 | `app/pages/login.vue`（欢迎回来 / 平台名 / 说明文字，垂直居中堆叠） | 典型的模板式 hero 排版 |
| 6 | 饱和色铺满状态区 | 首页「异常线索 42」大红数字；`TraceAlert` 整块彩色背景 | 状态应当靠**标签**表达，不是靠整块染色 |
| 7 | 间距节奏单一 | 各页卡片之间多为同一 gap，无主次 | 缺少「留白层级」，一眼望去全是等权重的块 |

**结论**：后台（`app/layouts/admin.vue` + `main.css` 里的 `.b-*` 体系）其实已经有一套很克制的 Element Plus 风格设计语言，问题主要出在**公众端 H5 页面**和**令牌未被统一遵守**这两点。

## 2. 提示词怎么写才有效

不要写「帮我改得好看一点、简约一点」——这类形容词对模型没有任何约束力。有效的提示词由 6 个要素构成：

| 要素 | 说明 | 反例 → 正例 |
|---|---|---|
| **① 角色与参照系** | 指定审美坐标系 | 「设计得漂亮些」→「按 Element Plus / Ant Design Pro 的克制口径，不要 SaaS 落地页风格」 |
| **② 负面清单** | **最重要**。把 AI 味具象成禁止项 | 「简约一点」→「禁止：渐变、彩色阴影、圆角 >8px、彩色圆底图标、居中三行标题」 |
| **③ 数值化约束** | 给具体数值，不给形容词 | 「圆角小一点」→「圆角统一 4px；卡片无阴影，改用 1px 边框 #e4e7ed」 |
| **④ 令牌唯一来源** | 要求所有颜色/间距从令牌取值 | 「颜色统一点」→「页面内禁止硬编码色值，一律引用 `main.css` 的 `--b-*` / `--ui-*` 变量」 |
| **⑤ 变更范围红线** | 明确禁止碰业务逻辑 | 「只改样式与 DOM 结构，不得改动任何接口调用、字段名、路由、状态流转」 |
| **⑥ 可验收的产出** | 要求先方案、后代码、再自检 | 「先只输出改动清单与对照表，我确认后再动代码；完成后附自检结果」 |

> **一句话记住**：AI 味 = 一批可枚举的视觉特征。**把特征列成禁止项，比描述你想要什么更管用。**

## 3. 可复制提示词

### 3.0 通用开场（每条提示词前都先发这段）

```
你现在的角色是一位资深 UI 工程师，审美参照 Element Plus / Ant Design Pro 的
克制口径，而不是 SaaS 营销落地页。

硬性约束：
1. 只允许改样式与模板结构，禁止改动任何接口调用、字段名、路由、props 契约、
   状态流转与业务判断逻辑。
2. 所有颜色、圆角、间距必须引用 app/assets/css/main.css 中已有的设计令牌
   （--b-* / --ui-* 变量），禁止在模板里新增硬编码色值或 Tailwind 调色板类
   （如 from-emerald-600、text-green-500）。
3. 禁止出现：渐变背景、彩色阴影（shadow-primary/30 之类）、圆角 >8px、
   彩色圆底图标、居中三行标题堆叠、整块饱和色背景。
4. 中文文案与中文注释，不要引入新依赖，不要重写整个文件，用最小改动完成。
5. 先告诉我你打算改哪几个地方、每个地方改成什么，等我确认后再动手。
```

### 3.1 公众端 H5 首页（`app/pages/index.vue`）

```
【任务】改造 app/pages/index.vue 的视觉，去掉 AI 味，改成克制的政务/工具类风格。

【问题】顶部 hero 用了 bg-gradient-to-br from-primary to-emerald-600 + rounded-2xl
+ shadow-lg shadow-primary/30，是典型的 AI 落地页写法。

【要求】
1. 去掉渐变与彩色阴影。hero 区改为：纯色深绿底（用 --ui-primary 令牌），
   圆角 8px，无阴影；或更克制地改为白底 + 1px 边框 + 深绿标题。
2. hero 内的圆形图标底去掉，二维码图标改为线性图标，直接使用深绿或白色描边。
3. 「扫一扫，查真伪」保持居中可接受，但副标题与 ①②③ 步骤条压缩为一行 12px
   小字，步骤之间用「·」分隔，不要三个独立彩色胶囊。
4. 下方两张数据卡（累计查询 / 异常线索）：改为与后台 .b-stat 同类口径——
   白底 + 1px 边框 #e4e7ed + 4px 圆角 + 无阴影；数字用 24px/600 深色
   （--b-text-title），不要用高饱和红绿；异常数字与正常数字同级处理，
   异常状态靠一个浅底深字小标签表达（复用 .b-tag-danger）。
5. 卡片标题行统一 13px，说明文字 12px，颜色用 --b-text-muted（#86909c）。
6. 删掉多余的装饰性圆角容器，保留必要留白。

【红线】不要动扫码输入框的逻辑、路由跳转、统计数据来源。

【产出】先给出改动清单（原写法 → 新写法对照），我确认后再改代码。
```

### 3.2 扫码结果页（`app/components/TraceAlert.vue` + `TraceResult.vue` + `TraceNotFound.vue`）

```
【任务】改造扫码结果相关组件，去掉渐变色块和 shadow 卡片。

【问题】TraceAlert.vue:73 用 bg-gradient-to-br + cfg.gradient，为「正常/异常/作废」
三种状态各配了一套渐变；各处信息卡统一带 shadow-sm。

【要求】
1. 彻底移除 cfg.gradient 这套渐变配置，改为「顶部状态条」方案：
   - 白底卡片 + 1px 边框；
   - 左侧一条 3px 竖向色带表示状态（正常 = --ui-success，
     冻结/作废 = --ui-error，警告 = --ui-warning）；
   - 状态标题用深色 16px/500，配一个浅底深字状态标签（.b-tag-success 等）。
2. 所有 rounded-xl + shadow-sm 的信息卡统一改为：圆角 4px、1px 边框
   var(--b-border)、无阴影。
3. 字段行（农药名称 / 登记证号 / 生产日期…）保持「左标签 + 右值」，
   标签色 --b-text-muted，值色 --b-text-strong，行高统一，
   行间用 1px 分割线 var(--b-divider) 而不是卡片嵌套。
4. 追溯码用 .font-code 等宽展示，字号不小于 13px，加浅灰底块。
5. 「查询结果仅供参考」页脚说明保留，字号 12px、--b-text-muted、居中。

【红线】三种状态的判定条件、字段取值、异常码不展示产品信息等业务规则一律不动。

【产出】先列出「渐变 → 状态条」的具体映射表（哪种状态对应哪个色带与标签），
我确认后再改。
```

### 3.3 后台中后台（`app/layouts/admin.vue` + `app/pages/admin/**`）

```
【任务】统一后台视觉，收敛到 main.css 已定义的 .b-* 设计语言。

【问题】
1. admin.vue 侧栏用硬编码 #283850、内容区 #f0f2f5，与 .b-* 体系混用；
2. 数据概览 6 张指标卡各配一个彩色圆底图标（绿/蓝/绿/蓝/橙/红），用颜色区分
   卡片身份而非语义；
3. 部分卡片带 shadow。

【要求】
1. 侧栏底色收敛为令牌（在 main.css 里新增 --b-sider-bg，值与现有一致），
   admin.vue 里不再写死 #283850；内容区背景改为 --b-fill（#f5f7fa）。
2. 指标卡去掉彩色圆底图标：图标统一 16px 线性图标 + --b-text-muted 中性色，
   放在标签文字左侧；数值用 .b-stat-value 口径（24px/600/--b-text-title）。
   只有「异常/预警」类卡片允许加一个浅底深字小标签提示。
3. 所有卡片统一 .b-card（4px 圆角 / 1px 边框 / 无阴影），删除 shadow 类。
4. 表格一律复用 .b-table，状态一律复用 .b-tag-*，操作列复用 .b-actions + .b-sep。
5. 侧栏选中态保持现状（浅底块 + 深色字），但把硬编码色值改为令牌引用。

【红线】11 个后台菜单、4 个设置 Tab 的功能与权限逻辑、所有 API 调用不动。
逐个页面改，先改 admin.vue 布局与数据概览，我确认后再继续其他页。

【产出】先给出「硬编码色值 → 令牌名」的完整对照表。
```

### 3.4 登录页（`app/pages/login.vue`）

```
【任务】登录页去模板化。

【问题】当前为左右双色分割背景 + 居中三行标题堆叠（欢迎回来 / 农资315·追溯码
管理平台 / 请使用企业分配的账号登录系统）+ 大圆角卡片，是模板式 hero 排版。

【要求】
1. 背景去掉双色分割，改为纯色 --b-fill（#f5f7fa）。
2. 卡片改为：白底 + 1px 边框 + 4px 圆角 + 无阴影，宽度收窄到 380–400px。
3. 标题区改为左对齐：主标题 18px/600 深色一行，副标题 13px --b-text-muted 一行，

5. 表单标签 13px/--b-text-strong，输入框圆角 4px，按钮用 --ui-primary 直角小圆角，
   不要通栏大圆角按钮。
6. 底部演示账号提示改为 .b-note 浅灰底样式，字号 12px，去掉绿色文字。

【红线】登录校验、会话写入、跳转逻辑一律不动。

【产出】先输出新版的布局结构（区块顺序 + 每个区块的字号/颜色/间距），再改代码。
```

## 4. 执行顺序与验收

**顺序**（先立规矩，再改页面；先动结构，再抠细节）：

| 步骤 | 内容 | 目的 |
|---|---|---|
| 0 | 先发 §3.0 通用开场 | 立红线，防止 AI 顺手改业务逻辑 |
| 1 | 用 §3.0 的约束追加一句：**「先只做一件事——把 main.css 里的令牌补齐并写清注释，不动任何页面」** | 令牌唯一来源是整个改版的地基 |
| 2 | §3.4 登录页（最简单，用来校准审美） | 一次对话就能判断 AI 是否理解你的取向 |
| 3 | §3.2 扫码结果页（公众端核心） | 业务最关键 |
| 4 | §3.1 公众端首页 | 结构改动最大 |
| 5 | §3.3 后台布局 + 数据概览，再逐页推进 | 后台已有基础，属于收敛 |
| 6 | 全局复查：`grep` 搜索残留的 `gradient`、`shadow-`、`rounded-xl\|2xl`、`#[0-9a-f]{6}` | 防止漏网 |

**每轮改完必问 AI 的 3 个问题**：

1. 「列出本次改动中所有**仍然硬编码**的颜色值，并说明为什么没有用令牌。」
2. 「确认本次改动**没有触碰**任何接口调用、字段名、路由和状态流转——逐条核对并说明。」
3. 「如果我只允许你再改一个地方来提升质感，你会改哪里？」（用来发现 AI 自己认为的薄弱点）

**验收标准（可量化）**：
- 全库 `grep gradient` 结果为 0（`scan.vue:253` 的扫描线动画可保留，属功能性视觉）；
- 页面内硬编码十六进制色值数量降到 0（`nearby-stores.vue` 的独立色板必须并入令牌）；
- 所有卡片圆角 ≤8px 且无阴影；
- 同一语义的颜色在全站只有一处定义。

## 5. 最后一句提醒

如果一轮改完发现 AI **又加了渐变、又加了彩色阴影、又把标题居中了**——这是模型的默认审美强势回归。此时不要重写提示词，直接补一句：

```
你刚才的改动里出现了【渐变 / 彩色阴影 / 居中标题】，这违反了我给的负面清单。
请撤销这几处，只保留符合约束的部分，并逐条说明每一处改动对应清单中的哪一条。
```

把负面清单**再念一遍**，比换一套说辞有效得多。
