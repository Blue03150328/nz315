## 3. 三条机制：为什么这么写（改之前先懂边界）

改动不是"加个判断"这么简单，三条都有**不写就会退化的边界**：

### 3.1 会话吊销 —— `issuedAt` vs `session_epoch`

- token 载荷：`base64url(userId.expiry.issuedAt).hmac`（**三段**）
- `getCurrentUser` 判据：**`issuedAt < session_epoch` → 视为未登录**
- 登出、重置密码 → `UPDATE user SET session_epoch = Date.now()`
- **为什么用严格小于**：同一毫秒内「登出 → 立刻重登」如果写成 `<=`，新签发的 token 会被自己的登出记录误杀。
- **为什么旧两段 token 要主动拒绝**：两段格式**承载不了签发时间**，服务端无从判断它是否已被吊销 → 只能一律作废。**副作用：部署后所有在线用户需重新登录一次**（预期行为，不是故障，提前跟用户打招呼）。
- ⚠️ **任何"改他人凭证状态"的写操作都要顺带 `await revokeUserSessions(userId)`**（改密 / 改角色 / 禁用），否则旧会话在 7 天 TTL 内继续有效。

### 3.2 Origin 校验 —— 必须完整比对，不许 `startsWith`

- 取 `x-forwarded-host || host`，与 `origin` 做**完整精确比对**（去尾部斜杠）。
- **旧实现是 `origin.startsWith('http://' + host)`** → 注册 `https://www.nz315.cn.evil.com` 就能穿过**全部写接口**的 CSRF 防护（本轮实测修掉）。**千万别"优化"回前缀比较。**
- **无 Origin 的请求（curl / 服务端调用 / Node fetch）照旧放行**，这是刻意保留的，别当成漏洞"修"掉——API 客户端与开发工具依赖它。

### 3.3 前端按角色收口 —— 与后端守卫逐条对齐

- `useUser()` 暴露 **`canWrite`**（非 viewer）与 **`canManageUsers`**（platform_admin / enterprise_admin）。
- 新增写入口的**完整动作是两个**：① 写接口用 `requireWritableUser`（或更严）；② 页面按钮加 `v-if="canWrite"`。
- 纯写流程页（追溯码生成 / 追溯码上传）在侧栏打 `writeOnly: true`，只读账号**整条隐藏**（进去只剩空白，没必要给）。
- **别再散落写 `role === 'viewer'`** —— 迟早与后端白名单漂移。
- **验收口径**：viewer 登录后**页面上不应存在任何可点的写操作**，而不只是"点了返回 403"。

## 6. 铁律（违反任意一条都可能出事故）

### 真浏览器截图（本项目首次跑通，可复用）

用全局技能 `browser-ui-screenshot` 的 `scripts/ui-shot.js`（Edge headless + CDP）。**本项目是 Nuxt UI v4 而非 Element Plus**，脚本自带的 `--click` 命中集合（EP 专用）用不上，走 **`--js-file` 逃生口**：

1. 用 `.env` 的 `SESSION_SECRET` 按 `auth.ts` 同算法**手搓三段 token**（`createHmac('sha256', secret).update(payload).digest('base64url')`）→ **免去登录表单交互**；
2. **inject 脚本**（`--js-file`）：`document.cookie = 'nz315_user=' + token + '; path=/'` → `location.href = 目标路径`，**返回即结束、不 await**（跨导航 await 会被销毁成 ERR）；
3. 再串 1–2 个 `--js-file` **轮询**「表格出数据行」（写成 `async` 立即返回的轮询，`evalJs` 已开 `awaitPromise`）；
4. 最后一个 `--js-file` **采集证据 JSON**（只读提示条文本 / 侧栏菜单 / 行内按钮 / Tab 列表），以单行 `JS> ` 打印 —— **比看截图更硬**；
5. **每个角色用独立 `--profile`** 防 cookie 串味；PNG 输出走 ASCII 路径（`C:/shots/`）。

⚠️ `--js-file` 路径要用**正斜杠绝对路径**；脚本开头的 `taskkill msedge` 会杀掉**所有** Edge → **多角色必须串行跑，不能并行**。

### 验收方法论（本轮最值钱的一条）

**"后端返回 403"和"用户看不到按钮"是两件事，必须分开验。** 前者用接口回归，后者**只能靠真浏览器/SSR 提取可见元素**——纯读代码或纯打接口都验不出来。本轮差点因为"接口已经拦住了"就以为收口完成。
