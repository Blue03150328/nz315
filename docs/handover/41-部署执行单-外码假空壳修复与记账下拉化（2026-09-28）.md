## 0. 本次要推的东西（一句话）

**两件事，5 个文件。**

### ① 外码来源页「假空壳」解析器修复（服务端）

用户扫了 `cx.jilinhengda.com` 的码，公众端显示「这个来源页面**要靠浏览器才能显示内容**，本平台读不到里面的资料」。

- **定因（外站无辜）**：该站是**服务端渲染的完整页**（200 / 17.4 KB / 5 种 UA 含「不发 UA」返回**逐字节同一份** / 无 JS / 无 JSON 接口）。失败在我们自己的 `parseSourceDocument()` —— `sourceText()` 的 `</td>`→Tab 与 `</div>`→换行规则遇到「**td 内再包 div**」时，把「品种名称：」与「亨达美田」拆到**两行、各剩一格**，而含标签路径**只按 Tab 切 + 只认同行「标签：值」** ⇒ `pairs` 为空 ⇒ 三空判据抛错。
- **改法**：兜底③「标签一行、值一行」从 `plain` 专用**放开到全路径**（下行**只取首个 Tab 格**）；新增 `EXTRA_KNOWN_LABELS`（单元识别码 + 原药六项）并入白名单；**新增 `commodityName`（品种名/商品名）单独一档，不参与「产品名称」一致性比对**（这类站写的「品种名称」是**商品名**，并进 `productName` 会误报「与登记资料不一致」）。
- **`SOURCE_PARSER_VERSION`：`2026-09-24.3` → `2026-09-27.4`**（快照缓存键含版本号）。
  ⚠️ **副作用（正常预期）**：线上**所有已缓存的外码快照会一次性失效**，之后每有人重新查看某个外码，就会重新抓一次外站并落一行新快照。存储会涨一点，属预期行为。

### ② 记账表单「补充信息」全部下拉化 + 自定义输入自动聚焦（前端）

- **用户指令**：「我要把这个页面的选项全部做成箭头下拉框选择，而不是直接写在页面上供选择，还有购买渠道的自定义，选择后并不能自己输入」。
- **改法**：原先**平铺在页面上的快捷芯片** —— 单位 7 个、用途 6 个、作物 6 个 —— **全部删掉，收进带箭头的下拉框**（原生 `<select>`，与原来的购买渠道下拉同款：自带箭头、手机上唤起系统选择器）。四个「可预设 + 可自由输入」字段（单位 / 购买渠道 / 用途 / 作物）**统一成同一套交互**：`picker[key] = { preset, custom }` 两半状态 + `PRESET_CUSTOM` 哨兵 + 共用的 `fillPicker()` / `pickValue()`。
- **新增 `onPresetChange()`**：下拉切到「自定义…」时，`nextTick` 后把焦点送进刚出现的输入框。
  🔴 **这一条是针对用户反馈的对症修复**：用户报「购买渠道选了自定义却不能输入」，**对照实验（把组件回退到旧版用真鼠标真键盘复测）证明旧代码逻辑本身是通的** —— 输入框只是**静默出现在下拉下方、落在弹窗滚动区里不显眼**，用户以为没得填。⇒ 自动聚焦（手机顺势滚入视口并弹键盘）。
- **🔴 `fillPicker()` 是编辑态的数据安全线**：老账里 `unit='毫升'` 这类**不在预设清单内**的值，会落回「自定义…」+ 输入框原样回填；否则用户一进编辑看到空下拉、一保存就把原值抹空（PATCH 语义下 `unit` 出现过即被覆盖）。

## 1. 动手前必须记住的六件事

1. 🔴 **`pm2 reload nz315`，只能 reload。** 这台机器上跑着别人的正式站 `www.cynx.cn`（端口 3000），**与 nz315 共用同一个 PM2 守护进程** —— `pm2 kill` / `pm2 delete all` / `pm2 restart all` 会把 cynx 一起带走。
2. ✅ **本轮零 DDL** —— 不改表结构、不补列、不建表。**第 4 步的三明治迁移本轮可跳**（照做只是为了拿"库零变化"的证据）。
   ⚠️ **但**：仍然**绝对不要裸跑** `node scripts/db-init.mjs`（不带 `--migrate-only`）—— 那会执行 `seed()`，往真实库插演示企业、4 条演示追溯码（**进 `trace_code` 核心表**）与演示账号。**要跑就带 `--migrate-only`。**
3. 🔴 **绝不把本机 `.output` 传上服务器，也绝不跳过 `npm run build`。** Nitro 的 `runtimeConfig` 在构建期把 `.env` 内嵌进产物，本机产物里是本机数据库凭据；而本轮改的是**服务端源码 + 前端组件**，不 build 就完全不生效。（本次走 `git archive`，天然不含 `.output`。）
4. ⚠️ **`pm2` 命令不要加 `env PATH=` 前缀**，但 **`npm` 必须加** —— 两者方向相反：`pm2` 的守护进程挂在系统 Node 上，PATH 一变会让 PM2 重建 daemon，**cynx 跟着挂**；而 `npm` 不加前缀会用到系统的旧 Node，构建会失败。
5. ✅ **本次不需要用户重新登录。** 未动 `server/utils/auth.ts`、未动 token 格式。**若有人被要求重登，那不是本次预期，贴我。**
6. 🔴 **粘贴纪律（本轮真的踩了，见 §5'）**：**每个代码块整段粘，别只挑最后几行。** 凡用到 `Q()` / `M` / `$DB_*` 的小节，前面都有一段「**先粘这一段**」—— 它是后面所有命令的**前置条件**；漏了会刷出一片 `Q: command not found`（**看着像数据库炸了，其实只是函数没定义**）。

### 🔧 两条已固化的流程铁律（33 号带下来的，本轮继续照做）

**① `mv .output .output.bak-<TS>` 必须在 `npm run build` 的紧前一行。**
Nitro（node-server preset）的静态资源是**运行期从 `.output/public/` 读盘**的，不是打进进程内存 ⇒ `.output` 一改名，`/`、`/trace` 这类 **SSR 页面照旧 `200`**（服务端代码已在内存里），但 `/_nuxt/*.js`、`/_nuxt/*.css` **连接中断**、`/tools/*.exe` **`500`** ⇒ 用户看到「**页面有字、但没样式没交互**」。
⇒ **需要停顿判断的步骤（备份、核对）全部放在 `mv` 之前，`mv` 之后一路跑到 build 结束。窗口 = 改名那一刻 → build 重新写完那一刻，本轮约 2–3 分钟。**

**② 判「包是否过期」只能逐文件比内容，绝不能比 SHA256。**
`git archive` 会在包首写 `pax_global_header`，**同内容、不同提交打出来的包 SHA256 必然不同** ⇒ 拿 SHA256 判新旧会得出「包全是新的」这种废结论。

> ℹ️ **诚实说明**：本轮**零 DDL、零数据写入逻辑变更** ⇒ 严格讲这个 dump **不是硬要求**。
> 但它是「构建/回滚过程中真出意外」时的唯一完整退路，**几十 MB、一两分钟**，建议照做。**你自己决定**，不做不影响上线。

> 🔴 **两个判据缺一不可**：
> ① **文件大小合理**（不是几十字节）；
> ② **`gzip -dc … | tail -3` 里有 `-- Dump completed on …`**。
> **没有 `Dump completed` = dump 中途断了 = 没有回滚兜底，立刻重跑**（别信"没报错就是成功"）。

> `Access denied; you need (at least one of) the PROCESS privilege(s) ... when trying to dump tablespaces`
> —— **这个错是非致命的**（跳过表空间那一节、业务数据照 dump），但**光看有没有报错会误判成败**，所以判据必须落到上面那两条硬证据上。
