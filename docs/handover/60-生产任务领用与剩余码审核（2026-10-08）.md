# 生产任务领用与剩余码审核

## 业务与操作

用户确认：安卓生产扫码为真实使用依据，生产结束后自动统计剩余码，厂家管理员审核，无需再次扫描空包装。预先领用明确的码清单，领用不写生产信息；扫码成功才绑定生产批次。仅本机开发，不部署。

后台入口`/admin/production-tasks`，侧栏“生产任务与审核”。选择产品、填写任务名/批号/生产日期/有效期至/质检合格/质量合格证号，粘贴或读取每行32位码TXT；最多10000个去重码，需先通过生成页入库留档。领用形成服务器任务，安卓打开任务连续采集。结束后剩余码进入待审核，批准后方可下一批领用。退回继续锁定，管理员可补充原因重新审核。

仅允许未绑定、无生产覆盖资料、正常且前11位匹配产品的码；历史整批绑定无法凭数量自动恢复。已用码不会释放，同码同任务重试返回既有收据；跨任务占用、跨企业和结束后新的扫码均拒绝。扫码失败或断网不能计已用。

## 结构及接口

新增production_task、production_task_code、production_task_review三表；不改旧表结构。任务明细保存完整领用/使用/放行清单，active_code_id唯一约束，已用码保留占用与历史。扫描人、设备、时间由服务器记录，审核保留每次确认人、原因、数量和时间。任务关联的批次资料锁定，旧批量修正/重绑及删除不能绕过占用；有任务历史的码和批次不允许删除。异常冻结/作废入口保留，异常码不能生产或放行。

- GET/POST `/api/admin/production-tasks`：分页列表/创建。创建使用客户端UUID requestId与完整请求哈希实现超时重试幂等。
- GET `/api/admin/production-tasks/:id`：任务资料、四态统计、码明细（100条分页、state筛选）及审核历史。
- POST `/api/admin/production-tasks/:id/scan`：code（32位码或二维码URL）、device，使用记录与码绑定同事务；实际成功由服务器响应确认。
- POST `/api/admin/production-tasks/:id/end`：创建者或管理员结束；与扫码共享产品及任务锁，结束后余码pending，全部用完自动结束。
- POST `/api/admin/production-tasks/:id/review`：管理员approve/reject及必填reason；批准前重查每条余码状态，任一变化整单回滚。

读接口登录可读，写接口requireWritableUser；审核仅enterprise_admin/platform_admin，厂家数据严格隔离。新批次质检必须明确合格。任务锁与旧生产接口产品锁一致；多设备争抢、结束与扫码、审核与下一次领用由数据库事务序列化。
