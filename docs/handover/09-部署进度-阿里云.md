`git commit` 后必须 `git rev-parse HEAD` 校验，报 `ambiguous argument 'HEAD'` 时按此恢复：
```bash

git cat-file -t "$SHA"          # 应返回 commit
mkdir -p .git/refs/heads/feature   # git 会把 refs/heads/<分支>/ 目录整个删掉，必须先建
printf '%s\n' "$SHA" > .git/refs/heads/feature/ewm   # 41 字节
git rev-parse HEAD && git branch -v && git status --short
```

## 3. 本次踩到的坑（下一个接手者必读）

### 3.1 🔴 `.env` 的 DB_PORT 是 3306（差点污染 cynx 生产库）
- 服务器 `.env` 里 `DB_PORT=3306` → **那是宝塔 MySQL 5.7（cynx 的生产库）**。
  若直接跑 `db-init.mjs`，会在 cynx 的 5.7 里建出 `nz315` 库和 14 张表。
- **在建库前的一次安全检查中拦下了**（改端口前**没有**跑过 db-init）。
- 更隐蔽的后续：改成 3307 后应用仍报 `Access denied for user 'nz315'@'localhost'` ——
  因为 **Nitro runtimeConfig 是构建时内嵌的**，`.output` 里还是 3306。
  → **改完 `.env` 必须重新 `npm run build`**（本次已重建，重建后登录即 200）。

### 3.2 `.my.cnf` 会压过 `MYSQL_PWD`（排查耗时点）
MySQL 客户端取值优先级：**命令行 `-p` > 选项文件 `password` > `MYSQL_PWD`**。
给 root 收紧密码并写了 `/root/.my.cnf` 之后，脚本里 `MYSQL_PWD=xxx mysql -u nz315 …` 会**拿 root 的密码去连 nz315**，
报出极具误导性的 `Access denied for user 'nz315'@'127.0.0.1'`。
→ **服务器脚本里连库一律加 `--no-defaults`**：`MYSQL_PWD="$DB_PASSWORD" mysql --no-defaults -h127.0.0.1 -P3307 …`

### 3.3 其余小坑
- **`pm2` 不在 `env PATH=/usr/local/node22/bin:/usr/bin:/bin` 里** → 用绝对路径 `/usr/local/bin/pm2` 或把 `/usr/local/bin` 加进 PATH。
- **`pgrep -f '…index.mjs'` 会误匹配到 cynx**（cynx 也是 Nuxt，命令行同样含 `.output/server/index.mjs`）→ 用 `pm2 pid nz315` 精确定位。
- **`scp` 源路径不要写 `C:/…`**（Git Bash 会把它当远程主机）→ 先 `cd` 到目录再用相对文件名。
- **`grep -c $'\r'` 判 CRLF 会假阳性** → 用 `od -c` 或 Python 数 `\r\n`。
- **长步骤拆成前台小步**：后台 `nohup` 的任务在会话结束时可能被中断（历史上 tar/initialize 都被中断过）。
- **本地脚本经 `ssh 'bash -s' < file` 上传执行时**：文件必须是**纯 LF**，否则行尾 `\r` 会让 `set +a`、`nginx -t` 之类命令报奇怪的错 → 上传前一律 `tr -d '\r'`。
