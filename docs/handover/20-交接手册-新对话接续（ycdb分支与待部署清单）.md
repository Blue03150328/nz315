## 2. 今天（09-22）这条线：外部二维码核验

### 2.1 用户要什么

用户拿一瓶**真实农药的瓶标二维码**（码值 `10929272500926240000223813617201`，来源是第三方平台 **`mashangzhuisu.com`**），要求：

> 「先用相机扫码出来**别人的**二维码，提取到**别人的码中的信息**后，再进行字段匹配到我们数据库的**相同产品**，最后给出具体结果。」

**注意语义**：不是"把我们自己的码当成外部码"，而是**拿别人的码当输入，用我们的登记库当基准去核验它**。

### 2.2 改前的天花板（为什么非改不可）

`ycdb` 上原有的外部核验**只对 `wla1.cn` 有专用接口**，其余平台统一走 `fetchGenericPage` 兜底——**而那个兜底只把页面 `<title>` 当产品名**。第三方平台实测是**纯 JS 渲染**，服务端拿到空壳 HTML、`<title>` 里也没有产品信息 ⇒ 整条链路只能返回"信息不足"。

**用户在两方案间明确选了"后者"= 通用字段提取**（另一方案 = 为该平台写专用适配器，即逆向别人的私有 API，随时失效，不可持续）。

### 2.3 现在的做法（`server/utils/external-verification.ts`）

**四路兜底（`extractLabeledFields`）**：① **JS/JSON 键值对**（`"productName":"xxx"`）② **逐行「标签:值」** ③ **表格相邻单元格**（`stripHtmlToText` 特意把 `td`/`th` 转制表符，让同行「标签｜值」能拼回一段文本）④ **标签独占一行则取下一行**。

配套三件套：`FIELD_ALIASES`（9 字段 × 中英标签/键名别名）· `NOISE_LABELS` 噪声黑名单（使用方法/产品性能/注意事项…，防把"注意事项"后的长段落当字段值）· `cleanFieldValue`（拒超长文本 / 链接 / 占位词）。

**兜底通道（纯 JS 渲染平台的唯一解）**：接口新增 `pageText` 入参（`fetchFromProvidedText`），`verifyExternalCode` **支持从粘贴内容里识别追溯码**；后台页新增「在新窗口打开来源页面」+ 页面内容粘贴框，结果区补展示 `剂型 / 毒性 / 有效期至`。
⇒ 流程是「**开链接 → 肉眼复制正文 → 粘回核验**」——**这是设计好的路径，不是缺陷**。

### 2.4 三个实测踩坑（★ 值得记）

| # | 现象 | 根因与修法 |
|---|---|---|
| ① | 只给 URL 时接口 **500** | `redirect: 'error'` 是"看起来更安全"的反面教材：`http://mashangzhuisu.com` 会 301 到 https，fetch 当场抛 `unexpected redirect`。改为 `fetchSourcePage`（`redirect:'manual'`）：**同站 http→https 放行一次、跨站跳转拒绝 400** |
| ② | **「见喷码」被当成生产日期**落进结果 | 占位词正则原为 `/^(见\|未知\|无\|…)$/`，而真实标签写的是"见喷码"**三个字**。已改为 `/^(见(喷码\|包装\|标签\|瓶身\|实物)?\|未知\|未提供\|不详\|待补充\|待定\|无\|-\|—\|\/)$/`。**教训：占位词按真实标签怎么写穷举，别按想象写** |
| ③ | 「2.85%硝钠·萘乙酸」≠「硝钠·萘乙酸」**假差异** | 来源页带含量、登记库不带 ⇒ 严格比对必 mismatch。新增 `normalizeProductName` 剥掉含量段做**宽松比对**；宽松命中结论仍 `match`，但附备注「仅含量标注写法不同（含量请人工复核）」——**既不误报差异，也不假装完全一致** |

**另一个刻意的设计决定**：`fetchGenericPage` **不再用 `<title>` 冒充产品名**。`<title>` 常是"XXX公司-追溯查询平台"，拿它当产品名只会制造**比空值更难排查的假差异**；宁可留空并在 `warnings` 里引导用户粘贴。

### 2.5 验证结果（可复跑）

- **接口三路径全 200**：仅 URL / URL+粘贴 / 仅粘贴。
- **最强的一条：只粘贴正文、不给链接也不给码值** —— 码被从正文里**自动认出**，平台标记「手工提供内容」，9 个字段全部提取正确（`2.85%硝钠·萘乙酸` / `500克` / `水剂` / `低毒` / `PD20092927` / `河南欣农化工有限公司`），**生产日期为空**（"见喷码"被正确拒掉 = 踩坑②修复生效的证据），六项核验**全部 match**。
- **真浏览器端到端**（**同一会话内**真实登录 → SPA 跳转 → 填表 → 点【开始核验】）：结论 **「已核验项目未发现差异」**，截图 `C:/shots/ext-verify-result.png`。
- **业务结论**：前 8 位 `1-092927-2`（1=PD + 登记证后六位 092927 + 2=委托加工）命中登记库 `PD20092927` 硝钠·萘乙酸 / 河南欣农化工有限公司；**登记数据存在（`pesticide_reg` 97,471 条）但我方无该产品** ⇒ `localProduct` 为空。**这正是"外部核验"应有的形态**。

> ⚠️ **CDP 会话 Cookie 不跨浏览器实例保存** ⇒ 真浏览器验证必须"登录 + 跳转 + 操作 + 断言"在**同一个会话**跑完，否则会误判成"被踢回登录页"。

1. **绝不影响 `www.cynx.cn`**。它跑在 3000，nz315 跑在 3100。
2. **绝不 `pm2 kill` / `pm2 delete all`** —— 两个站**共用 PM2 daemon**。nz315 靠 per-app `interpreter` 指到 `/usr/local/node22/bin/node` 与 cynx 的系统 Node v20 隔离。**只能 `pm2 reload nz315`**。
3. **`nz315.conf` 里绝不写 `listen 443 ssl default_server`** —— 会抢走 cynx 的默认 443。
4. **改了服务器 `.env` 就必须重新 `npm run build`** —— Nitro `runtimeConfig` **构建期内嵌**，改 `.env` 不 rebuild 运行期不生效。
5. **绝不把本机构建的 `.output` 传上服务器** —— 本机数据库凭据会被内嵌进产物，线上会连错库。
6. **生产库绝不裸跑 `db-init.mjs`**（理由见 §5）。**`--migrate-only` 一律带上。**
7. **部署顺序有因果：补列 → 构建 → `pm2 reload`**。别换序。
8. **静态资源清单构建期固化** —— 要放的静态文件（如工具包 EXE）**必须在 `npm run build` 之前**放进 `public/tools/`；build 之后再放 = **404，`pm2 reload` 也不管用**。
9. **服务器操作全部由用户逐条粘贴执行**，SSH 在我这边不可用；每条命令都要标明期望输出。
10. **一轮修改 = 一次提交**，提交信息用中文约定式（`feat:`/`fix:`/`docs:`/`refactor:`/`chore:`）；重要变更还要在 `PROJECT_LOG.md` 顶部加一条 + 同步 `AGENTS.md` 进度段。**`.env` / 凭据一律不提交。**

## 7. 踩过的坑（下一轮别重复）

### 7.1 本机沙箱环境（Windows，高频）

| 坑 | 现象 | 绕过 |
|---|---|---|
| **`rm` 被安全 shim 拦死** | `dirname: command not found`，exit 127 | **删文件一律用 node**：`fs.unlinkSync` / `fs.rmSync(dir,{recursive:true,force:true})` |
| `tail` / `head` / `wc` / `sleep` / `grep` / `find` / `ls` 多数不可用 | 管道破裂、无输出、exit 127 | 长命令输出用 `> 日志文件 2>&1` 落盘再 `Read`；查找用 Glob / Grep 专用工具 |
| `schtasks` / `sc.exe` 被策略拉黑 | 不可重试、不可绕过 | 查计划任务用 PowerShell `Get-ScheduledTask` |
| PowerShell stdout 可能整体被吞 | exit 0 但没有任何输出 | node `child_process` 起子进程 + `writeFileSync(...,'utf8')` 落盘再读 |
| 无 `gh` CLI、无 `mysql` 客户端 | — | 直连库用 `mysql2` 读 `.env` 取凭据 |
| 本机 git 写不了「嵌套引用」 | `refs/heads/a/b` 建不出来，**且所有命令都 exit 0 无报错** | 本地分支名**用平铺名**（`ycdb` 而非 `feature/ycdb`）——项目里既有 `feature--qd` 就是这个坑的历史受害者 |

### 7.2 真浏览器验证（本项目通用）

用全局技能 `browser-ui-screenshot`（Edge headless + CDP）。本项目是 **Nuxt UI v4 而非 Element Plus**，脚本自带的 `--click` 命中集合用不上，走 **`--js-file` 逃生口**。

- **点之前必须等 Vue 水合完成**（`#__nuxt.__vue_app__` 出现），否则点击**静默无效**（不报错、没效果）——这是最容易误判成"功能坏了"的假阴性。
- **dev 下验客户端跳转要先预热目标路由**：首次编译慢（1 秒级），采样窗口太短会误判成"导航没生效"。**用多点采样（如 4×400ms），不要单点断言。**
- **判定"`back()` 是否生效"的替代判据**：CDP 报 `Inspected target navigated or closed` 就说明导航真的发生了。
- **会话 Cookie 不跨浏览器实例** → 登录 + 操作 + 断言必须在**同一个会话**里跑完。
- `--js-file` 用**正斜杠绝对路径**；脚本开头的 `taskkill msedge` 会杀掉**所有** Edge → **多角色必须串行跑，不能并行**。

### 7.3 方法论（本项目最值钱的两条）

1. **`router` 这类"模板自由变量"静态检查抓不到。** 模板里写 `router.push()` 而 `<script setup>` 里没 `const router = useRouter()` —— `node --check` / SFC 编译 / tsc **全部静默通过**，只有真点下去才抛 `TypeError: Cannot read properties of undefined (reading 'push')`。**改了模板或 `setup()` 引用就必须真浏览器点一遍。**（09-22 实测：同类共三处。）
2. **"后端返回 403"和"用户看不到按钮"是两件事，必须分开验。** 前者用接口回归，后者**只能靠真浏览器 / SSR 提取可见元素**——纯读代码或纯打接口都验不出来。

见 **§2.4**（`redirect:'error'` 致 500 / 「见喷码」溜过占位词闸门 / 含量写法差异造成假 mismatch）。
