## 2. 为什么要合并（背景：两份实现已经分叉）

合并前，「抓外部页面并解析」这件事在项目里有**两套并行实现**：

| | **M1 公众侧** | **M7 后台侧**（合并前） |
|---|---|---|
| 实现 | `server/utils/source-parser.ts`（**带** `SOURCE_PARSER_VERSION`） | `server/utils/external-verification.ts` **内联**（`stripHtmlToText` / `normalizeLabel` / `FIELD_ALIASES` / `extractLabeledFields` / `extractOriginals` / `normalizeProduceDate`，**无版本号**） |

| 生产日期 | `actualDate()` 只认明确日期 | 宽松 + 「见喷码」映射 |
| 标签归一 | 仅去空格/括号 | 全角转半角 + 去 20+ 标点 |
| JS/JSON 键提取 | ❌ | ✅ |
| 落表 | `external_source_snapshot` | `external_verification` |
| 判定 | `source-compare.ts` **4 态**（含 `review` 降级）、**只读不预警** | 6 项内联判定、**mismatch 触发预警 3/5/6/7** |

**收敛方向**：内核取两边之长（M1 的组边界配对 + 严格日期 + 版本号，并入 M7 的同义词表 + 全角归一 + 脚本键提取 + `spec`），**各自保留适配器与判定语义** —— 这是刻意不合并的部分。

> 🔴 **一处重要的旧结论更正（2026-09-24 13:5x）**：M7 那份「下标拼装」并**不会**造成假预警 —— `verifyExternalCode` 的 `items` **只有 6 项**（`code-format` / `registration-suffix` / `registration-no` / `product-name` / `holder-name` / `production-type`），**根本不含原药项**，`originals` 不参与判定、不触发预警。它的真实影响是**落库数据质量**（`external_verification.source_data` 里原药企业与证号可能错位 ⇒ 人工回看历史工单被误导）。**别再把这条当"生产事故级"讲。**

## 4. 🔴 最关键的设计：纯文本与 HTML 是两条口径（改这里之前必读）

`sourceText()` 的第一句原本是 `.replace(/\r?\n/g, ' ')`（**为 HTML 设计**：源码里的换行属排版噪声，行结构只由块级标签产生）。**它在纯文本上是错的** —— 手工粘贴的整段文字会被压成一行，逐行配对全废。

现在内核用同一个探测区分输入：

```ts
const plain = !/<[a-zA-Z!/][^>]*>/.test(input)   // 不含标签 = 纯文本
```

| 输入 | 口径 | 谁在用 |
|---|---|---|
| **纯文本**（无标签） | **保留换行**；行分隔认「**冒号** / **Tab** / **2+ 空格** / **换行**」四种；含「标签一行、值一行」兜底（取下方 1–2 行内首个非空行，下一行本身是「标签：值」或纯标签则**不给值**，避免串行） | **M7 后台「手工粘贴页面内容」**（`fetchFromProvidedText`） |
| **含标签的 HTML** | 源码层换行**先压平为空格**，行结构只由块级标签产生；**不再启用**「分行」兜底 ⇒ **口径逐字节不变** | **M1 公众端 `/api/trace` 外页快照**（`fetchGenericPage`） |

🔴 **铁律：纯文本特有的兜底一律挂在 `plain` 探测下面**，否则会连带改变公众端快照的填充口径。
🔴 一刀切压平 `\r?\n` 会立刻打断 M7 手工粘贴通道（**2026-09-24 实测踩到，见 §5**）。

## 5. 抓到的真回归（现象 / 取证 / 修法）

### 现象
四路回归的用例 A（手工粘贴**与登记库完全一致**的多行文本）—— `registration-no` / `product-name` / `holder-name` **三项全判 `insufficient`**，`source.registrationNo` **为空**。而后台核验页的失败提示原文明确承诺「标签与值之间用**冒号、Tab 或换行**分隔」。

### 根因
内核 `sourceText()` 把 `\r?\n` 一律压成空格 ⇒ 纯文本整段并成一行 ⇒ `pairs` 只剩一个畸形对（`["农药名称", "0.5%溴敌隆母液 农药登记证号：…"]`）。

### 取证（这一步决定了"回归"还是"既有缺陷"）
```bash
git show HEAD:server/utils/external-verification.ts   # 合并前的实现
```
旧 `stripHtmlToText` **不压平换行**（只把块级标签转成 `\n`），`extractLabeledFields` 用 `text.split(/\r?\n/)` **逐行配对**，并且明确支持「形式 C：取下一非空行」。
⇒ **合并前纯文本多行是能解析的** ⇒ **确认是合并引入的回归，不是既有缺陷**。

### 修法
按 §4 的两条口径分流，并**恢复**「标签一行、值一行」兜底（比旧实现更严：下一行本身是标签时不取值）。

### 护栏
`tests/source-snapshot.test.mjs` 用例 7 / 8 把这个行为钉住（含「含标签的 HTML 不启用分行兜底」这条**刻意保留的边界**）。
