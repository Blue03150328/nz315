## 用户确认的规则

内部码的判定不要求生成时先入库。有效的农资315扫码网址即可识别为系统内部码；实际生产采集上传形成生产记录后正常展示产品与生产资料，否则显示“系统内部码 · 尚无生产记录”。生成留档不能作为已生产的证据。

| 输入及记录情况 | 公众查询结果 |
|---|---|
| 本站有效扫码网址，库中没有码 | `internal-pending`，尚无生产记录 |
| 本站有效扫码网址，仅生成留档，没有生产记录 | `internal-pending`，尚无生产记录 |
| 本站有效扫码网址，生产采集直接上传后形成生产批次 | 正常展示实际资料，并继续执行异常检查 |
| 已有有效工人采集记录，尚待质检 | 展示真实生产资料及待质检状态 |
| 已冻结或作废 | 保留原警示，作废不展示产品与批次 |
| 已生产且有效期已过 | 保留产品过期警示，使用单码更正后的最终日期 |
| 外站网址，码值恰好与本站记录相同 | 仍按外码查询，不冒用本站生产信息 |

网址归属不证明产品已生产、质检合格或真伪。

## 网址及入口

- 默认识别`www.nz315.cn`与`nz315.cn`的`/trace`入口，HTTP/HTTPS默认端口均可；部署配置的`runtimeConfig.public.traceBaseUrl`按相同源和路径识别。
- 必须只有一个`code`参数，内容为32位数字。相似域名、其他路径/端口、重复参数、凭据、片段、半截链接、浏览器自动修正路径均不作为有效内部扫码网址。
- 有效来源码与查询码不一致时拒绝查询。本站无效来源链接不抓取自己的页面。
- 直接打开瓶身`/trace?code=...`时，公众页面补上配置的扫码入口；扫码和首页手输保留原文，避免将外站或裸数字误包装为本站链接。
- 纯32位数字手输保留原查库兼容行为：已入库码查本站记录，未入库码仍走登记资料比对。裸数字缺少网址，不能仅凭它认定为内部码。

## 修改与业务边界

网站共享规则在`shared/utils/internal-trace-url.ts`，结果类型新增`internal-pending`；`server/api/trace.get.ts`以真实批次或`workerTracePreview`有效采集结果判断有无生产资料。未生产查询不创建码、不写扫码日志，不触发外站抓取。预览所需`worker_pool_code`/`worker_run`表缺失时仅该预览返回无记录，其他SQL错误继续报错。

主采集器`regcode-production`的工人外码模式使用`TraceUrlPolicy`按原始网址分类；服务器缓存下发`traceBaseUrl`，本地缓存保存该配置，默认仍使用正式域名。后台收据、列表、明细和TXT导出支持新分类`internal`/`external`/`unparsed`，原`own`/`other_enterprise`/`not_imported`历史行仍可查询与导出，不批量重写历史。

本轮不修改生产任务创建、领用、成员和分配清单约束，不把任意本站网址当作可生产的已领码。外码模式仅保存采集原文与分类，不自动创建内部生产记录；旧独立采集器及原文外码队列协议保持原有行为。
