## 1. 定因：上一轮的结论错在哪

### 1.1 两站都不是服务端渲染 —— 实抓就是空壳

上一轮（另一个 Agent）的结论是：

> 「`www.sdakzw.com/nyzs/完整32位码` 是服务端完整 HTML 页面，浏览器直接能看到产品、批次、原药信息，不需要 JavaScript 接口」
> 「`zp.hyny168.cn` 页面实际返回的是完整表格数据……并没有必须调用的公开 JSON 接口」

**两条都反了。** 本机实抓（2026-09-28）：

| 站点 | 实抓 | 实际是什么 |
|---|---|---|
| `http://zp.hyny168.cn/ny?c=<码>` | **200 / 12,107 B** | Vue 空壳：`<div id=app>` + 「正在加载系统资源，请耐心等待」+ webpack 运行时（52 个 chunk 映射） |
| `http://www.sdakzw.com/nyzs/<码>` | **200 / 1,661 B** | Vue3 + Element Plus 空壳：`<div id="app"></div>` + `/frontassets/js/index-*.js` + `/config.js` |

**为什么会看错**：浏览器里「直接能看到」是因为**浏览器替它们执行了 JS 并调了接口**。
把这两份 HTML 丢给我们的 `parseSourceDocument()`，剥离 `<script>` 之后剩下的就是一句加载文案 ——
`tests/source-adapters.test.mjs` 里那条「两站是纯前端空壳」用例把这一点钉住了
（断言通用解析在两份**真抓 HTML** 上一个业务字段都取不到）。

⇒ **标签根本不在抓下来的 HTML 里，补多少标签别名都不会有用**。这是本轮最关键的判断。

### 1.2 真正缺的是「按它们自己的接口取数」

| 站点 | 页面自己怎么取数（照抄其前端源码） | 我们复用什么 |
|---|---|---|
| hyny168 | axios 实例 `baseURL = '/prod-api'`；`/ny` 页调 `getTrace2()` → `GET /trace/{码}?reauth=` | `GET {页 origin}/prod-api/trace/{码}`（匿名可用、无鉴权头、无 Referer 校验） |
| sdakzw | `/config.js` 里 `window.__env__.VITE_API_URL = "http://api.sdakzw.com"`；结果页调 `GET /api/nongYaoItem/zhuisu/{码}`，`type === 'success'` 后取 `result` | 同左（实测未登记的码返回 HTTP 200 + `{code:400,type:"error",message:"单元识别码不正确…"}`） |

**字段名一律抄自对方自己的代码**，不靠猜：

* hyny168：页面 chunk 里的 `fieldMap`（label ↔ 字段一一对应）；
* sdakzw：结果页渲染函数里的绑定（`label:"农药名称："` 紧跟 `c(a.data.nongYao.nongYaoName)`）。

两条都写进了适配器头注释，日后外站改版时可逐条对。

### 1.3 顺手回退了一个「已提交但会读坏既有站点」的改动

`f820bcd`（上一轮，16:09 提交）给解析器加了三个通用兜底：`extractAttributeFields`、
`extractConcatenatedFields`、脚本键取数字。它当时**只在合成 HTML 上过了单测**，没做真实页面对照。
本轮补做 **`.4` vs `.5` 六个真实页面逐字段对照**（`logs/_equivalence-45.txt`），结果是**两处读坏**：

| 页面 | 变化 | 危害 |
|---|---|---|
| `ddspp.cn` | `batchNo`：`无` → `见瓶盖或瓶体，袋装请见喷码` | 那是「生产日期及批号」的**说明文字**，被全文标签扫描误当**批次** ⇒ **凭空声明了一个批次**，会进「生产日期及批号」比对项与后台展示 |
| `nyzs315.com`（空壳） | `productName` 变成 `商标名称：`、`holderName` 变成 `识别代码：/追溯网址：/农药类别：` | 原先读不出 ⇒ 正确落 `empty-shell`；现在有了**假产品名**，空壳判据不再触发 ⇒ 消费者看到**一页编造的字段** |

逐层单独跑（`logs/_layer-attrib.txt`）定位到**责任人是 `extractConcatenatedFields`**
（`extractAttributeFields` 在样本页面零命中；脚本键层无变化）。
**没有任何一个站点因为这次「扩展」多读到正确内容** ⇒ 整体 `revert`（`62561ef`），解析器版本回到 `2026-09-27.4`。

> 教训（值得写进 AGENTS 踩坑表）：**「合成 HTML 单测全绿」证明不了「真实页面没被读坏」**。
> 改解析口径必须做真实页面的**逐字段对照**，且要拿**有值**的页面（空壳页对照不出问题）。

## 2. 实现

### 2.1 适配器三态（新增第三态）

原先 `adaptSourceDocument()` 只有「拿到声明 / null（退回通用抓取）」两态。
问题是：**对方明确答复「查无此码」时，退回通用抓取会撞上空壳页**，
于是消费者看到的是「这个来源页面要靠浏览器才能显示内容」——**把对方的答复说错了**。

新增第三态 `{ notFound: true }`：

```
拿到声明 ⇒ 正常展示
{ notFound: true } ⇒ snapshot.issue = 'source-not-found'
                     文案「这个来源平台查不到该码，请核对包装上的二维码是否与本次扫描的一致」
null ⇒ 退回「抓页面 + 通用解析」（行为与从前完全一致）
```

- `SourceIssue` 多一档 `'source-not-found'`（`shared/types/source-snapshot.ts`），与 `empty-shell` 区分：
  **「我们没读懂」≠「对方说没有」**。
- 前端**不读** `issue`（实测 `app/` 下零引用，只显示 `message`）⇒ 本次改动**后端闭合**，不动前端。
- 判定门槛照抄对方自己：hyny168 用 `data.exists === false`；sdakzw 用 `type !== 'success'` 且
  message 命中 `单元识别码不正确|不存在|未找到|查无`（其它 error 一律不认，退回通用抓取）。

### 2.2 关键取舍（都写进代码注释了）

| 取舍 | 理由 |
|---|---|
| 码必须是标准 32 位，否则**不发请求直接放弃** | 不猜、不截；短码/异常码交给通用路径 |
| hyny168 顺带镜像对方「隐藏批次/生产日期」开关（`showBatchNo` / `showProduceTime` 为 false 时我们也不声明） | 对方页面此时显示「详见包装」；把厂家刻意不公开的批次当「已核对内容」是不对的 |
| sdakzw **不采集**「检验报告：合格」 | 那是它模板里**写死的常量**（`g("span",null,"合格")`），不是接口数据 ⇒ 绝不能当证据 |
| 两站的「商品名称」都进 `commodityName`（**只作展示**），绝不并进 `productName` | 沿用 39 号口径：并进去会让正规药误报「与登记资料不一致」 |
| 原药逐条配对（`rawName/permitNumber/rawCompanyName`、`name/dengJiZhengHao/producer`），缺字段留空不多补 | 沿用既有原药配对红线 |
| 核心字段（产品名/证号/持有人）全空 ⇒ 返回 null | 宁可不展示，也不把空数据当「来源页已核对」 |

### 2.3 🔴 代价（与 nyzs315 同族，必须知情）

**每成功调用一次，都会在对方系统里留下一条扫码记录** —— hyny168 实测响应带回 `scanNum`/`firstScanTime`，
且对方写出了 `scanLogId`；**对不存在的码同样会写**（本轮排查期间就写了几条）。
缓解手段：与快照共用 10 分钟缓存（同码同址 10 分钟内只调一次）+ 仅白名单宿主启用。
**要停止污染对方统计**：删掉 `source-adapters/index.ts` 里那一行登记即可整体下线（两站各自一行）。
