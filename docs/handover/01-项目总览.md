# 01 · 项目总览

> 生成日期 2026-09-10 · 对应版本 `master@98a4a1c` · 全部数据来自实测

## 1. 一句话定位

**农资315 · 农药追溯码管理平台**：面向**农药生产企业**的追溯码全生命周期 SaaS——企业在此生成 32 位追溯码、上传/绑定生产批次，消费者扫码即可看到产品、原药、批次、质检信息，后台提供码库、风控、统计与多租户账号体系。

- **合规驱动**：依据《农业农村部公告第 1049 号》，**2026-11-01 施行**（原 2579 号公告废止），是项目全部排期的刚性倒排节点。
- **对外域名**：`www.nz315.cn`；扫码 URL 规范 `https://{域名}/trace?code={32位追溯码}`。
- **本地代码目录**：`E:\wokeplace\二维码管理`（`package.json` 内 name 为历史遗留 `qrcode-redirect`，version `0.1.0`）。

## 3. 系统由两个端组成

### 3.1 公众端（消费者 H5，SSR 秒开）

| 路由 | 页面 | 说明 |
|---|---|---|
| `/trace?code=` | 扫码查询结果页 | 核心页：正品/异常差异化展示（单卡片布局：产品信息 + 批次三要素 + 多原药组分） |
| `/scan` | 沉浸式扫一扫 | BarcodeDetector 原生优先 + zxing 兜底，相册选图降级（iOS 微信禁调相机） |
| `/nearby-stores` | 附近农资店 | 高德 POI 实时检索（1km 网格缓存 10 分钟），PC 双栏 / 移动折叠地图 |
| `/profile` | 个人中心 | 微信网页授权登录后可见查询档案/历史（数据取自 `scan_log`） |
| `/` `/login` `/q/:code` | 首页 / 后台登录 / 旧路径重定向 | — |

**扫码结果类型**（`shared/types/trace.ts`）：`genuine` 正品 · `not-found` 查无此码 · `reg-expired` 登记证过期 · `expired` 产品过有效期 · `repeat` 重复查询 · `frozen` 已冻结 · `voided` 已作废 · `mismatch` 信息与标签不符。

## 4. 角色模型（4 类）

| 角色 | 标识 | 数据范围 | 能力 |
|---|---|---|---|
| 总部管理员 | `platform_admin` | 全部企业 | 唯一可管理企业入驻/续费/删除、用户权限、数据备份 |
| 厂家主账号 | `enterprise_admin` | 本企业 | 本企业全部业务 |
| 码管理员 | `code_admin` | 本企业 | 码生成/上传/库管理（无用户管理） |
| 只读账号 | `viewer` | 本企业 | 仅查看，一切写操作被 `requireWritableUser` 拦截 |

**双重登录闸门**（2026-09-09 新增）：厂家账号登录时与**每次业务请求**都校验所属企业 `status=1` 且 `renew_expire >= CURDATE()`，续费到期即 403（7 天会话跨越到期点同样失效）。

## 5. 核心业务链路（一条码的一生）

```
后台上传/生成
   │
   ├─ 追溯码生成页 → 选产品/规格/数量 → 生成（1-11 位强制结构 + 12-32 位固定段）
   │       ├─ 导出 urls.txt / TXT / CSV、二维码图片 zip
   │       └─【入库留档】→ status=1 已生成（可扫码查产品，无生产信息）
   │
   ├─ 追溯码上传页 → 上传码文件 → 智能提取 32 位码 → 结构/归属/查重校验
   │       └─ 填生产日期+批号+合格证号 → 批次自动建档或归并 → status=2 已绑定
   │
   └─ 码库管理（聚合视图）→【修正】把已生成的码绑定到批次（闭环）→ status=2

扫码（消费者）→ /trace?code= → 写 scan_log → 异常判定（作废/冻结优先）
   → 联查 product / product_original / batch → 渲染结果页
   → 命中异常条件时 triggerAlert() 写 risk_alert + 发站内信
```

## 6. 必须记住的 5 条业务规则

1. **32 位码结构**：第 1 位登记类别（1=PD/2=WP）+ 第 2-7 位登记证号后 6 位 + 第 8 位生产类型（1 持有人生产/2 委托加工/3 委托分装）+ 第 9-11 位规格码（企业规格主数据）+ 第 12 位后企业自定义。
2. **码只有两个状态**：`status=1` 已生成（可查、无生产信息）→ `status=2` 已绑定（**生产日期 + 批号 + 质量合格证号三要素齐全时自动流转**）。
3. **异常标记与状态正交**：`abnormal_flag` 0 正常 / 1 冻结 / 2 作废；**作废是终态不可恢复，作废码扫码不展示产品与批次信息**；冻结码仍展示基础信息。
4. **扫码不改变码状态**（无核销动作），只写 `scan_log`。
5. **唯一性红线**：登记证号全局唯一；规格码被追溯码使用后不可修改；同产品下批次号唯一（`batch.uq_product_batch`）。

## 9. 立刻要警惕的 7 个坑（详见 03/05 文档）

1. **dev 模式不可用**：Nitro 2.13.4 + Node 24 + 中文路径导致 ESM loader 500 → 一律用生产构建验证。
2. **`query()` 解构陷阱**：项目封装的 `query()` 返回**行数组本身**；取单行 `const [row] = await query()`，取多行**不要解构**（2026-09-10 因此出过一次线上级 500）。
3. **多租户 SQL 条件前缀必须 `' AND …'`**，用 `' WHERE …'` 会拼出双重 WHERE（厂家账号 500，总部账号不复现→验证盲区）。
4. **构建失败会清空 `.output/server/chunks`**，正在跑的服务页面路由会 ERR_MODULE_NOT_FOUND → 失败后必须重跑完整构建。
5. **端口 3100 是本项目开发端口**（3000 被「农码查」残留实例占用）；3080 是 DSH Web GUI，3306 是 MySQL。
6. **Nuxt UI v4 写法**：`UModal` 必须 `v-model:open` + `#content`；`USelect` 用 `:items`；`UTabs` 的 items 必须带 `value`；`UToaster` 需显式挂载。
7. **无物理外键**：全部靠代码保证一致性；删除类操作必须自己做引用检查（现有范式见 `enterprises/[id].delete.ts`）。
