## 7. 需求接收与变更约定（本项目工作方式）

1. **一轮修改 = 一次提交**，提交信息中文 + 约定式前缀（`feat:/fix:/docs:/refactor:/chore:`）。
2. 每次变更必须在 `PROJECT_LOG.md` **顶部**追加变更记录（现象/根因/修改文件/测试情况/遗留问题/给下一个 Agent 的提示），并同步 `AGENTS.md`「项目进度」段。
3. 需求落地前先**澄清概念**（历史教训：用户说「删除生产批次板块」实为「流程太绕」，最终方案是自动建档），避免直接照字面实现。
4. 用户提出的**展示类**需求（删/改文案、布局）与**数据类**需求（字段增减）处理方式不同：前者纯前端改动要零后端影响；后者必须前后端同口径校验（参考「7 项必填」的 `ENT_REQUIRED` ↔ `requiredFields` 双端同步）。
5. 参考项目「农码查」**只能取视觉，不能取逻辑**（它是 Mock 原型，曾移植出 767 行死代码与一个返回伪造核验结果的演示接口）。
