## 6. 🔴 铁律（违反会出生产事故 —— 别凭记忆，照这几条执行）

1. **`node scripts/db-init.mjs --migrate-only` 的 `--migrate-only` 绝不能省**。不带参数的 `db-init` 会跑 `seed()`，
   往生产库实打实插入演示企业 / 4 条演示码（含冻结作废码）/ 演示产品批次 / `admin123` 演示账号 = **生产数据污染**。
2. **与 `www.cynx.cn` 共用同一个 PM2 daemon**：只允许 **`pm2 reload nz315`**，
   **绝不** `pm2 kill` / `pm2 delete all` / `pm2 restart all`（会把同机的 cynx 一起带走）。
   **pm2 命令不要加 `env PATH=` 前缀**（Node 版本与 daemon 不一致会让 PM2 重建 daemon）。
3. **顺序固定：补列 → 构建 → reload**。`nuxt.config.ts` 的 runtimeConfig 是**构建期内嵌**的 ⇒ **改 `.env` 必须重新 build**。
4. **`public/tools/nz315-qr-tool-v1.2.0.exe` 必须在 `npm run build` **之前**就在位**（Nitro 静态资源清单构建期固化，build 之后再放 = 404，reload 也不管用）。
5. **三明治的基线必须在迁移【之前】dump**（`verify-db-migration.mjs dump` → `db-init --migrate-only` → `compare`）。
6. **`scripts/seed-abnormal-demo.mjs` 禁止在生产跑**（它造的是异常演示码）。
7. **只跑本次范围内的事**（本次不碰 nginx、不碰 `.env`、不重传工具包）—— 其他待办另开窗口，风险要隔离。
8. 写 SQL 的片段要**自包含**：凡依赖前序步骤设的 shell 变量，要么在片段里重新赋值，要么明确"整段一起粘"
   （上一轮就因 `$M` 空串报过 `bash: --no-defaults: command not found`）。
