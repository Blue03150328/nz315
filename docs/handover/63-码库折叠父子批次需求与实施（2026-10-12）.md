# 码库折叠父子批次需求与实施

本机已完成父子批次、采集器固定上传边界和包装规格快照，完成独立生产构建、接口与页面验收，并已安全迁移本机数据库。未推送、未部署线上、未安装手机或完成实机扫描验收。62号保留为此前数量汇总的历史记录，当前功能以本文件为准。

## 用户确认口径

- 原始码文件为总批次，例如10万张；展开后同级显示第一次已用2万张、第二次已用3万张、当前剩余5万张，不采用8万下继续套娃的结构。
- 根据真实成功上传的新码划分；重复和错误记录不扣剩余量，不生成空已用子批。
- 主采集器保留边扫码边自动上传，新增“完成本次上传”划界。两次完成之间的记录属于同一上传批次，网络分段、重试和断网恢复不另起子批；完成本次上传与结束采集/结束生产任务分开。
- 子批可独立查看详情、修正、冻结/恢复/作废、导出以及符合原规则的删除；剩余子批可进入新建生产任务并预选产品与来源。
- 总批次保留原全部操作，危险动作先弹窗说明影响全部子批、码数量与不可恢复后果。已绑定码禁止物理删除、作废终态等原约束继续有效。
- 每个码全局唯一且只可成功使用一次，一个任务允许从同产品、同规格的多个总批次取不同的码。
- 在已用子批更正生产日期、批号等共用资料时，同步整个关联生产任务，包括其他总批次中的关联码；不能扩大到同生产批号但属于其他任务的码。操作前说明同步范围。
- 未被领用的余码可直接分配；原任务已领未用的码须结束任务并审核通过后才可再次领取；冻结/作废码不可领取，已用码冻结/作废不退回剩余库存。
- 旧数据没有固定单次上传边界，暂时仅总批汇总，不按时间猜分组、不建立历史已用子批。新流程启用后才建立固定子批。
- 规格列只展示包装规格（如500毫升/瓶×10），不显示规格码；以后产品规格改为1升/瓶，旧批仍保留500毫升/瓶。旧资料无法核实则明确提示，不套用当前规格。
- 上传来源、采集/收到时间及个人上传账号继续保留。账号模块由用户同事开发，本轮只预留可信账号接口，不伪造设备登记人为上传人。

## 实施记录

### 父子批次与管理范围

码库主行保留总批次及原有操作，默认折叠；展开时按分页查询同级已用子批及唯一动态剩余行。10万张先用2万、再用3万，显示两个已用子批和5万剩余。历史已用量仍在父行累计，明确提示未记录上传边界，不猜造历史子批。子批详情在服务端按固定归属分页，剩余操作用服务端剩余范围条件，不在前端拼全批码ID。

冻结、恢复、作废和导出均限定选中的父批、已用子批或剩余范围；已用码作废不退回剩余。删除保留已绑定码与生产任务历史保护；父危险操作先说明影响全部子批和码数量。剩余行可新建任务并精确预选产品和来源，领取量由操作员填写；已领未用仍须任务结束并审核后释放，冻结/作废码不可领。

已用子批编辑先查询整个关联任务的跨总批范围，确认后用稳定请求ID提交。更正只写该任务的独立生产快照和实际已用码，保留共享业务批次及其他任务；未用码随后按任务快照生产。活动采集、未完成上传及关联冻结/作废码阻止更正。公众扫码、任务列表/明细/历史和父使用记录同步展示更正后的批号。父明细中的任务码不能绕过全任务更正。

### 上传边界与账号对接

主采集器 `regcode-production` 保留自动上传，新增“完成本次上传”。SQLite持久保存上传UUID、起始序号和固定结束序号；20条网络分段、丢响应、断网重试均沿用原身份。上传中的已用子批按成功码实时增长，完成后成员范围固定；继续扫码懒建下一批，不结束任务。空完成不建批，重复/错误事件保留收据、不扣剩余量。事件收据、首次绑定和固定子批归属同事务，落库失败整体回滚。

一次上传跨多个总批次时，各总批次各有一个子批，关联同一上传UUID。旧升级队列无上传UUID的记录继续原协议，不重新分类。采集会话须收齐全部事件且每个上传完成后才允许结束。

| 接口 | 用途 |
|---|---|
| `GET /api/admin/codes/upload-batches/{id}/children` | 查询当前页已用子批、动态剩余及历史汇总提示 |
| `GET /api/admin/codes?usageBatchId={id}` | 固定已用子批明细 |
| `GET /api/admin/codes?uploadBatchId={id}&scope=remaining` | 当前剩余范围明细 |
| `GET/POST /api/admin/codes/usage-batches/{id}/correct` | 整任务影响预览及幂等更正 |
| `/api/admin/codes/usage-batches/{id}/flag`、`/export`及`DELETE /{id}` | 已用子批管理；删除仍按原保护拒绝 |
| 父管理接口附带 `scope=remaining` | 限定操作剩余码 |
| `POST .../production-tasks/{taskId}/collection-sessions/{sessionId}/uploads` | 登记上传UUID及`firstSequence` |
| `POST .../uploads/{uploadId}/complete` | 固定`lastSequence`，未收齐为`closing`，齐全为`completed` |

上传登记和完成均提供后台个人认证及 `/api/device` 对应路径。个人认证从可信服务端身份保存`uploader_id/uploader_username/uploader_name`，查询返回`uploaderId/uploaderUsername/uploaderName`；请求体不能指定上传人。当前独立设备凭证没有个人登录信息，字段留空显示“上传账号待接入”，不能冒用设备登记管理员。用户同事负责个人账号模块和强制个人登录，本轮不替其实施；后续需将服务端核验的个人身份接到上传登记快照，设备拥有权仍独立校验。账号接入前不宣称已完成“移动端必须个人登录”。

### 包装规格快照

生成接口返回`specSnapshotToken`，服务端签名绑定产品、码数量、完整清单摘要和原包装名称；留档验证后保存`upload_batch.spec_name_snapshot`。列只显示包装，不显示规格码；修改当前产品资料不覆盖旧批。普通外部文件和无签名旧客户端不能证明生成时包装，保留NULL并显示“原规格资料未记录”。缺结构时带快照留档明确503，不默默丢弃快照。

领取仍校验同企业、同产品和前11位规格/生产类型。另对能完整解析的生成包装快照检查物理规格冲突，覆盖新建、追加和带追加的任务编辑；`500ml/瓶×10`与`0.5升/瓶×10`等价，`500毫升`与`1升`不能混同一任务。自定义名称及未知历史只保留未知，不能据此证明同规格，也不套用当前主数据。
