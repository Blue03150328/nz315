## 开始之前：先记住三件事

1. **服务器上跑着别人的正式站 `www.cynx.cn`**（端口 3000、MySQL 3306）。你这台机器上所有操作**只碰 nz315 的东西**：
   - 只改 `/www/server/panel/vhost/nginx/nz315.conf`，**不碰 `cynx.conf`**
   - PM2 只用 `reload`，**绝不用 `pm2 kill` / `pm2 delete all` / `pm2 restart`**（会和 cynx 共用守护进程）
   - nginx 只用 `nginx -s reload`，**不用 restart**
2. **只有 `node` / `npm` 这类命令需要带 PATH 前缀**：`env PATH=/usr/local/node22/bin:/usr/bin:/bin`
   （因为 nz315 用的是独立安装的 Node 22，系统默认那个 v20 是给 cynx 用的。漏了会报「node 版本不对」。）
   ⚠️ **`pm2` 反过来：绝对不要给它加任何 PATH 前缀**，直接用裸命令 `pm2 ...`。
   原因：PM2 CLI 用的 Node 版本如果和正在跑的 God Daemon 不一致，PM2 会**杀掉并重建 daemon**——而 daemon 是和 cynx 共用的，**cynx 会当场挂掉**。所以 pm2 一律走服务器原本的默认 PATH（也就是当初 `pm2 start` 时的那个环境）。
   第 2 步第一条命令里已经加了一句 `which pm2`，**先把它的输出记下来**，后面出问题好排查。
3. **这次不动数据库**。服务器上**不要**跑 `node scripts/db-init.mjs`——那会把演示数据灌进生产库。

### 2.1 体检（只读，不改任何东西）

```bash
which pm2; pm2 -v

```

**逐条对一下**：

| 该看到什么 | 说明 |
|---|---|
| `interpreter` 是 `/usr/local/node22/bin/node` | 关键！不是这个就先停下告诉我 |
| `status` 是 `online` | 服务在跑 |
| `.deploy-version` 里基线是 `8264bcb` | 确认服务器现在跑的是旧版 master |
| swap 有 2G | 构建需要，没有会 OOM |
| nginx 只有 80 块、反代 `127.0.0.1:3100` | 证书还没配（第 9 步才配） |
| `node -v` 打印 `v22.22.2`、`npm -v` 有版本号 | 说明 node22 工具链可达，第 7 步构建不会「command not found」 |
| 最后那条 `ls public/tools/` **没有任何输出** | **正常**。目录还不存在（git 不跟踪空目录），第 3 步会用 `mkdir -p` 建出来 |
| `which pm2` 打印出 pm2 的真实路径 | 记下来备用（正常应该是 `/usr/local/bin/pm2` 或宝塔 node 目录下），**后面所有 pm2 命令直接用裸 `pm2`** |

### 2.2 备份（这一步是"后悔药"，务必做完）

把下面**整段**复制粘贴，一次执行：

```bash
TS=$(date +%Y%m%d-%H%M%S); B=/root/nz315-backup-$TS; mkdir -p $B

cp -a .env .deploy-version package.json package-lock.json $B/
```

👉 **强烈建议把打印出来的 `TS=...` 那行记到手机备忘录**——回滚时全靠它。

> `mv .output .output.bak-$TS` 这步是把旧构建产物**改名**保留（不是删），万一新版有问题，10 秒就能切回来。

## 第 5 步 · ❗删掉 3 个已经下线的服务端文件

新版本把"服务器端生成二维码图片"改成了"下载离线工具、在你自己电脑上生成"，所以这 3 个服务端文件必须删掉：

```bash
cd /var/www/nz315
rm -f server/api/admin/codes/qrcode.post.ts \
      server/api/admin/codes/qrcode-download.get.ts \
      server/utils/qr-image.ts
ls server/api/admin/codes/ | grep qrcode || echo "qrcode*.ts 已清除 ✓"
```

**期望看到**：`qrcode*.ts 已清除 ✓`

> **为什么必须删**：构建时是"扫目录里的文件"来注册接口的。留着这 3 个文件，构建后旧接口会"复活"，而它们依赖的库已经从依赖清单里删掉了 → 一旦被访问就是 500 错误。
>
> ⚠️ **千万不要**执行 `git clean -fdx` 或 `rsync --delete`——那会把 `.gitignore` 排除的文件（包括那个 90MB 的 EXE）一起抹掉，而且 git 完全不知道这事，重建也补不回来。

## 第 6 步 · ❗把 PM2 配置换回服务器上的修正版（最容易踩空的一步）

```bash
cp /root/nz315-backup-*/deploy-server-corrected/ecosystem.config.cjs /var/www/nz315/deploy/ecosystem.config.cjs
grep -nE "PORT|interpreter" /var/www/nz315/deploy/ecosystem.config.cjs
```

**期望看到**：输出里同时有 `PORT: 3100` 和 `interpreter: '/usr/local/node22/bin/node'`

> **为什么**：这次合并让 `deploy/ecosystem.config.cjs` 这个文件重新回到了代码里，但它是**没修正过的原始版**（`PORT 3000`、没有 interpreter）。刚才第 4 步解包时，它把服务器上那份改好的**盖掉了**。
>
> 正在跑的 nz315 **不受影响**（配置早已加载进 PM2 进程表）。但这文件留着就是一颗雷——哪天有人手贱执行 `pm2 start deploy/ecosystem.config.cjs`，它就会去抢 **cynx 的 3000 端口**，正式站当场挂掉。
>
> 👉 如果提示"文件不存在"，说明服务器上原本就没有 `deploy/` 目录，跳过这步即可。

## 第 7 步 · 装依赖 → 构建 → 重载

**整段复制粘贴**（构建约 1–2 分钟，别着急）：

```bash
cd /var/www/nz315
free -m ; swapon --show                                              # 先确认内存/swap 正常
env PATH=/usr/local/node22/bin:/usr/bin:/bin npm install --no-audit --no-fund
env PATH=/usr/local/node22/bin:/usr/bin:/bin npm run build
pm2 reload nz315
```

**每步期望**：

| 命令 | 期望输出 | 耗时 |
|---|---|---|
| `npm install` | 末尾出现 `up to date` 或 `added N packages` | 10–60 秒 |
| `npm run build` | 末尾出现 **`✨ Build complete!`**，总大小约 **9.59 MB** | 1–2 分钟 |
| `pm2 reload` | 显示 `[PM2] Applying action reloadProcessId on app [nz315]` + 成功 | 数秒 |

**注意三点**：
- ❌ **不要用 `npm ci`**（会全量重装 780 个包，10 分钟起步，还可能把这台 3.5G 内存的机器搞 OOM）
- ❌ **不要改 `.env`**（服务器凭据原样不动；万一改了任何键，必须重新 build 才生效）
- ❌ **不要跑 `db-init`**

## 第 9 步 · 阿里云签证书 + 配 HTTPS 443

> 现状：`https://www.nz315.cn` 现在打的是 **cynx 的证书**，浏览器会报"连接不安全"。所以这一步必须做，否则 90MB 的下载摆在"不安全"页面上很难看。
> 用**阿里云免费证书**（Let's Encrypt 的通道被网络阻断了，走不通）。

### 9.1 在阿里云控制台申请证书

1. 登录阿里云控制台 → 顶部搜索框搜 **「数字证书管理服务」** → 进入
2. 左侧 **证书管理** → **证书资源包** / **个人测试证书（免费版）**
   （阿里云免费证书每年每账号 **20 张，每张 90 天**，不支持通配符）
3. 点 **创建证书** / **申请证书**：
   - **绑定域名**：`www.nz315.cn`
   - **验证方式**：选 **DNS 验证**（⚠️ 不要选"文件验证"，那样拿不到赠送的裸域名）
   - 其他按默认
4. 提交后等审核（一般几分钟到几小时，DNS 验证通常很快，因为域名解析本来就在阿里云）
5. 签发成功后 → **下载** → 选 **Nginx 格式**，得到一个压缩包，里面有 `.pem`（证书）和 `.key`（私钥）两个文件

### 9.2 把证书传上服务器

1. 宝塔面板 → **文件** → 进入 `/www/server/panel/vhost/cert/nz315/`
2. 上传刚下载的两个文件
3. 回终端重命名成统一名字（**文件名以实际下载的为准**，下面只是示例）：

```bash
cd /www/server/panel/vhost/cert/nz315/
ls -l
# 假设下载的是 nz315.cn.pem / nz315.cn.key：
mv nz315.cn.pem fullchain.pem
mv nz315.cn.key privkey.pem
chmod 600 privkey.pem
ls -l
```

**期望**：目录里有 `fullchain.pem` 和 `privkey.pem`，权限 600。

> ⚠️ 如果下载的文件名不是这个，就把下面的 nginx 配置里的路径改成你的实际文件名。

### 9.3 改 nginx 配置

**先备份**：

```bash
cp /www/server/panel/vhost/nginx/nz315.conf /root/nz315-backup-*/nz315.conf.bak
```

然后用宝塔 **文件** 管理器打开 `/www/server/panel/vhost/nginx/nz315.conf`，**整个文件替换成下面的内容**：

```nginx
# ========== 1) HTTP：全部跳 HTTPS，同时保留证书续期校验通道 ==========
server {
    listen      80;
    server_name www.nz315.cn nz315.cn;

    # 保留 acme 挑战通道（万一以后要回到 certbot 方案，它必须留在最前面）
    location ^~ /.well-known/acme-challenge/ {
        root         /www/server/nginx/html;
        default_type "text/plain";
        allow all;
    }

    # 其余一律跳 HTTPS
    location / {
        return 301 https://www.nz315.cn$request_uri;
    }
}

# ========== 2) HTTPS 主站：反代 Nitro（127.0.0.1:3100）==========
server {
    listen      443 ssl;
    http2       on;                       # ⚠️ nginx 1.30.4 已弃用 "listen 443 ssl http2" 写法
    server_name www.nz315.cn;

    ssl_certificate     /www/server/panel/vhost/cert/nz315/fullchain.pem;
    ssl_certificate_key /www/server/panel/vhost/cert/nz315/privkey.pem;

    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;
    ssl_prefer_server_ciphers off;
    ssl_session_cache   shared:SSL:10m;
    ssl_session_timeout 1d;

    # 追溯码文件上传用，给足大小与超时
    client_max_body_size 100m;

    location / {
        proxy_pass         http://127.0.0.1:3100;
        proxy_http_version 1.1;

        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_read_timeout  300s;
        proxy_send_timeout  300s;
        proxy_connect_timeout 10s;
    }
}
```

> 📌 **为什么 80 块是把 `location /` 换成 `return 301`，而不是在最外层写 `return`**：如果写在 server 最外层，会把上面的 acme 通道也一起跳走，那条通道就废了。

### 常见卡点速查

| 现象 | 原因 | 怎么办 |
|---|---|---|
| `npm run build` 中途被 killed | 内存不够（3.5G 机器） | 确认 2G swap 在（`swapon --show`）；先停掉别的吃内存的进程再重跑 |
| 站点打开是 502 | 构建没跑或构建失败 | `pm2 logs nz315 --lines 50` 看日志；确认 `✨ Build complete!` 出现过 |
| EXE 下载 404 | 没放文件，或放了但没重新构建 | 确认 `public/tools/` 里有文件，且第 7 步 build 跑过 |
| EXE 下载 200 但大小不对 | 上传被截断 | 重新传，比对 `sha256sum` |
| 页面能开但样式/交互全乱 | `.nuxt` 缓存和进程不匹配 | `pm2 reload nz315`；仍不行则删 `.nuxt` 与 `node_modules/.cache` 后重新 build |
| `https` 打不开但本机 `curl 127.0.0.1` 通 | 阿里云安全组没放行 443 | 见第 9.5 步 |
| `nginx -t` 报证书相关错误 | 证书文件名/路径不对 | `ls -l /www/server/panel/vhost/cert/nz315/` 核对实际文件名 |
| `pm2` 命令找不到 | 登录 shell 的 PATH 异常 | 先 `which pm2` 看它在哪；**千万不要**用 `env PATH=...` 前缀去硬找 pm2——Node 版本一不一致，PM2 会重建 daemon，cynx 跟着挂 |
| 报 `node: command not found` / 版本不对 | 漏了 PATH 前缀 | 命令前加上 `env PATH=/usr/local/node22/bin:/usr/bin:/bin` |
| cynx 打不开了 | 危险信号！ | 立刻检查有没有执行 `pm2 kill` / `pm2 delete all`；把第 2 步的 `pm2-describe.txt` 贴给我 |
