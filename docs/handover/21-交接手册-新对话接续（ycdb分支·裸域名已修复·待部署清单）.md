## 2. `ycdb` 上的三条线（本轮重点）

### 2.1 线一：外部二维码核验（后台）

**用户要什么**：拿一瓶**真实农药的瓶标二维码**（第三方平台 `mashangzhuisu.com` 出的码），要求「用相机扫**别人的**码 → 提取**别人的码里的信息** → 字段匹配到我们库里的**同一产品** → 给出结果」。

**注意语义**：不是"把我们自己的码当外部码"，而是**拿别人的码当输入，用国家登记库当基准去核验它**。

**现在的做法**（`server/utils/external-verification.ts`）：四路兜底 `extractLabeledFields` —— ① JS/JSON 键值对 ② 逐行「标签:值」 ③ 表格相邻单元格 ④ 标签独占一行则取下一行；配套 `FIELD_ALIASES`（9 字段别名）+ `cleanFieldValue`（拒超长/链接/占位词）。
**兜底通道**：接口支持 `pageText` 入参（粘贴正文），**能从正文里自动认出码**。⇒ 「开链接 → 肉眼复制正文 → 粘回核验」是**设计好的路径，不是缺陷**。

**码提取规则的唯一来源 = `shared/utils/trace-code.ts`**（`extractTraceCode` / `isTraceCode` / `isHttpUrl`）。此前前端 `useQrScanner.traceCodeOf` 与后端 `extractExternalCode` 各写一套，漂移的直接后果是「扫到别人平台的裸码时页面毫无反应」。**改码提取只改这一个文件。**

### 2.2 线二：公众端扫码接入登记资料库比对 ⭐ 本轮新增

**用户提问**：「为什么我微信直接扫了能有数据显示，走我们系统没有」＋明确要求「**用户端也需要和我们的登记库比对功能**」。

**根因**：微信扫码会**直接打开该码所属平台的 H5**（数据来自人家自己的库）；而我们的 `GET /api/trace` **只查本平台 `trace_code` 表**，未命中统一回 `not-found` + 「该追溯码未在追溯系统中登记」——**信息量为零**。

**破局点**：32 位单元识别码是**全国统一结构**（第 1 位类别 1=PD/2=WP · 第 2-7 位=登记证号后 6 位 · 第 8 位生产类型 1/2/3）⇒ **前 8 位可直接与登记资料库比对，与本平台有没有这个码无关**。

**改动（6 改 3 新）**：

| 文件 | 作用 |
|---|---|
| **新** `shared/utils/unit-code.ts` | 解析规则**三处共用**（后台核验 / 公众端兜底 / 两个前端结果页），杜绝再次漂移 |
| **新** `server/utils/registry-lookup.ts` | 按前 8 位查 `pesticide_reg`。**必须先按类别过滤**（否则别的类别撞后六位会给出**错误候选**）+ 复用 `findOriginalCandidates` 推导原药信息 + 进程内 LRU 缓存（500 条/10 分钟） |
| **新** `app/components/TraceExternal.vue` | 消费者结果页（橙色横幅「该码不是农资315签发的」+ 结构解析 + 登记资料 + 原药 + 「必须注意的三点」） |
| `server/api/trace.get.ts` | 未命中分支接兜底比对（新 `resultType='external-reg'`）。**只读：不写 `scan_log`、不触发风险预警** |
| `app/components/TraceNotFound.vue` | 补「前 8 位结构解析」卡 + 接口动态原因 |
| `app/pages/scan.vue` | `onRawResult` **不再静默丢弃非本平台二维码**（原实现扫到就什么都不做） |

**性能事实**：`RIGHT(registration_no, 6) = ?` **走不了索引**（`EXPLAIN` = 覆盖索引全扫 **95,386 行**），本机 **26-32 ms/次** ⇒ 靠进程内缓存兜。要更快需加**生成列 `reg_last6` + 索引**（DDL，**尚未做**）。

**合规边界（刻意写进页面，不能越界）**：① 登记资料命中 **≠ 产品是正品**（登记证号是公开信息）；② **生产日期 / 生产批次本平台给不了**（只在包装标签实物与该码所属平台）；③ 公众端**不抓外部平台页面**。

## 6. 铁律（违反任意一条都可能出事故）

1. **绝不影响 `www.cynx.cn`**。它跑在 3000，nz315 跑在 3100。
2. **绝不 `pm2 kill` / `pm2 delete all`** —— 两个站**共用 PM2 daemon**。nz315 靠 per-app `interpreter` 指到 `/usr/local/node22/bin/node` 与 cynx 的系统 Node v20 隔离。**只能 `pm2 reload nz315`**。
3. **`nz315.conf` 里绝不写 `listen 443 ssl default_server`** —— 会抢走 cynx 的默认 443。
4. **改了服务器 `.env` 就必须重新 `npm run build`** —— Nitro `runtimeConfig` **构建期内嵌**，改 `.env` 不 rebuild 运行期不生效。
5. **绝不把本机构建的 `.output` 传上服务器** —— 本机数据库凭据会被内嵌进产物，线上会连错库。
6. **生产库绝不裸跑 `db-init.mjs`**（理由见 §5）。**`--migrate-only` 一律带上。**
7. **部署顺序有因果：补列 → 构建 → `pm2 reload`**。别换序。
8. **静态资源清单构建期固化** —— 要放的静态文件（如工具包 EXE）**必须在 `npm run build` 之前**放进 `public/tools/`；build 之后再放 = **404，`pm2 reload` 也不管用**。
9. **服务器操作全部由用户逐条粘贴执行**，SSH 在我这边不可用；每条命令都要标明期望输出。
10. **一轮修改 = 一次提交**，提交信息用中文约定式（`feat:`/`fix:`/`docs:`/`refactor:`/`chore:`）；重要变更还要在 `PROJECT_LOG.md` 顶部加一条 + 同步 `AGENTS.md` 进度段。**`.env` / 凭据一律不提交。**
11. **往库里写演示数据必须带硬安全闸**（本机 host 白名单 + `【测试】` 前缀 + 一键 `--clean`）。本项目的 `.env` **曾经指向过服务器库**，这类脚本跑错地方就是生产事故。

## 7. 踩过的坑（下一轮别重复）

### 7.1 本机沙箱环境（Windows，高频）

| 坑 | 现象 | 绕过 |
|---|---|---|
| **`rm` 被安全 shim 拦死** | `dirname: command not found`，exit 127 | **删文件一律用 node**：`fs.unlinkSync` / `fs.rmSync(dir,{recursive:true,force:true})` |
| `tail` / `head` / `wc` / `sleep` / `grep` / `find` / `ls` 多数不可用 | 管道破裂、无输出、exit 127 | 长命令输出用 `> 日志文件 2>&1` 落盘再 `Read`；查找用 Glob / Grep 专用工具 |
| `schtasks` / `sc.exe` 被策略拉黑 | 不可重试、不可绕过 | 查计划任务用 PowerShell `Get-ScheduledTask` |
| PowerShell stdout 可能整体被吞 | exit 0 但没有任何输出 | node `child_process` 起子进程 + `writeFileSync(...,'utf8')` 落盘再读 |
| PowerShell `>` 重定向写出 **UTF-16** | Read 工具拒读（当二进制） | 用 node `execFileSync(...,{encoding:'utf8'})` 或 `Set-Content -Encoding utf8` |
| 无 `gh` CLI、无 `mysql` 客户端 | — | 直连库用 `mysql2` 读 `.env` 取凭据 |
| 本机 git 写不了「嵌套引用」 | `refs/heads/a/b` 建不出来，**且所有命令都 exit 0 无报错** | 本地分支名**用平铺名**（`ycdb` 而非 `feature/ycdb`）——项目里既有 `feature--qd` 就是这个坑的历史受害者 |

### 7.2 数据与口径（本轮新增两条，都很"静默"）

| 坑 | 现象 | 根因与对策 |
|---|---|---|
| **raw mysql2 解构口径** | `const [row] = await conn.query(...)` 后 `row.id` 恒 `undefined`，**而 `if (row)` 对空数组居然为真** ⇒ 静默走错分支、报错点漂到几十行外 | raw `conn.query()` 返回 **`[rows, fields]`**；项目封装 `server/utils/db.ts query()` 返回**行数组本身**。写脚本**统一收口到 `firstRow()` helper**。**本项目已踩三次** |
| **32 位码手抄必错** | 抄错一位（`990002`→`990001`）→ 页面变"未查询到"；又因**两个 `TraceNotFound` 页面恰好等长 30036B**、恰好排在第 6 个请求位置，现象酷似"服务端结果随请求顺序翻转" | **一律从 `qr-test/manifest.json` 取码**。另外：**别拿 HTML 字节数当页面指纹**，不同页面可能恰好等长 |

### 7.3 真浏览器验证（本项目通用）

用全局技能 `browser-ui-screenshot`（Edge headless + CDP）。本项目是 **Nuxt UI v4 而非 Element Plus**，脚本自带的 `--click` 命中集合用不上，走 **`--js-file` 逃生口**。

- **点之前必须等 Vue 水合完成**（`#__nuxt.__vue_app__` 出现），否则点击**静默无效**（不报错、没效果）——最容易误判成"功能坏了"的假阴性。
- **dev 下验客户端跳转要先预热目标路由**：首次编译慢（秒级），采样窗口太短会误判成"导航没生效"。**用多点采样，不要单点断言。**
- **判定"`back()` 是否生效"的替代判据**：CDP 报 `Inspected target navigated or closed` 就说明导航真的发生了。
- **会话 Cookie 不跨浏览器实例** → 登录 + 操作 + 断言必须在**同一个会话**里跑完。
- `--js-file` 用**正斜杠绝对路径**；脚本开头的 `taskkill msedge` 会杀掉**所有** Edge → **多角色必须串行跑，不能并行**。

### 7.4 方法论（本项目最值钱的三条）

1. **`router` 这类"模板自由变量"静态检查抓不到。** 模板里写 `router.push()` 而 `<script setup>` 里没 `const router = useRouter()` —— `node --check` / SFC 编译 / tsc **全部静默通过**，只有真点下去才抛 `TypeError`。**改了模板或 `setup()` 引用就必须真跑一遍。**（09-22 实测：同类共三处。）
2. **"后端返回 403"和"用户看不到按钮"是两件事，必须分开验。** 前者用接口回归，后者**只能靠真浏览器 / SSR 提取可见元素**。
3. **"接口返回对"和"页面渲染对"也是两件事。** 只验接口漏白屏，只验页面漏"渲染了错的组件"——**两层都要**（本轮把它做成了脚本的 `--verify`）。

### 7.5 外部核验那条线的三个实测坑（细节见 §2.1）

见 20 号 §2.4（`redirect:'error'` 致 500 / 「见喷码」溜过占位词闸门 / 含量写法差异造成假 mismatch）—— **机制未变，仍然有效。**
