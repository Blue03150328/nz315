# 后台业务流程优化（2026-10-05，本机完成，未上线）

## 当前功能与维护边界

1. 首页冻结码、作废码、待处理预警分别直达筛选结果。`shared/utils/admin-navigation.ts` 集中维护业务链接；`useAdminListRoute` 负责 URL 条件与页码恢复。码库异常入口显示全范围码明细，包含未归属上传批次的码。
2. 建档指引仅在「系统设置 → 建档指引」主动打开时加载。首页、规格、产品、上传页不常驻进度。总部选择企业，厂家自动使用登录账号绑定企业；进度依据真实资料。
3. 上传页拆为输入、校验预览、批次表单、当次结果卡。`useCodeImport` 管理请求状态，契约在 `shared/types/code-import.ts`。
4. `POST /api/admin/codes/import` 负责认证和读取请求，`server/utils/code-import.ts` 管理入库事务；解析和入库共用 `import-context.ts` 与 `import-validation.ts`。

## 导入报告已撤销（用户最终决定）

此前新增的历史导入报告功能已于2026-10-05撤销：删除两页、四个接口、菜单与跳转、CSV 工具、报告专用类型、报告写入及建表定义。旧地址404。上传仅保留当次结果，不保存或下载历史报告。

已经在本机创建过的旧报告表保留，不执行 DROP TABLE；应用不再读写，也不要求生产存在它们。此前记录中的「上线须新建报告两表」已失效。其他功能的既有迁移仍按部署基线执行。

## 上传与权限

- 同产品上传通过产品行锁串行执行，获取锁后重新查重。重复重试会显示本次重复跳过数量，不再返回保存的历史结果。
- 自动建批、创建上传批次、分块插码同事务；失败全部回滚，无可入库码不建批。
- 数据行总数 = 入库 + 重复跳过 + 校验拒绝 + 事务失败未写入；空行、表头另计。仅保留前20条校验预览，不再构造全量拒绝明细。
- 通知在提交后发送，有限重试，链接直达上传批次；发送失败不改变入库结果。
- 企业数据同库按 enterprise_id 隔离，服务端从登录账号确定厂家范围；建档进度与隔离独立。
