# 后台业务流程优化（2026-10-05，本机完成，未上线）

## 功能与维护边界

1. 首页冻结码、作废码、待处理预警分别直达筛选结果。`shared/utils/admin-navigation.ts` 集中维护业务链接；`useAdminListRoute` 负责 URL 条件与页码恢复。码库保留上传批次聚合，异常入口另外显示全范围码明细，包含未归属上传批次的码。
2. `AdminOnboarding.vue` 仅在「系统设置 → 建档指引」选项卡主动打开时加载（2026-10-05 用户反馈后调整）；首页、规格、产品、上传页不再常驻进度。`GET /api/admin/onboarding` 根据企业真实资料判断进度。总部必须选企业，厂家自动使用登录账号绑定的企业；只读账号仅查看。生成与上传是替代路径；进度不依据点击历史。
3. 上传页拆成 `CodeImportInput`、`CodeImportPreview`、`CodeImportBatchForm`、`ImportResultCard`。请求状态由 `useCodeImport` 管理，共用契约在 `shared/types/import-report.ts`。
4. 入库接口只做认证和读取请求，业务模块为 `server/utils/code-import.ts`。解析、入库共用 `import-context.ts` 与 `import-validation.ts`。规则原因代码在 `code-validator.ts` 定义，中文文案可独立改动。

## 报告与可靠性

- 新增 `import_report`（摘要、请求指纹、结果 JSON、版本）和 `import_rejection`（原始行号、码值或输入片段、稳定原因代码）。成功码继续留在 `trace_code`，不重复保存原文件。
- 页面提交原始内容，最终服务端重验，避免解析阶段拒绝行从报告中消失。空行、表头单独计数。过长非法内容只保留前255个字符。
- 数量关系：数据行总数 = 实际入库 + 重复跳过 + 校验拒绝 + 因事务失败未写入；原始输入另含忽略行。
- 同操作者与请求标识唯一，内容指纹不同返回409；相同请求通过报告行锁串行执行。业务写入和成功报告同事务提交，失败回滚至保存点后写失败报告，避免孤儿批次。
- 入库期间上下文加载复用事务连接，避免并发事务占满连接池后等待额外连接。
- 全部校验失败也保存报告，但不新建生产批次或上传批次。入参不完整、产品无权限等前置拒绝仍返回原有错误，不生成报告。
- 通知在事务提交后发送，最多尝试3次，发送状态写入报告；失败不改变已提交的入库结果。旧通知调用仍只尝试一次。
- 报告摘要、分页明细、CSV 下载共用 `requireImportReport` 权限检查；厂家只能访问本企业，总部可查看全部。CSV 分批流式输出，转义公式及长码。
- 企业数据采用同库按 `enterprise_id` 隔离。企业归属由签名会话对应的数据库账号确定，厂家的客户端企业参数不授予跨企业权限；建档进度只是业务资料准备情况，不承担数据隔离。
- 报告为历史结果，码库是当前数据。旧上传批次不补造报告。待提交报告可用原请求重试；没有引入队列或后台调度。
