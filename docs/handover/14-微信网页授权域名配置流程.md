# 14 · 微信公众平台「网页授权域名」配置流程（nz315）

> 生成时间：2026-09-17 10:55
> 适用对象：在宝塔终端**逐条粘贴命令**的操作者（每条命令都标了「期望输出」与通过判据）
> **本文前置结论**：微信硬性规定「网页授权域名**只支持 https**」，而 2026-09-17 实测
> `https://www.nz315.cn` 的 443 端口上站着的是 **cynx 的站点与 cynx 的证书**（第 9 步 HTTPS 尚未做）。
> → **流程分两段：第一段补 HTTPS（必做），第二段才配微信。**

---

## 0. 结论先行：现在直接去后台填域名，必然失败

实测证据（2026-09-17 10:47 · 本机 node 直连探测，非浏览器缓存）：

| 请求 | 实测结果 | 说明 |
|---|---|---|
| `http://www.nz315.cn/` | **200** · 标题「农资315 - 农药追溯查询」+ 备案号 | nz315 的 **HTTP** 入口正常 |
| `http://www.nz315.cn/MP_verify_OUOoNSqTrpZkfWli.txt` | **200** · 内容 `OUOoNSqTrpZkfWli` | 校验文件 **HTTP 侧** OK |
| `https://www.nz315.cn/` | 200，但标题是「**广西超优农选电子商务有限公司**」 | **命中的是 cynx**，不是 nz315 |
| `https://www.nz315.cn/login` | **404**（Nuxt 404 页） | nz315 的 443 **根本没有在服务** |
| `https://www.nz315.cn/MP_verify_OUOoNSqTrpZkfWli.txt` | **404** ← 微信要抓的就是这一条 | **配置必然校验失败** |
| 443 证书（`SNI=www.nz315.cn`） | `subject CN = www.cynx.cn`，`SAN` 只有 `DNS:www.cynx.cn`，Let's Encrypt，2026-11-17 到期 | 443 上没有 nz315 的证书 |

**为什么**：`nz315.conf` 目前**只有 80 端口块**（HTTPS 是 12 号手册的第 9 步，还没做）。
443 上只有 cynx 的 server 块，凡是不精确匹配 server_name 的 SNI 都会落到它 →
于是 `www.nz315.cn` 的 https 请求**全被 cynx 接走**。

**后果**：微信保存时会去抓 `https://www.nz315.cn/MP_verify_*.txt` → 404 → 提示「校验失败」。
而网页授权域名**每月最多改 5 次**，这种必败的尝试纯属浪费配额。

## 1. 前置条件自查表（2026-09-17 实测）

| # | 微信的要求 | 当前实测 | 状态 |
|---|---|---|---|
| 1 | **必须是已认证的服务号**（订阅号 / 未认证服务号看不到这一栏） | 凭据已配，`authorize` 端点 302 正常（2026-09-07 起） | ⚠️ **需你亲眼确认**，见 §1.1 |
| 2 | 域名已 ICP 备案，**新备案需满 24 小时** | `桂ICP备2024035642号-5`（2026-09-12 通过） | ✅ 已 5 天，满足 |
| 3 | **域名只支持 https 协议**，不支持 IP | ❌ 443 上是 cynx 的证书与站点 | 🔴 **阻塞 → 先做第一段** |
| 4 | 校验文件放在**域名根目录**且可访问 | HTTP 200 / **HTTPS 404** | 🔴 同上 |
| 5 | 配额：最多 **2 个**网页授权域名，**每月最多改 5 次** | 尚未使用 | ✅ |
| 6 | 域名格式：仅字母/数字/`-`，**不带协议头、不带端口、不带路径、不能是 IP** | 应填 `www.nz315.cn` | ✅ |

### 1.1 怎么确认「已认证服务号」

登录 mp.weixin.qq.com → 看账号名旁边是否有**蓝色 V 标**；或「设置与开发 → 账号设置 → 认证情况」。
**如果找不到「网页授权域名」这一栏，就说明不是已认证的服务号**，后面全部不用做
（订阅号无网页授权能力，须先认证 / 升级服务号）。

### 1.2 本项目只需要配「网页授权域名」这一项

- **JS接口安全域名**：本项目**未使用微信 JS-SDK**（全仓库 grep 无 `wx.config` / `jsapi_ticket`）→ **不用配**。
- **业务域名**：只影响「微信内打开网页时是否显示『非微信官方网页』提示条」，可选，且**每月只能改 3 次** → 本轮别碰。
- **IP 白名单**：网页授权走的 `sns/oauth2/access_token`、`sns/userinfo` **不需要** IP 白名单
  （只有 `cgi-bin/token` 一类接口才需要）→ **不用配，别去折腾**。

## 2. 第一段：给 nz315 补 HTTPS（4 步）

### 2.1 先自查证书是否已经申请过

```bash
ls -l /www/server/panel/vhost/cert/nz315/
```

- **期望**：列出 `fullchain.pem` + `privkey.pem`（或 `xxx.pem` + `xxx.key`）→ 直接跳到 §2.3，路径按实际文件名填。
- **报 `No such file or directory` 或目录为空** → 走 §2.2 去阿里云申请。

### 2.2 阿里云申请免费证书（沿用 12 号手册第 9 步）

1. 阿里云控制台 → 搜「数字证书管理服务」→ 左侧「证书管理 → SSL 证书」
2. 「**个人测试证书（原免费证书）**」→ 创建证书
3. **绑定域名填 `www.nz315.cn`**（免费证书**不支持通配符**，别填 `*.nz315.cn`）
4. **验证方式必须选「DNS 验证」**（域名与解析都在同一阿里云账号下，会自动加 TXT 记录；
   ⚠️ 选「文件验证」拿不到赠送的裸域名 SAN）
5. 等签发（一般 1–10 分钟，状态变「已签发」）
6. 点「下载」→ 选 **Nginx** 格式 → 得到 `.pem` + `.key` 两个文件

落位（宝塔惯例目录，09-15 已建好）：

```bash
mkdir -p /www/server/panel/vhost/cert/nz315
ls -l /www/server/panel/vhost/cert/nz315/
```

**期望**：两个文件都在（`.pem` 约 3–5 KB，`.key` 约 1.7 KB）。

> ⚠️ 阿里云免费证书 **90 天有效、不支持自动续期** → 到期前须重新申请替换，建议加手机日历提醒。

### 2.3 改 nz315.conf：80 跳转 + 443 反代

先备份：

```bash
cp -a /www/server/panel/vhost/nginx/nz315.conf /root/nz315.conf.bak-$(date +%Y%m%d-%H%M%S)
```

用宝塔「文件 → 编辑」打开 `/www/server/panel/vhost/nginx/nz315.conf`，**全选删除后整份替换**为：

```nginx
# ============================================================
# 农资315 · nz315.conf（80 跳转 + 443 反代）
# 位置：/www/server/panel/vhost/nginx/nz315.conf
# 生效：nginx -t && nginx -s reload   ← 只用 reload，绝不 restart
# ⚠️ 与 cynx.conf 完全独立，改本文件不影响 www.cynx.cn
# ============================================================

# ---------- 1) HTTP：只留「证书续期通道 + 微信校验文件」，其余 301 跳 HTTPS ----------
server {
    listen      80;
    server_name www.nz315.cn nz315.cn;

    # 证书续期通道（当前虽不用 certbot，留着零成本）
    location ^~ /.well-known/acme-challenge/ {
        root         /www/server/nginx/html;
        default_type "text/plain";
        allow all;
    }

    # 微信域名归属校验文件：HTTP 侧也直返，避免微信抓取时不跟随 301
    location = /MP_verify_OUOoNSqTrpZkfWli.txt {
        root         /www/server/nginx/html;
        default_type "text/plain";
    }

    location / {
        return 301 https://www.nz315.cn$request_uri;
    }
}

# ---------- 2) HTTPS 主站：反代 Nitro（127.0.0.1:3100）----------
server {
    listen      443 ssl;
    http2       on;                       # ⚠️ nginx 1.30.4 已弃用「listen 443 ssl http2」写法
    server_name www.nz315.cn;

    ssl_certificate     /www/server/panel/vhost/cert/nz315/fullchain.pem;
    ssl_certificate_key /www/server/panel/vhost/cert/nz315/privkey.pem;

    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;
    ssl_session_cache   shared:SSL:10m;
    ssl_session_timeout 1d;

    # 追溯码文件上传：单文件上限 50MB，留余量
    client_max_body_size 100m;

    # 微信校验文件：HTTPS 侧同样直返（不依赖 Nuxt 构建产物，换文件名只改这两处 location）
    location = /MP_verify_OUOoNSqTrpZkfWli.txt {
        root         /www/server/nginx/html;
        default_type "text/plain";
    }

    location / {
        proxy_pass         http://127.0.0.1:3100;
        proxy_http_version 1.1;

        proxy_set_header Host              $host;
        proxy_set_header X-Real-IP         $remote_addr;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_read_timeout    300s;
        proxy_send_timeout    300s;
        proxy_connect_timeout 10s;
    }
}
```

两个**必须知道的取舍**：

- 📌 **绝对不要写 `listen 443 ssl default_server`** —— 会抢走 cynx 的默认 443。
- 📌 **本次不加裸域名 `nz315.cn` 的 443 块** —— 阿里云免费证书是**单域名**，
  裸域名走 https 会报证书不匹配。→ **对外所有链接、扫码 URL 一律用 `www.nz315.cn`**
  （`nuxt.config.ts` 的 `traceBaseUrl` 已是 `https://www.nz315.cn/trace?code=`，天然一致）。

### 2.4 放校验文件（现在就放好，微信段直接用）

```bash
mkdir -p /www/server/nginx/html
printf '%s' 'OUOoNSqTrpZkfWli' > /www/server/nginx/html/MP_verify_OUOoNSqTrpZkfWli.txt
cat /www/server/nginx/html/MP_verify_OUOoNSqTrpZkfWli.txt; echo
```

**期望**：输出 `OUOoNSqTrpZkfWli`。

> ⚠️ 若微信**本次重新下载**了校验文件（文件名/内容可能变），按 §3.2 替换此处与两处 location。

### 2.5 生效 + 五项验证

```bash
nginx -t
```

**期望**：`syntax is ok` + `test is successful`。
👉 若报错**别硬试**，先看报错 —— 99% 是证书文件名不对、或 `listen` 写法不对。

```bash
nginx -s reload
```

然后**逐条**验证（判据都写好了）：

```bash
echo "--- ① 443 证书必须是 nz315（CN=www.nz315.cn），不能再是 www.cynx.cn ---"
echo | openssl s_client -connect 127.0.0.1:443 -servername www.nz315.cn 2>/dev/null | openssl x509 -noout -subject -ext subjectAltName

echo "--- ② 校验文件 HTTPS 必须 200 ---"
curl -sk -o /dev/null -w '%{http_code}\n' --resolve www.nz315.cn:443:127.0.0.1 https://www.nz315.cn/MP_verify_OUOoNSqTrpZkfWli.txt

echo "--- ③ 校验文件内容必须一字不差 ---"
curl -s --resolve www.nz315.cn:443:127.0.0.1 https://www.nz315.cn/MP_verify_OUOoNSqTrpZkfWli.txt; echo

echo "--- ④ 80 必须 301 到 https ---"
curl -sI --resolve www.nz315.cn:80:127.0.0.1 http://www.nz315.cn/ | head -5

echo "--- ⑤ nz315 与 cynx 必须都还活着 ---"
curl -sk -o /dev/null -w 'nz315 /login = %{http_code}\n' --resolve www.nz315.cn:443:127.0.0.1 https://www.nz315.cn/login
curl -sk -o /dev/null -w 'cynx  /      = %{http_code}\n' --resolve www.cynx.cn:443:127.0.0.1 https://www.cynx.cn/
pm2 list
```

| 项 | 通过判据 |
|---|---|
| ① | `subject=CN = www.nz315.cn`（**不再是 www.cynx.cn**） |
| ② | `200` |
| ③ | `OUOoNSqTrpZkfWli` |
| ④ | 首行 `HTTP/1.1 301`，且有 `Location: https://www.nz315.cn/` |
| ⑤ | `nz315 /login = 200`；`cynx = 200/301/302`；`pm2 list` 里 **nz315 与 cynx 都 online** |

> 📌 上面的命令是 Linux 标准做法（本机侧同原理已实测：用 node `tls` 探到 443 证书 `CN=www.cynx.cn`）。
> 若某条报错或输出看不懂，**原样贴给我**。

### 2.6 ECS 安全组放行 443

阿里云控制台 → 云服务器 ECS → 实例 → 安全组 → 配置规则 → **入方向** → 确认存在 `443/443 TCP 0.0.0.0/0`。
（80 已通说明安全组基本可用，但 443 可能单独没放行 —— 若服务器本机 curl 通、外部不通，就是这里。）

**外部复测**（在你自己电脑或手机上）：

```bash
curl -I https://www.nz315.cn/MP_verify_OUOoNSqTrpZkfWli.txt
```

**期望**：`HTTP/2 200`（或 `HTTP/1.1 200`），且浏览器打开时**地址栏不报证书错误**。

> ✅ 第一段到此结束。

## 3. 第二段：配「网页授权域名」（5 步）

### 3.1 找入口

1. 浏览器打开 **https://mp.weixin.qq.com** → **管理员微信扫码**登录
2. 左侧菜单：**设置与开发 → 账号设置 → 功能设置**
   （旧版界面叫「公众号设置 → 功能设置」，指向同一页面）
3. 页面上有**三块**：业务域名 / JS接口安全域名 / **网页授权域名** ← 找最下面那块
4. 点「**设置**」（或「修改」）。

> 这一步需要**管理员微信扫码确认身份**，不能跳过。
> **看不到「网页授权域名」= 号不是已认证服务号**（见 §1.1）。

### 3.2 下载校验文件（本项目最容易踩的一步）

点「设置」后页面会让你**下载一个 `MP_verify_XXXXXX.txt`**。

⚠️ 仓库里现有的 `MP_verify_OUOoNSqTrpZkfWli.txt` 是**之前**下载的。
**微信每次进这个页面会重新生成校验文件，文件名可能不同。**
→ **唯一权威 = 你这次点「下载」拿到的那个**，旧的作废。

拿到后（假设新文件名为 `MP_verify_新串.txt`、内容为 `新串`）：

**A. 本地仓库同步**（保持与线上一致）
- 把新文件放进 `E:\二维码管理\public\`
- **删除**旧的 `MP_verify_OUOoNSqTrpZkfWli.txt`

**B. 线上 nginx 直返**（推荐，免重新构建）

```bash
# 把下面的「新文件名」「新内容」换成你本次下载到的真实值
printf '%s' '新内容' > /www/server/nginx/html/MP_verify_新文件名.txt
cat /www/server/nginx/html/MP_verify_新文件名.txt; echo
```

**C. 同步改 `nz315.conf` 里两处 location 的文件名**（80 块 + 443 块各一处）→ 然后：

```bash
nginx -t && nginx -s reload
```

> 💡 **为什么走 nginx 直返而不是放 Nuxt 的 `public/`**：Nuxt 的 `public/` 是**构建时**拷进 `.output/public/` 的，
> 换文件就得重新 `npm run build`（要停 dev、吃内存、有 OOM 风险）。nginx 层直返只需 reload，秒级。
> 若你选 `public/` 那条路，**务必**记得 `npm run build` + `pm2 reload nz315`，否则线上还是旧文件。

### 3.3 先自测，再去后台点保存（重要）

```bash
curl -s -o /dev/null -w 'http  = %{http_code}\n' http://www.nz315.cn/MP_verify_新文件名.txt
curl -s -o /dev/null -w 'https = %{http_code}\n' https://www.nz315.cn/MP_verify_新文件名.txt
curl -s https://www.nz315.cn/MP_verify_新文件名.txt; echo
```

**期望**：两条都是 `200`，且第三行输出文件内容。

先自己确认能访问，**再去后台保存** —— 否则就是白交一次校验。

### 3.4 填域名 + 保存

回到后台弹窗：

- 输入框填：**`www.nz315.cn`**
  - ❌ 不带 `https://`（后台只填 host）
  - ❌ 不带端口 `:443`
  - ❌ 不带路径 `/xxx`
  - ❌ 不用 IP
  - ❌ 不要填 `nz315.cn`（裸域名的 https 本次没配，会报证书不匹配）
- 点「确定」→ **管理员微信扫码确认** → 保存
- 微信服务器会**立刻**去抓那个 txt，**几秒内**返回结果

**期望**：保存成功，页面上「网页授权域名」显示 `www.nz315.cn`。

> ❌ 报「校验失败 / 域名不合法」→ 回 §3.3 确认文件可访问（**尤其是 https**），再检查域名格式。
> ⚠️ 保存失败一般**不计入**月修改次数，但**别连续试到 5 次以上**。

### 3.5 服务器侧凭据核对与最终验收

**先核对凭据键在不在（只看键名，绝不打印值）**：

```bash
grep -oE '^(WECHAT_APP_ID|WECHAT_APP_SECRET|AMAP_WEB_KEY|NUXT_PUBLIC_AMAP_JS_KEY|DB_HOST|DB_PORT|DB_USER|DB_NAME|SESSION_SECRET)=' /var/www/nz315/.env
```

**期望**：至少列出 `WECHAT_APP_ID=` 与 `WECHAT_APP_SECRET=`（09-15 部署时已随 `.env` 传入）。

**若缺失** → 从本机 `E:\二维码管理\.env` 取值补进服务器 `.env`，然后**必须重新构建**：

```bash
cd /var/www/nz315
env PATH=/usr/local/node22/bin:/usr/bin:/bin npm run build   # 期望看到 ✨ Build complete!
pm2 reload nz315
```

（Nitro 的 runtimeConfig 是**构建时内嵌**进 `.output` 的，改 `.env` 不重建则运行期不生效 —— 09-15 已踩过一次。）

**真机验证（唯一有效的验证方式）**：

1. 手机**微信内**打开（普通浏览器会提示「请在微信客户端打开链接」，属正常）：
   `https://www.nz315.cn/api/consumer/wechat/authorize?redirect=/profile`
2. **期望**：出现「农资315 申请获得你的公开信息（昵称、头像等）」→ 点「允许」
3. 跳回 `https://www.nz315.cn/profile`，**显示微信昵称/头像**

**服务器侧查库确认已落行**：

```bash
set -a; . /var/www/nz315/.env; set +a
export MYSQL_PWD="$DB_PASSWORD"
mysql --no-defaults -h127.0.0.1 -P"$DB_PORT" -u"$DB_USER" "$DB_NAME" \
  -e "SELECT id, LEFT(openid,8) AS openid_前8位, nickname, last_login_at FROM consumer ORDER BY id DESC LIMIT 3;"
unset MYSQL_PWD
```

**期望**：出现一行或多行，`openid_前8位` 有值、`last_login_at` 是刚刚的时间。

> `--no-defaults` **不能省** —— `/root/.my.cnf` 会压过 `MYSQL_PWD`，导致误报 `Access denied … 'nz315'@'127.0.0.1'`。

## 5. 排错速查（本项目专属）

| 现象 | 根因 | 怎么办 |
|---|---|---|
| 后台保存报「校验失败」 | 微信抓的是 **https**，而 443 还是 cynx | 回 §2 先配好 443 |
| 授权页报 `redirect_uri 参数错误` | ① 域名没配/配错；② 用户从 **http** 进来，后端拼出的回调是 `http://…`，与白名单（https）不符 | 确认 §2.5 第 ④ 项已是 301；确认后端拿到的 `X-Forwarded-Proto` 是 `https` |
| 报 `10003` / `scope 参数错误或没有 scope 权限` | 网页授权域名没配，或不是已认证服务号 | §3.4 + §1.1 |
| 手机提示「请在微信客户端打开链接」 | 你在普通浏览器里打开了 authorize | 正常现象，改用手机微信 |
| 跳回 `/profile` 仍显示未登录 | Cookie 没种上：代码按 `X-Forwarded-Proto` 判定 `secure`，http 下不种 | 回 §2 修 https |
| `https://nz315.cn`（裸域名）报证书错误 | 免费证书是单域名，不含裸域名 | 统一用 `www.nz315.cn` |
| 改完 `.env` 不生效 | Nitro runtimeConfig **构建时内嵌** | `npm run build` 后 `pm2 reload nz315` |
| 换校验文件后仍抓旧的 | 微信侧缓存 | 手机微信「我 → 设置 → 通用 → 存储空间 → 清理缓存」，或换台没访问过的手机 |
| 站点 502 | 构建没跑成 / PM2 没起来 | `pm2 logs nz315 --lines 50`，确认出现过 `✨ Build complete!` |
| **cynx 打不开了** | **危险信号** | 立刻查是否执行过 `pm2 kill` / `pm2 delete all` / `pm2 restart`；只允许 `nginx -s reload` 与 `pm2 reload nz315` |

---

## 6. 绝对不要做的事

1. **不要**在 `nz315.conf` 里写 `listen 443 ssl default_server`（会抢走 cynx 的默认 443）
2. **不要**碰 `cynx.conf` 一个字节；**不要**重启 `cynx`；**不要** `pm2 kill` / `pm2 delete all`
3. **不要**用 `nginx -s restart`（nginx 无此命令），只用 `nginx -t && nginx -s reload`
4. **不要**把「网页授权域名」反复试到 5 次/月（失败通常不计次，但别赌）
5. **不要**在服务器上打印 `.env` / `/root/.my.cnf` / 数据库密码的值
6. **不要**跑 `node scripts/db-init.mjs`（会往生产库灌演示数据）
