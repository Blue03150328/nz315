## 1. 逐条：改了什么 / 实测证据

### N5 · 首页伪造统计数字（公网可见）
- `server/api/stats.get.ts`：8 行硬编码 → 两个真实 `COUNT(*)`（`scan_log` / `risk_alert` 全量）+ **60s 进程内缓存**；查询失败**返回 `null`**（前端 `index.vue` 已有 `|| '--'` 兜底会显示 `--`）。
- **实测**：`GET /api/stats` 由 `{"totalQueries":128630,"abnormalClues":42}` → `{"totalQueries":213,"abnormalClues":12}`（真值）。
- ⚠️ 口径：累计查询**只统计本平台签发的码**（非本平台码走只读兜底、刻意不写 `scan_log`）⇒ 天然低于真实扫码总量，**属设计使然**。

### N6①②③ · nearby 接口纯防御（**N6④ / N6-b 按用户决定暂缓**）
- ① `CACHE_MAX = 5000` + 满则丢最早一半；② 坐标范围校验（±180/±90），非法**短路返回 `located:false`**（不是 400，保持前端契约）；③ 同 IP **30 次/分钟**限流 → 429。
- **实测**：`lng=999&lat=999` → `200 {"located":false,"rows":[]}` / **38ms**（改前同样能推动 2 次高德调用）；同坐标二次请求 **4ms**（缓存命中）；连打 40 次 → **第 27 次起 429**（前序已用 4 次，阈值精确）。
- ⚠️ **未修的两条**（文件头已标注「已知未做 + 原因」）：**N6④** 拆分高德 key（POI 与 `ip-geo` 仍共用 `amapWebKey` ⇒ **配额被打爆时 `scan_log.province` 仍会静默写不进去**）；**N6-b** 搜索框（服务端仍不读 `keyword`）。用户表示该模块**可能整体下架、改为农资记账功能**，故不投入。

### N4 · 登记证过期 ⇒ 暂停绑定批次
- 新增公共守卫 `assertProductBindable(productId)`，插入 **3 文件 4 处**：`codes/batch-correct.post.ts:47` · `codes/[id]/correct.post.ts:53` · `codes/upload-batches/[id]/correct.post.ts:66`（新建批次模式分支开头）与 `:149`。
- **实测（双向）**：过期产品 `PD20990002`（2020-01-01）换绑 → **400「该产品登记证（PD20990002）已于 2020-01-01 到期…」**；未过期产品（2029-12-31）→ 守卫**放行**、被后续一致性校验拦住（不误拦）。
- ⚠️ **实施时改了 27 号一处**：新建批次那处从「`:111-113` 之间」**前移到分支开头** —— 原位置在 `exist` 未命中时已 `INSERT` 出新 batch 之后，会**留下无码引用的孤儿批次**。
- ⚠️ **上线后会出现"以前能绑、现在被拦"** —— **这是预期行为**。上线前建议先量：`SELECT COUNT(*) FROM product WHERE registration_expire IS NOT NULL AND registration_expire < CURDATE();`

### N2 · 公众端反馈入口（复用 `risk_alert`，零 DDL）
- 新增 `POST /api/feedback`（**本项目第一个匿名写接口**）+ `TraceFeedback.vue`；`TraceAlert.vue` 删掉**永不成立**的 `v-if="resultType === 'mismatch'"` 死按钮与「建设中」stub，改为**除作废码外都可反馈**；`TraceResult.vue` **正品页也加入口**。
- **实测**：入参四态（31 位码 → 400 / 内容过短 → 400 / 合法 → 200 且落 `risk_alert(alert_type=7)` / 同码 5 分钟内 → 429）+ 同 IP 第 6 次 → 429；**真浏览器三条**：正品页与异常页弹窗都能打开（含 textarea、空内容时提交禁用），**作废页无入口**。
- ⚠️ **实施时改了 27 号两处**：① 限流从 Handler 最前**移到入参校验之后**（放最前时连续几次 400 会吃光 5 次/小时额度，用户还没成功提交就被锁）；② **不走 `triggerAlert` 的合并** —— 它的 `code_id <=> NULL` 会把**所有非本平台码的反馈并成一条**、evidence 互相覆盖，改为**按 `code` 字符串合并**。

### N3 · 每日定时巡检（脚本 + 宝塔计划任务，不走 HTTP）

## 4. 顺带发现（本轮新挖，**未处理，供你决策**）

1. 🔴 **`deploy/nginx-nz315.conf` 的 `proxy_pass` 指向 `127.0.0.1:3000`**（主 location 与微信校验文件那两处都是 3000），但 nz315 的 Nitro **跑在 3100**、**3000 是 cynx**。
   ⇒ **照这份模板部署会把 nz315 的流量打到 cynx 上**。线上目前是通的，说明**服务器上的实际配置与仓库这份不一致**（应是部署时手工改过）。
   **建议**：下次上服务器时核对 `nginx -T | grep -A2 nz315` 的实际端口，并**把仓库这份模板同步改成 3100**（否则它就是个定时炸弹）。
2. **公众可写路径的安全前提已核实**：`deploy/nginx-nz315.conf:87` 有 `proxy_set_header X-Real-IP $remote_addr;` ⇒ **nginx 会覆盖客户端自带的 `x-real-ip`**，配合 `clientIpOf` 优先读它的设计 ⇒ **生产环境限流无法靠伪造请求头绕过** ✅。（本机 dev 无 nginx，可伪造 —— 那不是缺陷。）
3. **验证手法踩坑（已写进 `browser-ui-screenshot` skill）**：CDP 里 `el.click()` **必须在 hydration 完成后才有效** —— 过早点击会静默无效、无任何报错，极易被误判成「弹窗打不开」；另 `ui-shot.js` 的 `--js-file` 是把文件内容**当表达式**执行，**不能有顶层 `return`/`await`**，必须写成 `(async () => { … })()`。
