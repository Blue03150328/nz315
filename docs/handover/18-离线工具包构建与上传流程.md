# 18 · 离线工具包：构建与上传流程（可复用）

> **这份文档解决什么**：每次离线工具发新版，都要「本机打包 → 落进网站仓库 → 传到服务器 → 构建生效」。
> 它**不随版本过期**（17 号那种部署执行单是一次性的，这份是长期的）。
> **首次记录**：2026-09-19（离线工具 v1.2.0「纯生图工具」上线时）。

---

## 一、三个决定流程的关键事实

| # | 事实 | 后果 |
|---|---|---|
| 1 | 工具源码在**本机独立工程** `E:\wokeplace\二维码生成离线软件`，**不是 git 仓库** | 工具侧改动**无法用版本控制回溯**；每次发版请顺手记进 `PROJECT_LOG.md`。强烈建议 `git init` |
| 2 | 网站仓库里只有**发布件** `public/tools/nz315-qr-tool-v<版本>.exe`，且被 `.gitignore` 排除（`public/tools/*.exe`） | `git archive` 打的**上线代码包里没有它** → **每次部署必须单独上传**，漏了就 404 |
| 3 | **Nitro 把静态资源清单在构建时写死进产物** | 见下面「顺序铁律」 |

### 🔴 顺序铁律：工具包必须在 `npm run build` **之前**放进 `public/tools/`

本机实测证据：构建产物 `.output/server/chunks/_/nitro.mjs` 里逐条列着静态资源清单，形如

```js
"/tools/nz315-qr-tool-v1.1.0.exe": {
  "type": "application/octet-stream",
  "etag": "\"5aa0e4d-8mrloAmZ3f2QOqYb8+5Rvy08x7A\"",
  "size": 95030861,
  "path": "../public/tools/nz315-qr-tool-v1.1.0.exe"
},
```

**构建之后**再往 `.output/public/` 丢文件 —— 清单里没有这条记录 → **访问 404，`pm2 reload` 也不管用**。
正确做法：放进源码目录 `public/tools/`，让构建自己带过去（`nuxt build` 会把 `public/` 复制进 `.output/public/`）。

## 二、流程 A · 本机出新版

### A1. 改版本号

`E:\wokeplace\二维码生成离线软件\app\package.json` 里 `version` 递增（如 `1.2.0` → `1.2.1`）。
产物名由 `build.portable.artifactName` 决定：`${productName}-v${version}-便携版.exe`。

### A2. 打包（★ 必须用系统 Node 24）

```bash
cd "E:/wokeplace/二维码生成离线软件/app"
PATH="/e/software/nodejs/install:$PATH" npm run dist
```

产出：`app/dist/农药追溯码生成工具-v<版本>-便携版.exe`

> ⚠️ **用托管 Node 22 打包会在「PNG→ICO」图标转换步骤 V8 OOM 崩**（exit `2147483651`，
> `Fatal process out of memory: Zone`）—— 换系统 Node 24 即通过。这条踩过，别重试第二次。

### A3. 自验（三套测试）

```bash
cd "E:/wokeplace/二维码生成离线软件"
node test/test-parse-codes.js            # ① 解析器单测，快
unset ELECTRON_RUN_AS_NODE && \
  "app/node_modules/electron/dist/electron.exe" --no-sandbox test/test-electron-import.js   # ② 真实 Electron E2E
node test/verify-qr-output.js            # ③ 出图可解码性（zxing 读回原文）
```

> `ELECTRON_RUN_AS_NODE=1` 会把 Electron 降级成纯 Node → **必须 `unset`**（设空值无效，它判的是"变量是否存在"）。

### A4. 落进网站仓库 + 改页面

| 动作 | 位置 |
|---|---|
| 复制发布件 | `E:\二维码管理\public\tools\nz315-qr-tool-v<版本>.exe`（**注意文件名不等于产物名**，见下） |
| 改页面常量 | `app/pages/admin/generator/index.vue` 的 `OFFLINE_TOOL`：`name` / `version` / `size` / `fileName` / `url` / `sha256` |
| 删旧包 | `public/tools/` 里上一版 EXE **删掉**（留着会有人从直链下到旧版） |

**`fileName` vs `url` 的区别（容易搞混）**：

- `fileName` = **下载到本机后显示的文件名**，等于打包产物名：`农药追溯码生成工具-v1.2.0-便携版.exe`
- `url` = **服务器上的实际路径**：`/tools/nz315-qr-tool-v1.2.0.exe`

两者名字不同是历史原因，**别试图统一**（改了 `url` 就必须同步改服务器文件名）。

SHA256 用 node 算（本机 `certutil` 输出带空格，不好直接贴）：

```bash
node -e "console.log(require('crypto').createHash('sha256').update(require('fs').readFileSync('public/tools/nz315-qr-tool-v1.2.0.exe')).digest('hex'))"
```

### A5. 提交

```bash
cd "E:/二维码管理"
git add app/pages/admin/generator/index.vue
git commit -m "feat: 离线工具 v<版本> 接入生成页"
```

## 三、流程 B · 上传到服务器

### B1. 传文件（二选一）

- **宝塔面板**：文件 → 地址栏输入 `/var/www/nz315/public/tools` → 上传
- **SFTP**（面板上传卡住/超时就用这个）：WinSCP / FileZilla，账号同宝塔，传到同一路径

### B2. 服务器终端核对 + 删旧版

```bash
cd /var/www/nz315/public/tools
ls -l
sha256sum nz315-qr-tool-v1.2.0.exe
rm -f nz315-qr-tool-v1.1.0.exe
echo "--- 删旧后 ---"; ls -l
```

**判据**：SHA256 与页面展示值**逐字符一致**、字节数对得上、删旧后**只剩一个 EXE**。

### B3. 构建（**必须在 B2 之后**）

```bash
cd /var/www/nz315
env PATH=/usr/local/node22/bin:/usr/bin:/bin npm run build
ls -l .output/public/tools/
pm2 reload nz315
```

`ls -l .output/public/tools/` 是「上传有没有生效」的判据 —— 里面应只有新版本那一个文件。

### B4. 验证（公网侧）

```bash
curl -sI https://www.nz315.cn/tools/nz315-qr-tool-v1.2.0.exe | grep -Ei 'HTTP/|content-length|content-type'
curl -s -o /dev/null -w '旧版应为 404 : %{http_code}\n' https://www.nz315.cn/tools/nz315-qr-tool-v1.1.0.exe
```

期望：`HTTP/2 200` + `content-length` 等于实际字节数 + `content-type: application/octet-stream`；旧版 `404`。

**再用浏览器在生成页上真点一次「下载离线工具」** —— 该按钮走 `fetch → Blob → 临时 a 标签`（不是直链），
所以「curl 200」与「页面上点得动」是两件事，都要验。

## 四、常见坑

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面上点下载 404（但文件明明在服务器上） | 构建后才放的，或漏了 build | 确认文件在 `public/tools/` 后**重新 build** |
| 下载到的还是旧版 | 服务器上旧 EXE 没删 / 浏览器缓存 | 删旧文件；页面 `OFFLINE_TOOL.url` 是否已指向新版本名 |
| 打包崩 `exit 2147483651` | 用了托管 Node 22 | 换系统 Node 24 打包 |
| `require('electron')` MODULE_NOT_FOUND | `ELECTRON_RUN_AS_NODE` 被注入 | `unset ELECTRON_RUN_AS_NODE`（**不能设空值**） |
| 90 MB 传完 SHA256 对不上 | 传输损坏（二进制不报错） | 删掉重传，别抱侥幸 |
| 生成的图扫不开 | 工具里追溯地址错了 / DataMatrix 模块 <4px | 地址应为 `https://www.nz315.cn/trace?code=`；DM 建议 ≥4、静区 ≥2 |
