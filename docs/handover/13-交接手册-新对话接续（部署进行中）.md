## 3. 铁律（违反任意一条都可能出事故）

1. **PM2 只允许 `pm2 reload nz315`**。**禁止** `pm2 kill` · `pm2 delete all` · `pm2 restart`（daemon 与 cynx 共用，重建 daemon = cynx 挂）。
2. **pm2 命令一律裸写**（`pm2 describe nz315`），**绝对不要给它加 `env PATH=...` 前缀**。已实测：`which pm2` = `/usr/local/bin/pm2`（v7.0.3）。加 PATH 前缀有两个后果：① `env: 'pm2': No such file or directory`；② 就算找到了，CLI 的 Node 版本一旦和 daemon 不一致，**PM2 会杀掉并重建 daemon → cynx 挂**。
3. **只有 `node` / `npm` 类命令需要 PATH 前缀**：`env PATH=/usr/local/node22/bin:/usr/bin:/bin npm run build`。因为 nz315 用独立安装的 node22，系统 `/usr/bin/node`(v20) 是给 cynx 用的。
4. **nginx 只用 `nginx -t && nginx -s reload`**，**不用 restart**；**不碰 `cynx.conf` 一个字节**。
5. **不跑 `node scripts/db-init.mjs`**——本次零数据库变更。
6. **不在服务器跑 `git clean -fdx`**——会抹掉 gitignored 的 90MB 离线工具 EXE，git 不知情。
7. **改 `.env` 必须重新 `npm run build`**：Nitro 的 runtimeConfig 是**构建时内嵌进 `.output`** 的，改完不重建运行期不生效（历史上踩过一次「Access denied」，重建后才 200）。
8. **上传包/EXE 必须校验 SHA256**（见 §4），传坏了极难排查。

## 9. 本轮踩过的坑（**下一轮别重复**）

### 给服务器写命令的坑（最贵的一类）

- **猜命令路径**：手册里写 `env PATH=/usr/local/node22/bin:/usr/bin:/bin pm2 ...`，pm2 根本不在那段 PATH 里 → 用户撞墙。**根因**：为了给 `node`/`npm` 指定版本而套的 PATH，把 pm2 也圈进去了；而 pm2 的真实位置（`/usr/local/bin/pm2`）是当时**猜**的，恰好猜对，但"猜对"不等于"有依据"。
- **猜输出形态**：写「`ps -eo pid,args | grep God Daemon` 看第 1 列 = node 路径」——实测第 1 列是 **PID**，而且 **PM2 会改写进程标题**（`PM2 v7.0.3: God Daemon (/root/.pm2)`），`ps` 里**根本没有** node 路径。**双重错**。
- **通用铁律**：写进运维手册的「命令 + 期望输出」，**证明输出形态的那一半和命令本身一样需要证据**。没真跑过的命令，要么不写，要么**显式标注「未验证」**——写"应该会看到 X"而实际是 Y，用户只会更慌。

### 本机 git 的坑（同族第 7 次复现）

- **写不了嵌套引用**：`refs/heads/a/b` 创建不出来，且**所有相关命令 exit 0 无报错**。绕过：本地分支用**平铺名**（`ewm` ← `origin/feature/ewm`），或 node `fs` 直写 loose ref。判定引用只看 `git rev-parse` 与 `.git/refs/heads/`，**绝不信退出码**。
- **checkout/merge 后"文件不落盘"**：工作区只落地"两分支差异文件"，`git status` 报一堆 ` D`，极易误判成"代码丢了"。**真相是文件没丢**，`git reset --hard HEAD` 全量铺回即可。**把 `git reset --hard` 当 checkout/merge 后的常规收尾动作。**
- **判定"文件是否缺失"只能用 `git status`**：`git ls-files` + `existsSync` 会因 `core.quotePath` 把中文名转义成八进制而**假阳性报缺失**。
- **没有全局 git 身份** → 用 `git config --local` 写（本仓库历史作者为 `Administrator <admin@nz315.cn>`）。
- **远端引用值变化 ≠ 故障**：先看 reflog（`update by push`）+ `git ls-remote` 核实，再下结论。
- **`git archive` 打包**只含已跟踪已提交内容，天然排除 `.env`/`node_modules`/gitignored 大文件——正是部署要的。**列 `tar tzf` 条目不要假设 `./` 前缀**（按 `/^\.\/deploy\//` 过滤会得出"包里没有 deploy"的假阴性，我犯过）。
