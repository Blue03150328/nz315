# 产品七列简版导入（2026-10-17，本机完成，未上线）

厂家只填写生产类型、登记证号、产标名、规格代码和1～3个原药登记证号。此前本机22列候选已由本方案替换，不再要求手填规格名称、产品资料或原药生产企业，也不再自动创建规格。

## 模板与填写

第一张表固定七列表头：生产类型、登记证号、产标名、规格代码、原药登记证号1、原药登记证号2、原药登记证号3。产标名指产品商标；兼容此前“产品商标”和“商标”别名，但同一表不能重复提供这些列。

- 必填生产类型、完整产品登记证号、规格代码、原药登记证号1。原药2/3不用时留空，无商标可留空；原药2空而3有值时保留实际填写的证号。
- 生产类型提供Excel下拉，接受持有人生产/委托加工/委托分装以及1/2/3。持有人生产须与账号归属企业的登记持有人名称归一匹配；委托类型允许外部持有人，并分别保存产品归属与证件持有人。
- 第二张表为填写说明；第三张表为本企业启用规格的代码、名称、企业和状态对照。总部先选企业再下载；普通企业忽略伪造的enterpriseId，始终只下载本企业对照。无启用规格时明确提示先建档。
- 仅读取第一个工作表，每行一个产品。支持xlsx/xls、一个文件、10MB、1000数据行。表头可换序、可删可选列；未知列、重复列、第四原药列、缺表头数据、公式（含结果为空）整批拒绝。1000行按首表使用范围判断，空行跳过但保留原行号。
- 网页下载接口为GET /api/admin/products/import-template，禁止缓存。以随应用发布的模板为基础只更新规格对照XML，保持首表生产类型下拉、冻结行、文字格式和说明。通用静态模板不含任何厂家真实规格，供先行填写；实际代码请从网页企业模板核对。

## 自动补齐与校验

- 规格代码只在本企业已有规格中精确匹配，1/01/001均归为001。仅允许001～999，拒绝小数、科学计数文本和规格名称；数值单元格读取真实值，避免显示取整导致错误关联。规格停用、不存在或多重历史匹配均拒绝，不创建/启用/修改规格。
- 产品与全部原药证号归一大写后批量精确查询pesticide_reg。产品名称、类别、剂型、含量、毒性、持有人、有效期和原药企业/成分全部来自登记库，名称沿用商标+完整成分产品名称+剂型+规格规则。未收录、必需登记资料缺失时该行失败，不通过成分猜选原药供应商。
- 原药证件须为原药或母药；同一产品重复证号拒绝；原药成分与产品明确不符时拒绝。复配产品尚缺部分成分来源时成功导入并给出待核对提示，不以原药条数等同成分数。产品成分资料缺失时提示无法完成成分核对；原药自身缺成分时无法补齐，拒绝该行。
- 产品与原药有效期按Asia/Shanghai当日核对：截止当天可用，早于当天阻止；登记库无有效期时保留空值并提示核对，格式错误拒绝。登记库更新滞后时需先核实补录，不假造新日期。
- 产品默认启用，限制使用字段沿用现有默认0；七列不提供此字段，需按实际在单个编辑中核实。原有单个新增/编辑的自定义填写与新证豁免通道保留。
- SKU沿用企业+登记证号+规格+商标查重，包含停用产品、同文件重复和并发提交；生产类型、产品名称或原药变化不能绕过重复判定，不覆盖旧产品或原药。

## 失败行与事务

成功行保存，业务失败行给出原Excel行号、登记证号、原因和原值。网页可下载“产品导入失败行.xlsx”，第一表只有可重传的七列失败产品，第二表列出失败文件行号、原文件行号、登记证和原因；修正后直接重新选择上传。成功产品重传提示重复。

企业行锁协调并发和规格操作，产品及原药共事务、每行保存点；该行后续原药插入失败时回滚该产品和已插原药，后续行可继续。非预期数据库故障回滚整批。操作日志记录企业、文件名、成功/失败数、核对提示数和前十条简要错误。

产品批量导出统一同样七列及顺序，“产标名”字段读取原产品商标，规格和证号保留前导零。导出可进入同一导入流程；既有SKU仍报重复。超过1000条需拆分导入；历史原药为空、未被登记库收录或已过期的导出行仍须按当前导入规则核实，格式兼容不等于所有历史资料必然可重新建档。
