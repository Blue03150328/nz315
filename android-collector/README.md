# 农资315 · Android采集APP

适配优博讯i6310 PRO的扫码采集工具，Android最低8.0，目标使用环境Android12。离线模式无需登录或联网，支持内部码、外部码和可选箱瓶关联；1.1.0新增独立联网生产入口。真实设备兼容性以验收记录为准。

## 联网生产（1.1.0）

首页点击“联网生产任务与剩余码审核”，填写服务器地址并使用后台账号登录。每台采集设备使用独立码管理员账号；同一账号在其他设备登录会替换当前会话。密码与会话不保存到磁盘，退出或进程关闭后重新登录。正式版本只连接HTTPS，调试版本可连接本机HTTP测试服务。

1. 在网站先生成码并入库留档，不提前绑定生产资料。
2. 在APP选择产品，填写任务名、批号、生产日期、有效期至、质检合格及质量合格证号；粘贴或通过文件选择器读取具体32位码清单，每行一码，最多10000个。也可在网站创建任务后在设备列表打开。
3. 点击确认领用，只锁定码清单。连续扫描实际用于产品的二维码，服务器确认才记已使用；正在提交时不要扫下一个，广播模式会提示前一码未确认。超时保留当前码，联网后重试同一码，服务器不会重复计数。
4. 结束生产，系统自动统计具体未用码并提交审核，无需再扫描剩余包装。结束后禁止继续生产；此前成功但收据丢失的码仍可重试核对。
5. 厂家管理员在后台查看完整明细并批准剩余码再次领用；退回继续锁定。管理员APP也提供审核操作。已用码仍属于原批次，不允许普通修改/删除入口覆盖。

扫码头广播及键盘模式沿用首页“扫码设备设置”；联网时后台不接收广播，确认结束的对话框暂停接收。设备识读提示音不代表服务器成功，以APP“生产扫码成功”收据为准。该模式不把联网码混入原离线箱瓶数据，不支持断网继续计数。

本机验收地址使用电脑局域网IP（设备上的localhost是设备自身），仅调试版可填`http://电脑IP:3100`。正式域名需先部署本轮服务器接口及三表迁移，旧版服务器不能直接使用新功能。

调试包在`release/nz315-collector-1.1.0-debug.apk`，仅用于测试。原正式版覆盖升级必须使用原私钥执行`build.ps1 -Release`，不能以调试签名覆盖，也不能为了安装测试版卸载或清除有未导出数据的原APP。原有离线数据库和导出格式未改变。

## 使用流程

1. 安装正式签名APK，打开“扫码设备设置”。在设备ScanWedge/扫码设置中选择广播输出，动作默认`android.intent.ACTION_DECODE_DATA`，字符串字段默认`barcode_string`。具体固件字段不同可在APP中修改。
2. 如设备只能使用键盘输出，在APP勾选键盘模式，设备设置扫码后附加回车。采集页面保持输入框焦点。两种输出方式任选一种，避免同时输出产生重复提示。
3. 新建任务，选择内部/外部模式、是否关联箱码、默认先箱或先产品。资料只填写一次，未知资料留空并标记待补。任务名称必填，填写生产日期时必须是真实日期。
4. 内部产品码保存32位数字字符串；完整内部链接只接受本任务配置的网址。默认`https://www.nz315.cn/trace?code=`。同一任务前11位保持一致，防止产品/生产类型/规格混采；完整产品字典和数据库状态仍须在平台导入时校验。外部产品码保留全部扫码原文，不打开链接。箱码始终保存原文，不提取32位。
5. 先箱后产品：点“采集箱码”并扫箱，自动切换产品，连续扫瓶/袋，核对数量后点“完成本箱”，再点“下一箱”。
6. 先产品后箱：点“采集产品码”连续采集，显示待关联；点“采集箱码”补扫箱，再完成本箱。数量按实际扫描统计，不设置每箱瓶数。
7. 暂停采集时、资料编辑时和后台页面不接收采集。切到其他应用时停止订阅广播；再次打开任务恢复数据库记录。振动及“已保存”提示表示本次记录已提交，设备自身扫码提示音仅表示识读成功。
8. 查看记录可切换箱、重新打开箱、删除误扫、移箱。移箱前两箱均需重新打开且必须属于同一任务；实物也应一起移动。箱码更正通过明确操作完成，不允许直接扫新箱覆盖旧箱。清除误扫箱码保留已有产品为待关联，误扫空箱清除后不影响任务完成。
9. 任务完成前所有已使用箱均需有产品并完成；缺失公共资料仍明确标记待补。“采集完成”仅代表本机采集状态，不代表平台生产绑定或质检放行。

## 导出与保存

点“导出文件夹”，在系统目录选择器中选择Documents下的可写文件夹。Android12不能直接授权部分系统根目录。每次导出使用独立名称，不覆盖旧结果。采集中也能导出，快照保留未完成和待关联状态。

- `追溯码清单.txt`：UTF-8，每行一个产品码。内部模式可用于现有平台码文件解析；外部模式不承诺平台能够识别。
- `采集明细_原始.csv`：产品码、箱码、时间、来源和状态的原始数据。程序读取，禁止用Excel打开再另存导致长码精度损失。
- `采集明细_表格查看.csv`：单元格增加文本前缀，适合表格查看，防止数字精度损失与公式执行；不是原始码文件。
- `箱码关联.csv`：一行一个箱与产品关系。未启用装箱时不生成。
- `任务资料.json`：schemaVersion=1的完整结构，包括任务资料、组、产品、操作记录。后续平台对接以此为依据。
- `操作记录.csv`：更正、移箱、删除及状态切换记录。
- `二维码图片/`：按需生成产品二维码PNG，内部模式补上任务保存的网址，外部模式使用原文；序号与采集明细对应，不生成箱码。
- `导出完成.json`：最后写入，包含每个文件的大小和SHA256。必须可解析、status为COMPLETE并且哈希一致，才代表导出成功。失败目录保留失败说明，不得导入，原数据仍在APP内。
- 多行原文采用`追溯码清单.jsonl`替代TXT，读取value可还原字符；扫描头附加的末尾回车默认移除，可在设备设置关闭，以保留原码实际换行。

离线模式去重范围为**同一设备、同一任务**，同任务不同箱重复也拒绝。不同设备间离线无法即时判重，导入平台时还须再次校验。离线文件仍不自动同步，暂无文件恢复导入及自动打印；箱码、产线与任务JSON不会自动进入网站数据库。联网模式单独使用服务器领用及使用记录。

**每日导出并拷贝到电脑备份。正常使用同一签名新版APK覆盖安装保留本地数据；卸载、清除应用数据或设备损坏会丢失未导出的采集记录。** 云备份和设备迁移默认关闭，避免未经核对复制生产采集状态。

## 构建与更新

使用固定JDK17、Gradle8.11.1、AGP8.9.2、Kotlin2.1.20、SDK35及BuildTools35.0.0。Gradle Wrapper带官方分发包SHA256。依赖为Google/Maven Central，首次构建需要下载；运行APP不需要网络权限。

配置`JAVA_HOME`及`ANDROID_HOME`，执行：

```powershell
.\build.ps1
.\build.ps1 -DeviceTests
```

Windows中文路径自动映射临时盘符，结束后解除映射，不搬动源码。正式构建通过环境变量指定`NZ315_KEYSTORE_PATH`、`NZ315_STORE_PASSWORD`、`NZ315_KEY_PASSWORD`，别名`nz315-collector`，再执行`build.ps1 -Release`。签名私钥及密码必须单独保管，不在源码或分发包中。遗失签名后不能覆盖更新已有安装。

后续更新时增加versionCode，固定applicationId与同一签名。例如：

```powershell
.\build.ps1 -Release -VersionCode 2 -VersionName 1.0.1
```

构建产物在`app/build/outputs/apk/`。本项目只用于Android采集，根项目网站发布归档排除此目录。

架构与迭代约定见[docs/架构与迭代.md](docs/架构与迭代.md)，实测与未验范围见[docs/验收记录.md](docs/验收记录.md)。
