# 1.1.0 两页界面与即时录入结果

日期：2026-10-07。用户最终确认两个主页面：设置生产采集任务、生产采集任务记录。此前讨论过的三页方案不采用。

## 页面职责

- 生产采集任务：设置产品、规格、生产批次等资料，选择码模式及箱瓶顺序，配置扫码设备，进入已有任务。
- 生产采集任务记录：输入或扫描二维码，输入下方直接显示本次保存状态、完整内容入口、箱归属及时间；显示当前箱最新5条已保存产品码。完成本箱、开始下一箱、导出和任务切换均在此页。
- 全部箱与产品记录是记录页内的查询视图，不增加第三个底部页面。更正与完成任务放进“更多任务操作”。

## 数据与反馈约束

1. 本次结果与已录入列表分开。重复、无效码或存储失败显示“未录入”，不能伪装成成功记录，不增加数量。
2. 每次成功反馈基于事务提交后的数据库快照；输入、广播和键盘输出共用流程。
3. 当前箱列表最多查询5条，按时间及SQLite行号倒序，避免同毫秒连续扫描顺序不稳定或加载全任务。
4. 切换箱时更新列表，修改或删除后不保留失效的成功反馈。重启后从数据库恢复最新码；未保存的失败尝试不当作历史码恢复。
5. 任务设置页及历史查询不接收扫码；旋转历史查询仍保持查询状态。底部任务和记录入口始终可见。
6. 数据库版本仍为1，导出schema仍为1，无表结构迁移。applicationId和正式签名保持不变；versionCode使用3，避免与首轮覆盖升级测试版2冲突。

## 验证

实测结果在交付前补齐；设备环境为独立Android15模拟器，不代表Android12或优博讯实体扫码头验收。

UI回归脚本：`tests/ui-records-smoke.mjs`。只有显式设置ANDROID_SERIAL和NZ315_UI_TEST_DEVICE=1才运行，并在测试设备生成独立任务；不会卸载或清除应用数据。可用NZ315_UI_APK指定同签名新版APK验证覆盖升级，用NZ315_UI_OUTPUT指定截图和报告目录。
