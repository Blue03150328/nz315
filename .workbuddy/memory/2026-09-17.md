## 微信授权 502「未返回 openid」排查与修复（13:55 用户报障 → 14:0x 完成，提交 `a372c7e`）

- **用户原话**：「我在 nz315 首页→我的→登录微信之后返回这个（502 截图），我需要修复这个问题，**https 一定要配吗**」。
- **结论：这次 502 与 HTTPS 无关**（下午 14:0x 复测，HTTPS 仍一点没动：443 证书 `CN=www.cynx.cn`、`https://www.nz315.cn/` 是 cynx 首页、
  https 校验文件 **404**、**80 未 301**）。真正的链路证据：`http://www.nz315.cn/` 200、校验文件 200、
  `authorize` 302 且 `redirect_uri` = **http** 回调 → **微信确实带着 code 回调到了服务器**（`缺少 code` 是另一条 400 分支；
  全仓库只有 `callback.get.ts` 一处会产生 502 那句文案）→ **OAuth 第一步在 http 下是通的，http redirect_uri 被微信接受了**。
  → 顺带推翻一个既有认知：14 号文档/AGENTS.md 说「微信必抓 https 校验文件、不补 HTTPS 必然配不上域名」——与「授权回调能发生」**存在张力**，
  说明**微信校验很可能走 http**（或对 http 宽容）。下次核对公众平台域名配置状态时要重新验证，**别再直接沿用**。
- **根因在代码层：失败详情被吞**。原代码 `tokenRes?.errmsg || '未返回 openid'` 两处盲区：**(a)** ofetch 对**非 JSON 的 Content-Type**
  会**原样返回字符串** → `openid`/`errmsg` 全 undefined；**(b)** 只看 `errmsg` 不看 `errcode`。
- **🔴 跨会话必记的微信侧实测事实（本机亲自验证，别再猜）**：
  1. 微信 `sns/oauth2/access_token` 响应头是 **`Content-Type: application/json; encoding=utf-8`**（**不是** text/plain，本机链路实测）；
  2. **微信失败响应必带 `errmsg`**（实测 `{"errcode":40029,"errmsg":"invalid code, rid: …"}`）→ 所以**线上出现「errmsg 为空」就意味着拿到的根本不是微信 JSON**；
  3. 用**真 appid + 假 secret + 假 code** 请求会返回 **40029 invalid code**（而不是 40125 invalid appsecret）→ **这就是「凭据是否匹配」的低成本探针**，
     不需要真 code 就能判断一对 appid/secret 是否有效（`40013`=appid 无效、`40125`=secret 不匹配）。
- **⚠️ 新隐患（部署前必须核对）**：本机 `.env` 的 `WECHAT_APP_ID` = `wx9bd4bc120dea3f98`，而本机
  `.output/server/chunks/_/nitro.mjs` **内嵌** `wechatAppId` = `wx1a6093c716310340`，**两个不同公众号，且两个 appid 都真实存在**。
  `runtimeConfig` 构建期内嵌 → **线上用哪个取决于服务器那份 `.output` 是用哪份 `.env` 构建的**。**appid 口径未核准前不部署**。
- **修复产物**：`server/api/consumer/wechat/callback.get.ts` 加 `callWechatApi()`（`responseType:'text'` + 手动 `JSON.parse` + `__raw` 兜底）
  与 `describeWechatFailure()`（`errmsg（errcode=…）` / 原始响应），失败详情 `console.error` 进 PM2 error log。新增 `docs/handover/15-微信授权502排查与修复.md`。
- **验证手法（可复用）**：`esbuild.transform` 转译该路由 → 把 `~~/server/utils/*` 的 import 替换成 stub → 注入 `globalThis.$fetch` 等
  Nitro 全局 → 动态 import 后逐场景驱动**真实路由逻辑**（6 场景全过，含 text/plain 字符串、HTML、空响应）。比"只跑 tsc"有效得多。
- **🔴 本轮踩坑（自己造成的）**：清理临时脚本时用 `f.startsWith('_tmp-')` **通配删除了 15 个文件，其中 10 个是历史遗留脚本**
