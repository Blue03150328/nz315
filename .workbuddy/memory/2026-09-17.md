## 微信网页授权域名配置：诊断 + 流程文档（提交 `6f0dfeb` on master）

- **用户诉求**：把 nz315 授权到微信公众平台的「网页授权域名」。
- **实测发现（关键，跨会话必记）**：`www.nz315.cn` 的 **443 端口目前没有 nz315**。
  - `https://www.nz315.cn/` 返回的标题是 **cynx（广西超优农选）** 的首页；
  - `https://www.nz315.cn/login`、`/MP_verify_OUOoNSqTrpZkfWli.txt` 都是 **404**；
  - 443 证书 `subject CN = www.cynx.cn`、`SAN = DNS:www.cynx.cn`（Let's Encrypt，2026-11-17 到期）。
  - 根因：`nz315.conf` **仍只有 80 端口块**（12 号手册第 9 步 HTTPS 未做），443 上只有 cynx 的 server 块兜底，
    凡不精确匹配 server_name 的 SNI 都落到它。
  - HTTP 侧正常：首页 200（含备案号）、校验文件 200（内容 `OUOoNSqTrpZkfWli`）。
- **微信官方口径（已查证）**：网页授权域名**只支持 https**、需 ICP 备案（新备案满 24 小时）、
  校验文件须放域名根目录、**最多 2 个域名 / 每月最多改 5 次**、需管理员扫码、
  **仅已认证服务号可配**（订阅号/未认证号看不到该栏）。
  → **HTTPS 未修好之前去配必定失败**（微信抓 https 拿到 404），且白费配额。
- **顺带确认（省事的结论）**：本项目**未使用微信 JS-SDK**（全仓库无 `wx.config` / `jsapi_ticket`）
  → **只需配「网页授权域名」一项**；网页授权走 `sns/oauth2/access_token` + `sns/userinfo`，
  **不需要 IP 白名单**；「业务域名」可选且每月只 3 次，本轮不碰。
- **产出**：`docs/handover/14-微信网页授权域名配置流程.md`
  （前置条件自查表 + 两段 8 步可粘贴命令 + 每步通过判据 + 验收清单 + 排错速查 + 禁止事项）。
- **坑位提醒（写文档时推导出来的真实风险）**：`authorize.get.ts:15-17` 用请求头 `X-Forwarded-Proto` 拼回调域名
  → **80 端不 301 到 https 时，从 http 进来的用户回调会拼成 `http://…`，微信直接报 redirect_uri 错误**。
  所以「80 跳 301」不只是好看，是**功能必需**。
- **nginx 两个硬约束**（写进 14 号文档）：① **绝不写 `listen 443 ssl default_server`**（会抢 cynx 的默认 443）；
  ② 不加裸域名 `nz315.cn` 的 443 块（阿里云免费证书是单域名，裸域名会证书不匹配）→ 对外统一用 `www.nz315.cn`。
- **本机环境补充**：`curl` 直连会被**系统代理**接管（返回 `HTTP/1.1 200 Connection Established`），
  且 Git Bash 的 `head`/`grep`/`rm`/`dirname` 本轮全瘫 → 线上探测一律改用 **node 直连脚本**
  （`https`/`tls` 模块 + `rejectUnauthorized:false` + `servername` 拿 `getPeerCertificate()`），临时脚本用完即删。
- **git**：本轮 `git commit` 正常落盘、引用正常（未复现静默失败），工作区干净。

## AppSecret 变更流程（用户 11:15 提问，已补进 14 号文档 §4）

- **微信侧只有「重置」，没有「查看」**：路径 = 登录 mp.weixin.qq.com → **设置与开发 → 基本配置 → 公众号开发信息**
  （旧版叫「设置与开发 → 开发 → 基本配置」）。AppID 明文可复制（本项目 18 位）；
  AppSecret 默认不可见，**只能点「重置」** → 管理员扫码 + 公众号登录密码 → **新值只显示一次**。
- 🔴 **重置后旧值立即失效**，线上微信登录会持续报 `errcode 40001 invalid credential`，直到服务器同步并生效
  → 正确顺序是**先把两边 `.env` 改好、准备好构建，再去后台点重置**。
- **项目侧改两处**：本机 `E:\二维码管理\.env` + 服务器 `/var/www/nz315/.env`（均已含该键，本机值 32 位）。
  - **路线 A（推荐）**：改 `.env` → `npm run build` → `pm2 reload nz315`（runtimeConfig 构建期内嵌）。
  - **路线 B（免构建）**：`deploy/ecosystem.config.cjs` **第 50-53 行**（回退后的原版行号）已预留 `NUXT_WECHAT_APP_SECRET` 注释位；
    ⚠️ 但 **`pm2 reload nz315` 不会重读 config 文件的 env**，必须 `pm2 startOrReload deploy/ecosystem.config.cjs`。
- **代码引用链（只有这一条）**：`nuxt.config.ts:55-56`（`process.env.WECHAT_APP_*` → runtimeConfig）
  → `server/utils/consumer-auth.ts:99-105` `getWechatConfig()` → `authorize.get.ts` / `callback.get.ts`。
  `.env.example` 已含这两个键的模板。
- ⚠️ **顺带发现的潜在雷（未擅改，只提醒）**：仓库里 `deploy/ecosystem.config.cjs` **仍是未修正版** ——
  `PORT`/`NITRO_PORT` = **3000**（= cynx 的端口）、**无 `interpreter`**（不加就会用系统 node v20 启动，
  而 Nuxt 4.5 要求 ≥22.19）。服务器上那份是 09-16 手工修正过的（3100 + interpreter），
  12/13 号文档为此专门写了「解包后要用备份里的 deploy-server-corrected 覆盖回去」这一步。
  → 根治办法是把仓库版也修正成 3100 + interpreter，那样部署流程能少一步手工还原（待用户确认后再动）。
