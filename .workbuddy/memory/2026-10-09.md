## 诊断：内部生成的码，扫出「农资315 · 外码查询」

**现象**：用户扫一张"内部生成"的码，公网 `www.nz315.cn` 返回页头「农资315 · 外码查询」，
正文"尚未取得厂家来源资料…该码由外部平台提供"，下方却整块展示 `PD20241971` 的登记资料。

**结论（已实证）**：该码**不在 `trace_code` 表**。不是被作废/冻结（那会走异常页），也不是格式非法
（格式非法根本不会展示登记资料）。线上 `/api/trace` 在 `trace_code` 未命中时走「登记资料库兜底」分支
→ `resultType='external-reg'` → 渲染 `app/components/TraceExternal.vue`（页头那句"农资315 · 外码查询"
就是这个组件的固定标题）。

**机制定位**：`server/api/trace.get.ts` 第 71–112 行（**ycdb 线**）：

```ts
const [tc] = await query('SELECT * FROM trace_code WHERE code = ? LIMIT 1', [code])
if (!tc) {                       // ← 未命中
  const registry = await lookupRegistryByCode(code)   // 用码前 8 位撞农药登记资料库
  ... resultType: 'external-reg'  // → TraceExternal 页
}
```

登记资料来自 `server/utils/registry-lookup.ts`：只取码**前 8 位**解析
（第 1 位类别 `1=PD / 2=WP` · 第 2–7 位登记证后六位 · 第 8 位生产类型 `1/2/3`），
拿「后六位 + 类别」去 `pesticide_reg` 撞候选。

**铁证（本机直连公网实测）**：
`GET https://www.nz315.cn/api/trace?code=12419711000000000000000000000000`
（前 8 位与截图一致，后 24 位填 0）返回：

- `resultType: "external-reg"`
- `reasons[0]`：`该追溯码不是本平台（农资315）签发的追溯码，本平台没有该码的生成与生产记录`
- `registryCandidates[0]`：`PD20241971` / 氯虫·噻虫胺 / 广西瑞施特生物科技有限公司 / 颗粒剂 /
  0.16% / 「噻虫胺 0.12%、氯虫苯甲酰胺 0.04%」/ 2029-06-10 / `importedAt 2026-09-03 15:37:46`

→ 与用户截图**逐字段完全一致**（含「资料入库时间 2026-09-03 15:37:46」）。
⇒ 截图那一整块"登记资料"是**登记库兜底的产物，跟这个码本身毫无关系**；
且该码前 8 位必然是 `12419711`。

**本机库旁证**（只读查询，脚本已删）：`trace_code` 仅 120 行（演示库），无 `12419711%`、无含 `241971` 的码；
`product` 表无 PD20241971（仅 4 个演示产品）；`pesticide_reg` 后六位 241971 唯一命中 PD20241971（与截图对上）。

**🔴 附带发现（重要，易误判）**：「公众端外码兜底」只在 **ycdb / SMXT** 分支，
**master 工作区没有** `server/utils/external-verification.ts` / `registry-lookup.ts` / `TraceExternal.vue`。
⇒ 本机 dev（当前 checkout = master，端口 3100）扫同一个码会显示「该追溯码未在追溯系统中登记」（not-found），
**与线上行为不同，属版本差异、不是缺陷**。要本地复现线上行为须切 ycdb。

**未判定（待用户提供信息）**：这个码到底怎么来的 —— 离线出图工具生成的码未导入网站？
