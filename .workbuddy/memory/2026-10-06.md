## 定位（P0）：公众端「记账 · 保存」点了没反应 —— 前端 `number.trim()` 崩溃

**结论：故障在前端，`/api/bill` 根本没被调用；不是接口问题。**

- **崩点**：`app/components/BillFormModal.vue:182`
  `if (form.totalAmount.trim() === '' || ...)`
- **原因**：金额输入框是 `UInput type="number"`，而 Nuxt UI v4 运行时
  `node_modules/@nuxt/ui/dist/runtime/components/Input.vue:78-80` 对
  `props.type === 'number'` 一律走 `looseToNumber(value)`（`utils/index.js`：
  `parseFloat` 成功即返回 number）⇒ `form.totalAmount` 运行时是 **number**，
  number 上没有 `trim` ⇒ `TypeError: form.totalAmount.trim is not a function`
  抛在 async 事件处理器里（Vue 不弹 UI），表现 = **点保存毫无反应**。
- **失效边界（与实测现象完全一致）**：
  | 场景 | totalAmount 运行时类型 | 结果 |
  |---|---|---|
  | 新建记账（金额必填，必然手填） | number | ❌ TypeError，静默失败 |
  | 编辑账单且**不动金额** | string（回填走 `String()`） | ✅ 正常保存 |
  | 产品名为空时点保存 | —— | ✅ 正常提示「请填写产品名称」（校验在崩点之前） |
- **引入时间**：`20caee5`（09-29 10:25「增加账本筛选并提升记账完整率」）把原来的
  `totalAmount: form.totalAmount === '' ? 0 : Number(...)`（对 number 安全）改成上面的
  `.trim()` 写法。`type="number"` 早在 `0542d72`（09-23）就存在 ⇒ **该 bug 自 09-29 起就在
  代码里，09-30 16:06 的构建已把它带上线**，不是 10-06 这版新引入的。
- **复现脚本**：`tmp/repro-bill-trim.mjs`（直接 import Nuxt UI 真实运行时工具，非手抄实现），
  四场景输出与截图逐一对应。
- **全项目扫描**：`(quantity|netContent|totalAmount)\.trim\(\)` 仅命中这 1 处；
  另外三处 `type="number"`（`admin/batches`、`admin/generator`、`admin/specs`）均用
  `v-model.number` 且无字符串方法调用，安全。
- **修复（已实施，本机未提交未上线）**：新增 `toText(v) = String(v ?? '')` 归一函数，
  把组件内 **9 处** `.trim()`（校验 2 处 + 主 payload 4 处 + 重复确认 payload 3 处）
  全部收口；`type="number"` 与 UI 保持零变化。只改 `app/components/BillFormModal.vue`
  1 个文件，零 DDL、零依赖、零 `.env`、零 nginx。全仓扫描确认无其他同类写法。
