## UI 改版提示词手册（docs/UI改版提示词.md，提交 31285cd）

**背景**：用户反馈现有界面「不够简约舒适、AI 味有些浓」，诉求是**要提示词**（指导 AI 改 UI），不是直接改代码。

**诊断方法（可复用）**：
1. 读 `app/assets/css/main.css` 摸清令牌体系（`--ui-*` 映射 + `--b-*` 中后台设计语言，圆角 0.375rem，主色 hsl(142 32% 30%)）
2. 看 `screenshots/` 实况截图（home-mobile / trace-genuine-bound / login / admin-dashboard）
3. `grep gradient` + `grep #[0-9a-fA-F]{6}` 定位 AI 味写法的**具体文件行号**

**实测结论（重要，后续改版直接引用）**：
- AI 味头号出处：`app/pages/index.vue:41` 的 `bg-gradient-to-br from-primary to-emerald-600` + `shadow-lg shadow-primary/30`
- `app/components/TraceAlert.vue:73` 用 `cfg.gradient` 给正常/异常/作废三态各配一套渐变
- 色彩不统一：`main.css` 是沉稳深绿，页面里另有 emerald-600、`nearby-stores.vue` 自成一套色板（#f8f9f4/#2c5c3a/#e67e22）、`admin.vue` 硬编码 #283850
- **后台其实已有克制的 `.b-*` 设计语言，问题集中在公众端 H5 + 令牌未被统一遵守**
- `scan.vue:253` 的 linear-gradient 是扫描线动画，属功能性视觉，改版时保留

**方法论沉淀（写提示词的核心）**：
- 负面清单 > 正面形容词（「AI 味」是可枚举的写法集合）
- 给数值不给形容词（4px 而非「小圆角」）
- 必须先冻结设计令牌，再改页面
- 红线：只改样式与模板结构，禁碰接口契约（本项目契约变更频繁，最易误伤）
- 执行顺序：令牌 → 登录页（校准审美）→ 扫码结果 → 首页 → 后台 → 全局 grep 复查

**产出**：`docs/UI改版提示词.md`（5 段可直接复制提示词 + 六要素方法论 + 执行顺序 + 4 条可量化验收标准 + 模型审美回潮补救话术），PROJECT_LOG.md 已追加记录。

## 排查：广西田园「辛菌·吗啉胍」原药候选为何只有 2 家（只读分析，未改代码）

**问题来源**：用户在产品管理添加广西田园 PD20110775 辛菌·吗啉胍，选原药时下拉只有 2 家。

**实测数据（pesticide_reg 全库只读查询结论）**：
- 该产品登记行：PD20110775，content `5.9%`，ingredients 原文 `辛菌胺 0.9%、盐酸吗啉胍 5%`，`ingredient_main`=辛菌胺，`ingredient_all`=`["辛菌胺","盐酸吗啉胍"]`
- 候选池筛选条件（regdata.ts findOriginalPool）：`dosage IN ('原药','母药') AND ingredient_main IN (产品全部成分) AND 登记证在有效期内`
- **命中仅 2 条，且都是「母药」**：PD20101360 山东胜邦绿野化学有限公司 / PD20101189 陕西省西安嘉科农化有限公司
- **盐酸吗啉胍的原药/母药登记 = 0 条**（全库 grep 确认）；数据源里也没有「吗啉胍·辛菌」反序命名
- 结论：只有 2 家是**数据源客观事实**，不是系统 bug

**"两个成分可互换"的根因**：候选池按「成分集合」合并（`ingredient_main IN (...)`），未把候选绑定到具体成分；候选下拉只显示「登记证号 | 企业名（原药）」，不显示该候选属于哪个成分 → 界面上两个成分的原药看起来可任意互换。

**命名顺序规范（查到出处）**：混配制剂名称用「·」连接各有效成分通用名，**按中文通用名称拼音顺序排列**（《农药登记资料要求》农业部公告第2569号 附件11）。辛(xīn) < 盐(yán)，故规范写作「辛菌·吗啉胍」。数据源里 `ingredient_all` 数组顺序不统一（有的 ["辛菌胺","盐酸吗啉胍"]，有的 ["盐酸吗啉胍","辛菌胺醋酸盐"]），是源数据顺序，非命名语义。

**关键发现（待接线）**：`product_original` 表**已有 `ingredient` 列**（"对应有效成分名（提示溯源用，可空）"，db-init.mjs:98），但 **post/patch/get/trace 四处的 SQL 都没写没读**（只读写 reg_no/company）→ 该列恒为 NULL。扫码结果页 TraceResult.vue 现仅展示「原药登记证号 + 原药生产企业」，**不显示原料/成分名**。这就是用户要的「扫码显示原料及其对应厂家」的缺口。

**后续可选方案**：A) 扫码按 reg_no 联查 pesticide_reg 带出 `ingredient_main`/product_name 展示（改动小）；B) 录入时把每行原药绑定到具体成分写入已有 `ingredient` 列，扫码显示「成分 → 原料 → 厂家」（彻底解决可互换）。本次未实施，等用户定方案。
