## git push 失败根因坐实：唯一可用代理属 WorkBuddy 沙箱，用户终端拿不到

## 【重要更正】本机其实有可用代理：xray.exe 监听 18808 / 18809

**上一节"本机无出网代理"的结论是错的**——我只探了 7 个常见端口（7890/7897/10809/1080/8080/10808/20171），全关，就下了结论。实际代理用的是**自定义端口**，漏掉了。

- **`xray.exe`（PID 3368）** 监听 `127.0.0.1:18808 / 18809 / 18810` —— 这是代理内核在跑。
- 实测（`curl -x` 访问 `https://api.github.com`）：
  - **18808 → SOCKS5 ✅ HTTP200/0.81s，HTTP 代理 ✅ HTTP200/0.77s（混合端口，首选）**
  - 18809 → SOCKS5 ❌ 超时；HTTP 代理 ✅ HTTP200/0.80s（仅 HTTP 入站）
  - 18810 → 两者皆 ❌（连接立即被拒，没在服务）
- `git -c http.proxy=http://127.0.0.1:18808 ls-remote https://github.com/cli/cli HEAD` → **成功**，拿到 `ba51bb47799e308109a980fca846a90d164f5811`。**代理对 git 有效。**
- `git ls-remote origin`（带代理）→ `fatal: could not read Username for 'https://github.com': terminal prompts disabled` → **网络已通，401 缺凭据**。说明剩下唯一的阻塞是认证。

**教训（方法论）**：判断"有没有代理"不能只探常见端口。正确做法是 `netstat -ano | grep LISTENING | grep 127.0.0.1` 列全部本机监听端口，再用 `tasklist` 对 PID 查进程名，找 `xray/v2ray/clash/sing-box/mihomo` 之类内核。

**其他事实**：
- `reg.exe` 被沙箱黑名单拦截（`Program Blocked by Security Policy`），**读不到 Windows 系统代理设置**，只能让用户在 GUI 里看。
- 本机 `origin` = `https://github.com/Blue03150328/-----.git` —— **URL 里仓库名就是 5 个横线**（`od -c` 逐字节确认，不是显示替换），看着可疑，需用户核对是否写错。

## ⚠️ git 引用写入在本机失效（重大环境事实，2026-09-12 发现并绕过）
- **现象**：`git commit` 报告成功（退出码 0、reflog 有记录、提交对象落盘可被 `cat-file` 读到），但 **`refs/heads/*` 文件不落盘** → 分支显示 `No commits yet`（HEAD unborn）、`git status` 把 **149 个文件全列成 `A`（已暂存新增）**、`git log` / `git rev-parse HEAD` 报 "does not have any commits yet"。
- **关键线索**：本机 git 身份是 `27475`，而仓库历史 **183 条提交的作者全是 `Administrator <admin@nz315.cn>`** → 历史提交都在原开发机完成，**本机从未成功提交过**。
- **二分测试**：`mkdir -p .git/refs/heads/feature` → 退出 0 且目录**真的出现**；`printf '%s\n' <sha> > .git/refs/heads/feature/ZSM` → 文件**真的出现**（41 字节）。**唯独 git 自己的 lockfile + rename 路径不生效**；沙箱内与沙箱外（`dangerouslyDisableSandbox: true`）**表现完全一致**，故**不是沙箱隔离导致**。
- **绕过手法（已验证有效、跨命令持久）**：手工写 loose ref ——
  `mkdir -p .git/refs/heads/<分支的斜杠路径>`，再 `printf '%s\n' <完整40位sha> > .git/refs/heads/<分支名>`
  （内容 40 位 sha + LF = 41 字节，与仓库既有 `master` / `feature--qd` 格式一致）。写后 `git rev-parse HEAD`、`git branch -v`（正确显示 `feature/ZSM 7755621 [ahead 1]`）、`git status`（恢复干净）**立即全部正常**。
- **根因未定**：`mkdir` 与写文件都正常，只有 rename 失效。排查方向：杀软 / 同步盘的实时防护拦截 rename。**归因不足，不下结论。**
- **纪律**：本机做任何 git 操作后，**必须验证 `git rev-parse HEAD`**；异常立即用上述手法补 ref。
