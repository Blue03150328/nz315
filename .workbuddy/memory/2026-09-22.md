## 外部二维码核验：从「只认 wla1.cn」改成「平台无关的通用字段提取」（已提交 `e0b0203`，分支 ycdb）

### 需求原话与分支

用户先给了真实瓶标二维码（码值同上 `10929272500926240000223813617201`，来源平台是第三方 `mashangzhuisu.com`），
要求：**「先用相机扫码出来别人的二维码，提取到别人的码中的信息后，再进行字段匹配到我们数据库的相同产品，最后给出具体结果」**。
随后在「给该平台写专用适配器」与「做通用字段提取」之间，用户明确选了**后者**（"用后者"）。

### 为什么必须改（原实现的天花板）

`ycdb` 上原有的外部核验**只对 `wla1.cn` 有专用接口**，其余平台统一走 `fetchGenericPage` 兜底 ——
**而那个兜底只把页面 `<title>` 当产品名**，等于什么都没提取。第三方平台（`mashangzhuisu.com`）实测是**纯 JS 渲染**，
服务端拿到的是空壳 HTML，`<title>` 里也没有产品信息 → 整条链路只能返回"信息不足"。

**结论性判断**：抓第三方平台私有接口 = 逆向别人的内部 API（随时改、随时加签名），脆弱且不可持续；
**通用标签提取 + 人工粘贴兜底**才是稳态方案。

### 通用提取怎么做的（四路兜底，都在 `extractLabeledFields`）

1. **JS/JSON 键值对**：正则匹配 `"productName":"xxx"` / `productName: 'xxx'` 之类（对 SSR 直出 JSON 的页面有效）
2. **逐行「标签:值」**：`农药名称：2.85%硝钠·萘乙酸`
3. **表格相邻单元格**：`stripHtmlToText` 特意把 `td`/`th` 转成 `\t`，这样同一行的「标签 | 值」能拼回一段文本再匹配
4. **标签独占一行 → 取下一行**

配套：`FIELD_ALIASES`（9 个字段 × 中英标签/键名别名）· `NOISE_LABELS` 噪声黑名单（使用方法/产品性能/注意事项…，
避免把「注意事项」后面的长段落误当字段值）· `cleanFieldValue`（拒超长文本/链接/占位词）。

### 三个实测踩坑（★ 都值得记）

1. **`redirect: 'error'` 会让整条链路 500**：`http://mashangzhuisu.com` 会 301 到 `https://`，
   fetch 直接抛 `unexpected redirect` → 接口 500。改成 `fetchSourcePage`：`redirect:'manual'` 自己判断，
   **同站 http→https 放行一次，跨站跳转拒绝（400）**。这是"看起来更安全"的写法反而炸掉的例子。
2. **「见喷码」被当成生产日期**：占位词正则原来只写了 `/^(见|未知|无|…)$/`，而标签上写的是 **"见喷码"**，
   照样溜进结果 → 已改成 `/^(见(喷码|包装|标签|瓶身|实物)?|未知|未提供|不详|待补充|待定|无|-|—|\/)$/`。
   **教训：占位词永远要按"真实标签怎么写"来穷举，不是按你想象怎么写。**
3. **「2.85%硝钠·萘乙酸」≠「硝钠·萘乙酸」造成假差异**：来源页带含量、登记库不带 → 严格比对必然 mismatch。
   新增 `normalizeProductName` 剥掉 `[数字%]` 含量段做**宽松比对**；宽松命中时结论仍是 `match`，
   但备注写明「仅含量标注写法不同（含量请人工复核）」——**既不误报差异，也不假装完全一致**。

### 一个功能设计决定

`fetchGenericPage` **特意不再用 `<title>` 冒充产品名**。`<title>` 常年是"XXX公司-追溯查询平台"这类站点标题，
拿它当产品名只会制造假差异（比返回空更难排查）。宁可空着，并在 `warnings` 里提示用户粘贴页面内容。

### ★ 本轮最重要的发现：真实平台的正常码会被误判 mismatch 并写进风险预警

实测抓真实 wla1（`http://www.wla1.cn/p?id=12618401501000000000003780168217`）：
- 登记库 `PD20261840` = **精草铵膦**；外部平台产品名 = **`15%精草铵膦可溶液剂-2`**
- `normalizeProductName` 只剥 `\d+%` ⇒ 剩下 `精草铵膦可溶液剂-2` ≠ `精草铵膦` ⇒ **mismatch**
- ⇒ 结论变成「发现信息差异」并**落 `risk_alert`（alert_type=5，实测 id 3/4，`enterprise_id=null`）**

**为什么这条最要紧**：外部核验的价值是"发现别人的码有问题"；如果**正常码也报风险**，预警就会被噪声淹掉（告警疲劳）。
