### 缺陷详情（★ 值得记的教训）

模板里写了 `router.back()` / `router.push('/')`，但 `<script setup>` 里**没有 `const router = useRouter()`**。实测该页 `#__nuxt.__vue_app__.config.globalProperties` **只有 `$router` / `$route` / `$head` / `$unhead`**，**没有裸的 `router`** → 不存在全局 fallback，直接 `undefined`。

- **实测报错**：`TypeError: Cannot read properties of undefined (reading 'push')`（走 `unhandledrejection`，**不在 console.error 里** → 用 `console.error` 劫持会漏判）。
- **同类共三处**：`TraceNotFound.vue`（返回 + 重新查询）· `TraceAlert.vue`（返回）· `nearby-stores.vue`（移动端顶栏返回）。
- **修改**：每个文件各加一行 `const router = useRouter()`。提交见 git log。

### 两个方法性踩坑

1. **这类 bug 静态检查抓不到**：`router` 是模板表达式里的自由变量 → 编译期完全合法，`node --check` / SFC 编译 / tsc 全静默。**必须真浏览器点一遍**（又一条印证）。
2. **dev 下验客户端跳转必须先预热目标路由**：首次跑「点【重新查询】」时 `errors: []` 但 URL 没变 → 一度以为修复无效，实为 **dev 首次编译首页（约 1.1s）+ 2.5s 采样窗口太短**。预热 `/` 后重跑即稳定通过。**采样优于单点断言**（本轮改成 4×400ms 采样点才看清是"慢"而非"无效"）。
3. 判定「`back()` 是否生效」的替代判据：CDP 报 **`Inspected target navigated or closed`** 就说明导航真的发生了（未修前这类按钮只会抛错、页面纹丝不动）。
