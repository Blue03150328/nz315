## 调研：追溯码「生成后找不回」的现状（仅结论，未动代码）

用户问：生成追溯码后切走页面/忘记下载，想回来重下却没有生成记录怎么办。核实结论（均为代码级证据）：

- **生成不入库**：`server/api/admin/codes/generate.post.ts:1` 明确「生成不入库」；第 62-78 行只把 `allCodes` 回传前端，**服务端零持久化**。结果唯一载体是 `generator/index.vue` 的 `result.value`（内存）。
- **切菜单不丢**：`generator/index.vue:18` 为 `keepalive: true` ⇒ 左侧菜单往返不丢结果；**真会丢的是刷新 / 关标签 / 退出登录 / 会话失效**。
- **唯一持久化路径 = 点「入库留档」**：`stock-in.post.ts:32-39` 建 `upload_batch`（`file_name` 固定为 `生成入库 YYYY-MM-DD HH:mm`，第 20 行）+ 码写 `trace_code`（`status=1` 未绑定）。
- 🔴 **码库管理没有导出能力**：`app/pages/admin/codes/index.vue` grep `导出|下载|export|download` **零命中**，只有 冻结/整批修正/删除/详细（明细逐条看）⇒ **留档之后也导不出这批码**。
- 🔴 **重新生成 ≠ 找回原码**：码第 12-32 位 = 毫秒时间戳 + 6 位随机 + 2 位校验（`generate.post.ts` FIXED_CONFIG）⇒ 重生成得到的是**全新一批码**。码已印/已交印刷厂时，当前系统**无任何途径找回原码**。
- 🔴 **审计日志不含码值**：`generate.post.ts:56-60` 的 `追溯码生成` 只记 `{productId, quantity, generated, duplicates, cfg}` ⇒ 无法从 `operation_log` 恢复码值。
- 已有旁证：`generate.post.ts:45` 生成前会拉**本企业 trace_code 全表** code 做重码检测（量大时的性能隐患，另记）。
- 待用户拍板的候选方案：① 码库管理加「导出本批次码」（补齐重下能力，根治）；② 生成页加未保存防丢失提醒（`beforeunload`+醒目文案，低成本）；③ 生成页加「生成后自动入库留档」开关；④ 独立「生成记录表」（与既有设计相悖，不推荐）。
