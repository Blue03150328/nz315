## 外码抓取失败定因（用户报「有些可以有些不行」）—— 本机必然全失败，"可以的"是假数据

- **定因（硬证据）**：`source-fetch.ts:32` 用 `lookup(host,{all:true})` + `records.some(r => !isPublicAddress(...))` 判定；本机代理把**所有**域名解析成 fake-ip —— 实测 `mashangzhuisu.com→198.18.69.172`、`ddspp.cn→198.18.64.136`、`nyzs315.com→198.19.162.175`、连 `www.baidu.com→198.18.64.143`。黑名单第 9 行**恰好含 `198.18.0.0/15`** ⇒ 每次抓取都在 DNS 校验这关被拒，文案「来源网址不是可访问的公网地址」。`dns.Resolver.setServers(['223.5.5.5'])` 也返 fake-ip（UDP 53 被劫持）⇒ 只有 **DoH** 能拿真实 IP。
- **库内数据**：`external_source_snapshot` 共 11 行，真实抓取 **9 条全 `unavailable`**；唯一 2 条 `[ok]` 的 message 写着「**本机离线样本视觉验收**」——是我用 `tests/fixtures/ddspp.html` 造的假快照（含用户一直看到的那条 `57878377-…`）。**用户把这两条当成了"功能可用"，实为假数据污染判断。**
- **绕开 DNS 直连真实 IP 的实测（DoH 拿 IP + 直连）**：`ddspp.cn`(47.105.56.37) **200 / 235KB** 含"登记证""生产日期" ✅ · `nyzs315.com`(1.117.20.2) **200 / 49KB** ✅ · `mashangzhuisu.com`(122.114.5.21) **301 → https** · `www.wla1.cn`(47.112.180.65) **403**，换浏览器 UA **仍 403**（非 UA 反爬，疑 WAF/IP 策略）。
- ⇒ **结论**：站点普遍活着、真实 IP 都是合法公网 ⇒ **线上服务器（DNS 正常）抓取判定会通过**；本机的失败是环境问题不是代码 bug。线上真实的"有些不行"会是另一批原因：反爬 403、域名失效、多 IP 里混入保留段（`some()` 全或无）、JS 壳页面解析不出。
- 诊断脚本留在 `logs/_diag-source-fetch.mjs`（库内分布+系统DNS）、`_diag-dns-real.mjs`（系统 vs 公共DNS vs DoH）、`_diag-direct-ip.mjs`（DoH+直连）、`_diag-ua.mjs`（403 是否反爬）。
